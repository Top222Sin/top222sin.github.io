L4 分数阶 PID（Fractional-Order PID / FOPID）

整数 PID 只有 3 个旋钮（Kp/Ki/Kd），调的是「比例 / 积分 / 微分」三项，且积分、微分的阶数被钉死在 1。分数阶 PID 再开两个自由度——积分阶 λ 和微分阶 μ 不必等于 1，于是「积分了多少」「微分了多少」都能连续调。暖通、家电这类「想柔顺一点、别太冲」的对象，多这两个旋钮往往比死磕 Kp/Ki/Kd 更顺手。

一、为什么整数 PID 不够「柔」

整数 PID：

很多实际对象（热惯性、粘滞、柔性结构）的相位特性不是整数阶的：想补相位就只能硬压 Kd（放大噪声）或硬加 Ki（拖慢）。分数阶 PID 让「微分 / 积分」的阶次本身变成可调参数，刚好补上对象缺的那点相位，而不必把增益推到极端。

连续形式：

  • λ 管积分阶：<1 是「不完全积分」（更柔、无积分饱和尖峰），=1 退化为普通积分。
  • μ 管微分阶：>1 给更多相位超前（更抗超调），=1 退化为普通微分。

二、核心：Grünwald-Letnikov（GL）离散化

分数阶算子没有现成差分，用 GL 定义近似：

  • 积分项（α = −λ）：D^{-λ}e = h^{+λ} · Σ wI[j]·e(k-j)
    • λ=1 时 h^{+1}·ΣwI[j]e(k-j) 正是标准矩形积分 —— 真正的积分器，故全历史不截断，否则丢 DC / 积分器行为（本 demo 初版就栽在这里，见第六节）。
  • 微分项（α = +μ）：D^{μ}e = h^{-μ} · Σ wD[j]·e(k-j)
    • 权重随 j 快速衰减，用截断窗口即可（本 demo Hd=400）。

退化自检：μ=1 时系数应为 (1, −1, 0, 0, 0) —— 即退化为普通微分 e(k)−e(k−1)。

三、代码走读（pid_l4_fopid.cpp）

  • tustin_ss：双线性（Tustin）把连续二阶对象 G(s)=1/(s²+0.5s+1)（wn=1, ζ=0.25）离散成状态空间 Ad/Bd/Cd。
  • gl_weights(alpha,H)：生成 GL 系数向量（积分全历史 N 项；微分截断 Hd=400 项）。
  • sim_fopid：每步 yk=C·x、ek=r−yk；积分累加 sI 走全历史、微分 sD 走截断窗口；控制量
    u = Kp·ek + Ki·dt^{lam}·sI + Kd·dt^{-mu}·sD。
  • 比较同一 Kp/Ki/Kd 下：整数 PID（λ=1, μ=1） vs FOPID（λ=1, μ=1.2）。

四、你会看到什么（已用受管 Python 3.13.12 验证，全部 PASS）

对象 G(s)=1/(s²+0.5s+1)，dt=0.02, T=25, r=1，Kp=1.6, Ki=0.9, Kd=0.9：

检查 结果 含义
整数 PID（λ=1, μ=1） IAE=1.1231，ISE=0.4486，超调=0.0173 基准
FOPID（λ=1, μ=1.2） IAE=1.1110，ISE=0.4139，超调=0.0000 μ 多给相位超前，超调被压掉
FOPID IAE < 整数 IAE PASS 质量指标也更好
FOPID 超调 < 整数超调 PASS 更柔顺
FOPID 稳态误差 < 0.02 PASS（5.8e-5） 全历史积分保住 DC
GL μ=1 系数 (1,−1,0,0,0) PASS 退化自检成立

关键结论：同 Kp/Ki/Kd 下，μ=1.2 多出的相位超前把超调从 0.0173 压到 0.0000、IAE 也更小。λ/μ 是 PID 之外的两个额外自由度，整定时可与 Kp/Ki/Kd 一起用指标（见 L4.6 IAE/ISE）打分寻优。

五、与 PID 家族的衔接

  • 对比 L1.3 PID 三项：FOPID 就是把它三项里的「积分阶 / 微分阶」从 1 放开。
  • 对比 L2.2 增益调度：增益调度是「换一组 Kp/Ki/Kd」，FOPID 是「换积分/微分阶」——两条不同的「柔性整定」路线。
  • 对比 L1.5 整定：整定目标一致，FOPID 把搜索空间从 3 维扩到 5 维。

六、工程坑（真实）

  1. 积分项必须全历史：GL 积分权重衰减极慢，截断（如限 400 步）会丢掉积分器 → 稳态下垂。本 demo 初版 H=400 截断积分，稳态误差飙到 0.02 以上，改成全历史 wI=gl_weights(-lam,N) 才修好。
  2. 微分项截断窗口要够长：wD 虽衰减快，但 Hd 太短（如 20）会让高频微分失真。
  3. μ 不是越大越好：μ 过大 = 过激微分 = 对噪声极敏感；建议配合 IAE/ISE 指标寻优，而非盲调。
  4. 无编译器确认：本机无 C++ 编译器，demo 用受管 Python 3.13.12 做算法镜像 24/24 PASS，再逐字转写 C++17，并用 C++ 控制流镜像 24/24 PASS 兜底静态类型 bug。

七、自检

  • 把 mu 从 1.2 改到 1.5，看超调/IAE 是否继续降（注意高频噪声敏感度）。
  • 把积分截断改成 H=50，重跑看稳态是否重新下垂（反向验证全历史必要性）。

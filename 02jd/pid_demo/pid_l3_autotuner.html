L3.3 在线/自动调参系统（AutoTuner 状态机）⭐

单点整定只是算法，工程里要的是一套能自动跑、能自检、能告警的系统。本篇仿 PX4 McAutotuneAttitudeControl 的状态机，把”辨识→增益→验证→保存”串起来，并加一道质量门——坏 plant 直接告警、拒绝落库。

一、为什么需要系统级框架

L3.1 教你”怎么算出好增益”，但生产环境要回答更多问题：

  • 多轴（roll/pitch/yaw）要逐个激励、辨识、落库；
  • 辨识出的增益要在闭环验证里确认真的好用；
  • 遇到退化/异常 plant（传感器故障、参数漂移、符号反了），不能 blindly 把垃圾增益写进飞控——要告警并拒绝保存。

状态机的价值：把”辨识实验”变成安全协议——每个状态都有进入条件、超时退出、失败路径。真实飞控的自动整定（PX4 mc_autotune）同样是逐轴状态机（_state == state::roll/pitch/yaw，代码里 _sys_id.updateFilters(...) 逐轴做激励），但其辨识算法是阶跃激励+系统辨识+GMVC 增益设计，不是本 demo 的 relay/Z-N——本 demo 借鉴其”状态机/激励/验证/落库”思想，算法本体是教学简化，不等同于 PX4 实现。

二、状态机与质量门

每个轴的流程：

  1. EXCITE：对该轴注入 relay 激励，plant 自激振荡；
  2. IDENTIFY：量 Ku/Pu，套 Z-N 得 Kp/Ki/Kd（复用 L3.1）；
  3. VERIFY：用这组增益跑闭环阶跃，算超调、稳态误差、是否发散；
  4. 质量门（SAVE）：指标全过 → 落库；任一不过 → FAILED 告警，不写参数。

状态机设计要点（工程模式）

  • 每个状态要超时：EXCITE 超时（振荡不出来）→ 说明 plant 不配合（死区/符号反），进 FAILED 而非卡死；
  • 状态转换记录审计：每个状态停留时长、关键中间量（a/Pu/Ku）落盘——事后可查”这次整定为什么失败”；
  • 质量门阈值带余量：设计阈值 vs 判定阈值之间留缓冲（如设计超调<0.5、判定阈值 0.6），避免噪声恰好撞线。

三、代码走读（pid_l3_autotuner.cpp）

  • tuneAxis(p, name, ...)：单轴全流程。relay 辨识 → Z-N 增益 → closedStep 验证 → 质量门。
  • 质量判据：超调 < 0.6 且 |稳态误差| < 0.05 且 不发散（有限窗口 |y| < 3 是工程判据——只能说明窗口内未越界，不证明数学意义的不发散；严谨做法加窗口增长率/末段 RMS 检查）。
  • 主程序跑三轴健康 plant（roll/pitch/yaw）+ 一个退化 plant（负增益）：
    • 健康三轴 → 全 SAVED，状态 COMPLETE，无告警；
    • 退化 plant → 闭环验证失败 → alarm=true、不保存（注：负增益在本 demo 的具体反馈符号/增益/检测窗口下必触发告警；一般系统负增益可能表现为大偏差/饱和而非数学发散，结论以本 demo 测试为准）。

四、你会看到什么

  • 状态机图：从 IDLE 一路走到 COMPLETE；VERIFY 下方有一条红色”质量门不达标 → FAILED”分支。
  • 报告区：健康三轴 ✔ 落库；退化 plant ✘ 告警拒存。

五、工程坑（真实）

  1. “负增益”是符号反的极端例：真实里更常见的是部分符号错（某轴接线反、标定符号错）——只影响一轴，其他轴正常，最容易漏检。逐轴独立质量门正是为此。
  2. 辨识激励的安全性：EXCITE 期间系统处于”非正常”状态——真机要限幅、限时、手动 abort 通道（PX4 里就是飞手遥控/安全检查打断）。仿真里也要有”用户中断”接口的意识。
  3. 保存的原子性：三轴分别 SAVE，若 yaw 失败而 roll/pitch 已存 → 参数集不完整——工程上要么全轴成功才落库（事务式），要么落库带”部分完成”标记。
  4. 重复整定的回归：整定系统本身要能验证”新增益 ≥ 旧增益”（对比基线），否则自动整定可能越整越差——加一个”与当前参数对比”的决策门。

六、自检

  • 把健康 plant 的 K 改成 -2（人为接反），看它如何被质量门识别为 FAILED——体会”自动告警”的价值。
  • 把质量门阈值（超调 0.6）放宽到 0.9，看退化 plant 会不会”蒙混过关”——印证阈值要有工程余量。
  • 把 N（辨识时长）调太小，看辨识未收敛导致质量门误判——引出”辨识充分性”检查。

七、下一步

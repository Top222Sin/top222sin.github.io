L1.5 抗积分饱和（Integral Windup）基础

调好了增益，执行器一限幅，系统可能突然”抽风”——这是积分饱和在作怪。

一、windup 是什么

执行器有物理上限（u ∈ [−uMax, uMax]）。当误差很大、PID 输出长期饱和时：

积分项还在照常累加 ∫Ki·e。等误差终于反向，这个已经”涨爆”的积分项继续推着输出往同一方向走 → 系统冲过头、大超调、很久才拉回来。

饱和越久、误差越大，windup 越严重；Ki 的影响是双面的（Ki 大 → 饱和期间积得快，但也可能更快把误差压小）——“大 Ki 必 windup”不严格，但”大 Ki + 易饱和执行器”组合风险显著升高是工程共识。解除饱和瞬间输出 = 积分存量 + 当前项，会大幅冲顶/冲底（”退饱和冲击”；实际限幅器下输出本身连续，冲击体现在后续超调而非输出跳变）。

二、怎么治：条件积分（clamping）

本 demo 用简化版（饱和即冻结）验证核心收益；工程实现应带方向判断（上例），否则”误差反向但积分仍在涨”的窗口内会欠补偿。注意假设 Ki>0、限幅对称。

三种抗 windup 方案对比

| 条件积分（clamping） | 饱和时按误差方向冻结积分 | 最简单、零开销 | 方向判断写错会欠补偿 |
| 积分限幅（clamp integ） | 积分器输出限幅 | 硬保证积分有界 | 上限选取玄学 |
| 反算抗饱和（back-calculation） | 饱和时把 (u−u_unsat)/Tt（跟踪时间常数）反馈回积分器 | 精确、工业标准 | 多一个系数 Tt |

PX4 RateControl::updateIntegral() 用的是条件积分（饱和方向门控 + 积分限幅），不是标准 back-calculation（L2.3 详解）。back-calculation 的数学形式：İ = Ki·e + (u_sat − u)/Tt——饱和超出的部分反向冲刷积分器，让积分器”知道”输出被砍了。

三、代码走读（pid_l1_antiwindup.cpp）

  • sim(cfg, ...)：一阶 plant，带限幅；cfg.aw 开关控制是否条件积分。
  • 指标：超调（首峰超出末值比例）、稳态误差、发散检测。
  • 对拍：oAW < 0.4（抗饱和后超调小）、eAW < 0.05（仍达标）、oNo > oAW + 0.1（windup 明显更糟）。

四、你会看到什么

  • 红色（无抗饱和）：冲到远超设定值，再慢慢荡回来——典型 windup。
  • 绿色（条件积分）：平滑贴到 1.0，超调很小。

五、工程坑（真实）

  1. D 项不参与 windup：D 项没有积分状态，不会 windup——“饱和时冻结 D”没有理论依据。工程上饱和时对 D 的处理是抑制其 kick/噪声（derivative-on-measurement 或滤波），与积分冻结是两回事。
  2. 增量式≠免疫（呼应 L1.3）：增量式”饱和时停止累加 Δu”确实简单，但若执行器本身带积分（如伺服的位置输出），windup 会转移到执行器内部——要在执行器真实输出处做饱和检测（飞控常用 control allocator 的饱和反馈，不总能直接测到执行器输出）。
  3. 条件积分的欠补偿：饱和解除瞬间误差已小，冻结的积分可能不够——表现为”慢吞吞回到设定值”。工业上反算法（back-calculation）更精确，PX4 的 setSaturationStatus + updateIntegral 是工程化条件积分（按方向门控，非简单冻结）。
  4. windup 检测要区分饱和来源：执行器饱和 vs 速度/位置限幅（串级里外环限幅是”软饱和”——只有上游环含积分且未获下游饱和反馈时才形成串级 windup，L2.1 的 vmax 本身不产生 windup）。

六、自检

  • 把 uMax 从 2.0 降到 1.0，看饱和更久、windup 更夸张。
  • 把 Ki 从 1.5 调到 4.0，看无抗饱和时超调如何爆炸——积分增益越大越怕 windup。
  • PX4 怎么做的？见 L2.3：它的抗饱和来自 control allocator 的饱和反馈（setSaturationStatus），思想完全一致。

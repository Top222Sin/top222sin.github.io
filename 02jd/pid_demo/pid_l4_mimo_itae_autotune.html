L4 MIMO 解耦 + ITAE 自动整定（「指标即偏好」亲手演示）

L4.9 MIMO + IAE 自动整定 已经证明：解耦后每回路用 L4.6 的 IAE 当打分函数、网格搜索 (Kp,Ki) 能比统一 NOM 把全系统 IAE 砍掉 63%。但 L4.9 第五节也点出 IAE 的致命偏性——它偏向激进增益（增益越大响应越快、误差累计越小，无约束时一路顶到搜索窗边界）。本 demo 把 L4.9 的目标函数从 IAE 换成 ITAE（Σ k·h·|e|·h，给早期/中段误差加权），与 IAE 同台顺序整定，亲手演示那句老话：指标换了，最优就移向更温和的增益。

一、为什么还要换一个指标

L4.9 的 IAE 整定落到了网格最激进端 (Kp=2.3, Ki=1.5)，全系统 IAE=1.4750。但这只是「IAE 这个偏好」下的最优——它不管你调得猛不猛，只要误差小就行。

真实工程要的是「又快又稳」。L4.6 里的 ITAE 就是为这个设计的：

直觉上，ITAE 比 IAE 多乘了一个「时间砝码」k·h。这意味着：

  • 一个前期冲过头、后期慢慢荡回的响应（超调/振荡），在中段有持续大误差，被 ITAE 重点惩罚；
  • 一个温和、单调、略慢的响应，误差更早归零，ITAE 反而小。

所以同一对象、同一解耦器、同一整定流程，仅把目标从 IAE 换成 ITAE，最优增益应当被「推」向更温和（更低 Kp、更保守）的方向。本 demo 就是要亲手验证这一点。

二、核心：同一流程，只换打分函数

做法与 L4.9 一字不差，仅 metric 标志从 IAE 切到 ITAE：

关键设计：两遍整定用完全相同的网格、仿真、解耦框架，唯一的变量是指标。这样「最优增益的差异」可以干净地归因到「指标的偏好不同」，而不是别的。

三、代码走读（pid_l4_mimo_itae_autotune.cpp）

  • 矩阵库 / inv / sim 与 L4.7、L4.9 逐字一致（2×2 递推、D=inv(Kss) 预补偿、Kd=0.2 固定）。
  • iae(e) / itae(e)：离散 Σ|e|·h 与 Σ(k·h)·|e|·h，来自 L4.6。
  • tune(int metric, r, fixed_other)：同一个函数吃两个指标——metric==0 用 IAE、metric==1 用 ITAE；整定回路 1 时变增益进 g1 槽、测 E1，整定回路 2 时进 g2 槽、测 E2（这是 L4.9 验证时踩过的「槽位」坑：谁的误差被评，变增益就得进谁的槽）。
  • main 先 tune(0,…) 得 IAE 最优，再 tune(1,…) 得 ITAE 最优，各跑全系统与单回路阶跃，最后 11 项 chk 对照。

四、你会看到什么（受管 Python 3.13.12 验证，11/11 PASS）

对象 K=[[1,0.3],[0.5,1]]，τ1=1, τ2=2，dt=0.05, T=15，Kd=0.2 固定；顺序整定：

目标 回路1 最优 (Kp,Ki) 回路2 最优 (Kp,Ki) 全系统 IAE 全系统 ITAE
IAE（L4.9 同款） (2.3, 1.5) (2.3, 1.5) 1.4750 1.5910
ITAE（本 demo） (1.4, 1.5) (2.3, 1.3) 1.5218 1.2646
检查 结果
IAE 整定复现 L4.9 基线（全系统 IAE≈1.4750） PASS（确认同台可比）
换成 ITAE 后，ITAE 指标自身更优（1.2646 < 1.5910） PASS
代价：ITAE 目标的 IAE 仅升 <5%（1.4750→1.5218，+3.2%） PASS
回路1 Kp：ITAE(1.4) < IAE(2.3) → 更温和 PASS
回路2 Ki：ITAE(1.3) < IAE(1.5) → 更温和 PASS
两目标稳态 y1≈1、y2≈1 PASS
单回路阶跃下交叉耦合峰值 <0.05（解耦仍压住） PASS（两目标均 ≈0）

核心结论：仅把目标从 IAE 换成 ITAE，最优增益就整体移向更温和——回路 1 的 Kp 从 2.3 降到 1.4，回路 2 的 Ki 从 1.5 降到 1.3。ITAE 把全系统 ITAE 压低 **20.5%**，代价仅是 IAE 上升 **3.2%**。「指标即偏好」被亲手验明。

五、洞见：指标就是一句「你最在意什么」

把两张表并排看，结论其实很朴素：

  • ITAE 的「砝码」k·h 在惩罚前期过冲：猛整定虽快，但初段误差曲线陡、中段拖着尾巴，被 ITAE 记上一笔；温和整定早期就收敛，反得低分。
  • 代价极小：ITAE 最优的 IAE（1.5218）只比 IAE 最优（1.4750）高 3.2%——说明「温和一点」几乎不牺牲总误差量，却显著改善时间加权误差与超调倾向。这正是工程上「ITAE 整定比 IAE 整定更常用」的底层原因。
  • 这与 L4.8 完全同构：L4.8 里把 FOPID 的 (λ,μ) 寻优目标从 IAE 换成 ITAE，最优也明显移动（μ>1 的微分冲击会抬高早期误差、被 ITAE 罚）。「选哪个指标，最优就落哪」不是比喻，是数学事实。

六、工程坑（真实）

  1. 整定回路时变增益必须进对应槽：sim(g1,g2) 里回路 1 误差在 E1、回路 2 在 E2；扫回路 2 时变增益要进 g2 槽并评 E2，否则会「评错回路」导致最优错乱（本 demo 验证脚本初版就栽在这，修好后与 L4.9 基线 1.4750 严丝合缝对齐）。
  2. 同台对比要先对齐基线：ITAE 整定的「更优」必须相对 IAE 整定的同一仿真而言。先确认 IAE 整定复现 L4.9 的 1.4750，再谈「换指标后移向温和」，否则对比无意义。
  3. 不等式断言方向：chk("ITAE更优", max(0, ITAE_t - ITAE_i), tol)——只有 ITAE 目标反而更差才 FAIL；写成 ITAE_i - ITAE_t 会把「改善量」误当误差而 FAIL（记忆 §三 老坑）。
  4. 交叉耦合要单回路阶跃测：耦合应测 r=[1,0] 下回路 2 的偏离 y2，不能测 r=[1,1] 下 |y2−1|（那只是回路 2 自己的 setpoint 暂态，不是耦合）。
  5. 无编译器确认：本机无 C++ 编译器，demo 用受管 Python 3.13.12 做算法验证（11/11 PASS），再逐字转写 C++17，并用 C++ 控制流镜像（11/11 PASS）兜底静态类型 bug。

七、自检

  • 把 tune 的 metric 在 main 里对调再跑：最优增益应互换回 IAE 的激进端——确认「差异真的来自指标，而非随机」。
  • 把网格 Kd 也放开（加一维 gKd），重扫 IAE vs ITAE：观察 ITAE 是否进一步倾向更高 Kd（更多阻尼=更温和），亲手看「温和」在多维上如何体现。
  • 把对象改成更易超调的（如 τ1=0.5 或 K=[[1,0.6],[0.6,1]] 强耦合），看 ITAE 与 IAE 的最优分歧是否更夸张。

八、与 PID 家族的衔接

  • 上游：L4.9 MIMO + IAE 自动整定（本 demo 的母版，仅换目标）；L4.7 MIMO PID（解耦器 D=K⁻¹ 与 2×2 框架）；L4.6 IAE/ISE/ITAE（两把尺子）；L4.8 指标驱动寻优（同构的「指标即偏好」）。
  • 跨仓同构：control_demo L4.5 MIMO 解耦 用同一 D=K(0)⁻¹ 范式；本 demo 在其上叠加「解耦后双指标整定对比」。
  • 下游：自动整定 + 模糊/增益调度（见 L4.5 模糊 PID）=「按工况/按指标调增益」的两套实现。

L3.4 全流程工具链（Capstone）⭐

把 L1→L3 所有积木串成一条龙：PX4 风格「位置→速度→加速度/速率」串级（纯 C++ 教学复刻，结构思想源自 PositionControl + RateControl，教学抽象，非 PX4 代码复刻），端到端阶跃响应对拍真值，并内嵌内环自动整定与退化告警。这是整套学习路径的收口。

一、为什么需要 capstone

单独会 P/I/D、会整定、会抗扰还不够——真实飞控是多层嵌套的：

  • 外环输出是内环设定值（呼应 L2.1）；
  • 速率环用 PX4 并行式 K·(P+I/s+sD)+FF（呼应 L2.3）；
  • 内环增益靠自动整定（呼应 L3.1/L3.3）；
  • 遇退化必须告警（呼应 L3.3 质量门）。

三层串级的”为什么”（全链路总结）

capstone 的工程价值：把”每个环单独学过”变成”一套能跑通的完整系统”，并暴露环间交互（内环慢 → 外环抖；外环限幅 → 内环不饱和）——这些只有拼起来才看得到。

二、本 demo 干了什么

  1. 三环串级仿真：位置环用 P + 速度限幅（防超调），速度环 PID，速率环并行 PID + 前馈；执行器一阶惯性；端到端阶跃。
  2. 内环自动整定：把速率环 plant 近似为 FOPDT（辨识用近似模型，K=1, T=τ，纯滞后 L 由采样/执行器延迟等效估计——注意：框图里的 1/(τs+1) 执行器本身无纯滞后，FOPDT 的 L 是工程等效项，不是模型字面含义；relay 振荡在无延迟一阶/双积分对象上可能不收敛到经典极限环，故需在代码中显式加入等效延迟或在辨识模型中保留 L），用 relay 辨识（复刻 L3.1）得 Ku/Pu，与 理论真值（数值求根 ωu·L+atan(ωu·T)=π，见 L3.1；连续时间 FOPDT 理论值，离散仿真/采样/限幅会引入偏差）交叉校验后，套保守 Z-N 得内环增益。
  3. 退化注入与告警：
    • 传感器符号翻转 → 反馈变正反馈 → 发散 → 告警；
    • 执行器变慢 10×（模型失配、未重整定）→ 超调显著恶化 → 告警。

为什么用”保守 Z-N”（工程决策）

自动整定得到的增益直接上真机，风险偏好应保守：

决策框架：内环（高带宽、强耦合执行器）保守整定；外环（低带宽、余量足）可稍激进。整定后的 VERIFY 质量门（L3.3）是最后一道保险。

三、代码走读（pid_l3_pipeline.cpp）

  • relayIdentify(...)：复刻 L3.1 的 relay 自激振荡辨识。
  • simCascade(cfg, dt, N, xsp)：三环串级离散仿真；sensorFault 开关注入传感故障；含积分抗饱和（限幅回撤）。
  • 对拍判据：
    • 健康串级：|稳态误差|<0.05、超调<0.3、不发散、调节<20s；
    • 内环辨识：|Ku_est−Ku_true|/Ku_true < 0.3（relay vs 精确真值）；
    • 退化：符号翻转→发散 → 必告警。

四、你会看到什么

  • 左图：三环串级方块图（位置 P → 速度 PID → 速率并行 PID + 前馈 → 执行器 → 双重积分 plant），传感器反馈处可注入退化，触发 ALARM。
  • 右图：健康响应收敛到设定值、无稳态误差；退化响应发散、被告警拦截。

五、工程坑（真实）

  1. **内环辨识时外环要”打平”**：给速率环做 relay 激励时，外环（位置/速度）必须处于”设定值不动”状态，否则外环干扰辨识信号——真实飞控自动整定要求飞机悬停/平飞就是这个原因。
  2. 每环的 dt 可以不同：位置环 100Hz、速度环 250Hz、速率环 500~1000Hz 是常见配置（内环越快）——多速率实现要处理环间插值/同步，别全用同一个 dt。
  3. 退化检测的时机：符号翻转在积分器累积之前就应被发现（第一拍就方向错）——用”误差方向 vs 输出方向”一致性检查可秒级告警，不用等发散。
  4. 仿真通过 ≠ 真机通过：真机有噪声、延迟、非线性（电机饱和、桨叶失速）——capstone 的判据在真机要留 2~3 倍余量。

六、自检

  • 把 vmax（速度限幅）从 0.6 调到 2.0，看健康串级超调如何变大——体会外环限幅是防超调的关键。
  • 把内环 Pr 直接设 0（不整定速率环），看串级如何变迟钝/振荡——印证自动整定的价值。
  • 打开 sensorFault，看系统如何立刻发散并被告警——这正是 L3.3 质量门在真实链路里的落点。

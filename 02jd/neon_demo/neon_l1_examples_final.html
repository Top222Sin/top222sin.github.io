NEON 主线 · 实例大全与最终总结

贯穿始终的两个旋钮：① ILP 深度（累加器数）≥ 每周期 NEON 端口数 才能喂满吞吐；
② 数据按缓存层次分块/预取 + 结构化（连续/对齐） 才能喂饱带宽。下面的每个实例，本质都是在
这两个旋钮上做文章。

一、3x3 卷积：直接 NEON（vext 滑动窗口）

原理：3x3 是最常见卷积。直接法的瓶颈是”同一行像素被相邻输出窗口重复读 3 次”。
NEON 的解法是载入一行 4 像素后，在寄存器内用 vextq_f32 滑动出窗口的 3 列，
一次算出 4 个输出列，把重复访存压到 1/3。

关键指令：vld1q / vextq_f32（寄存器内字节滑窗）/ vmlaq_n_f32（乘加标量权重）。
ncnn 落点：src/layer/arm/convolution_3x3.h 的 conv3x3s1_neon 正是这套 vext 手法；
convolution_1x1.h、convolution_3x3_winograd.h 是 1x1 与 Winograd 两条旁支。
何时用：kernel=3、stride=1、通道数不大时，直接法最省（无额外变换开销）。这是 NEON 卷积的”地基”。

二、4x4 / 5x5 卷积：统一走 im2col + GEMM

原理：当 kernel 不是 3（或 stride 任意），手写 vext 滑动就不优雅了。通用打法是
im2col：把每个输出位置对应的 k×k 邻域拉成一行，整张特征图变成”列矩阵”，卷积立即退化为一个
GEMM（C = W · im2col）。这把所有卷积统一到我们 L3 第三部分已经打透的 8x4 NEON 微内核上。
代码里的 im2col() + gemm_scalar() 与你 neon_l3_gemm.cpp 的打包 GEMM 是同一条链路（生产换 NEON 8x4 即可）。

关键指令：vld1q/vmlaq/vaddvq（在微内核里）。
ncnn 落点：convolution_im2col_gemm.h（im2col + transpose8x8_ps 打包 + gemm）。
何时用：kernel≥4、或 depthwise 之外的通用卷积、或需要吃满 L1 分块时。

5x5 还有一条旁支：用两次 3x3 近似（因式分解 / 序列）替代一次 5x5，乘法更少——但精度/语义
需确认，通用场景仍以 im2col 为主。

三、Winograd F(2,3)：卷积的”傅里叶”

原理：3x3 卷积在像素域要做 9 次乘/输出点；Winograd 把它搬进变换域，只需 4 次”逐点乘”
（从 9→4，省 ~2.25× 乘法）。三步即编解码：

B/G/A 是固定常数矩阵（见代码 WIN_B/WIN_G/WIN_A）。ncnn 的
convolution_3x3_winograd.h 里 transform_kernel/transform_input/transform_output 就是这三步；
逐点乘那一步是 NEON vmulq 直接干的活——这正是我们 L3 第五部分说的”卷积 = 编解码”的同款逻辑，
而 FFT 是它在连续信号上的通用版（见 §四）。

关键指令：变换阶段 vld/vmla（矩阵乘），核心阶段 vmulq_f32（逐点乘，NEON 最舒服的形态）。
何时用：3x3、通道数大、对乘法数敏感时（MobileNet/ResNet 的瓶颈层）。代价：需要 tile 对齐与
边界填充，小特征图不划算，所以它是 3x3 大图场景的”省乘法”选项，不是万能替代。

四、傅里叶变换：基-2 FFT 的 NEON 蝶形

原理：FFT 把时域信号搬进频域（与 Winograd 把像素搬进变换域是同一思路的连续版）。基-2 迭代
FFT 由 N·logN 只”蝶形” 组成，每只做复数乘加：

NEON 关键点：复数存成 SoA（两个独立数组 re[]/im[]），一次 vld1q 取 4 个实部/虚部，
四只蝴蝶并行；复数乘变成分量级 vmulq/vsubq/vaddq，干净无 vtrn 折腾（对比 L3 第五部分 SVE 用
svld2 拆交织复数，思路一致，SVE 更省一步）。

关键指令：vld1q / vmulq_f32 / vsubq_f32 / vaddq_f32 / vaddvq_f32（规约）。
ncnn/MNN 落点：推理引擎的 FFT 多用于 语音/音频前处理、可分离卷积的频域加速、某些检测后处理；
MNN 的 KleidiAI/kai 路径也含 FFT 类 ukernel。代码 fft_radix2_neon() 与 dft_naive() 对拍验证。
何时用：长序列变换、频域滤波、需要 O(N logN) 而非 O(N²) 时。

原理级拆解（图三·乙）：上图说”四只蝴蝶并行”，这里的 “4” 来自 SIMD 宽度——复数按 SoA 存，128-bit 寄存器装 4 个 float32，于是 vmulq/vaddq/vsubq 每条指令的 4 个 lane 各跑一只独立蝴蝶的复乘/加减，互不干扰。下图为这只”一次 4 只”的打包与并行：

SoA vmulq vA_re × vB_re 4 lanes a_k · b_k k = 0..3 “4” 从哪来？ 128-bit 寄存器 ÷ 32-bit float = 4 lanes。一条 vmulq/vaddq/vsubq 同时作用 4 个 float， 所以 4 只蝴蝶并行。完整复乘：tw = w·b 需 tw_re = w_re·b_re − w_im·b_im， tw_im = w_re·b_im + w_im·b_re（也用 vW_im）；每步都是 4-lane 操作 → 每条指令 4 只蝴蝶。

五、稀疏矩阵：为何”稀疏”反而难矢量化，结构化才救得回来

原理：稠密 GEMM/卷积天然连续、对齐，NEON 吃得饱；稀疏矩阵(SpMV)的灾难是 gather——
每个非零元要按列下标 x[col[p]] 去取，地址不连续、不可预测，NEON 的连续 vld1q 用不上，只能标量。

两条出路（代码都给了）：

  1. CSR SpMV（spmv_csr）：简单正确，但本质是标量 gather，NEON 帮不上忙——除非一行内有连续段。
  2. BSR 4×4 块稀疏（bsr4_neon）：把矩阵切成 4×4 稠密块，块内连续 → vld1q 取块行、
    vmlaq 做 4 路点积，NEON 重新吃饱。这就是 NCNN/MNN 做结构化稀疏（如 2:4 结构化稀疏：
    每 4 个权重保留 2 个，块内规则可矢量化）的思路。结论：稀疏要”结构化”才能喂 NEON——这也呼应
    我们 L3 反复强调的”数据必须连续/对齐”旋钮。

六、其他典型 NEON 数学（softmax / 层归一化 / 激活 / 距离 / 快速倒数）

算子 NEON 关键指令 核心技巧 参考（标量）
softmax neon_exp_ps / vaddvq_f32 / vdivq_f32 先减 max 防溢出；exp 用 2^ix·2^frac 位技巧避免无 exp 指令 std::exp
layer_norm / RMSNorm vaddvq / vmlaq / vrsqrteq_f32(+牛顿) 均值/方差水平归约；vrsqrte 给 1/√，一次牛顿提精度 手算
sigmoid neon_exp_ps / vdivq_f32 1/(1+exp(−x)) std::exp
relu vmaxq_n_f32(0) 一行 max(0,x)
L2 距离 vsubq / vmlaq / vaddvq_f32 差平方累加后 sqrt 手算
快速倒数 vrecpeq_f32 / vrecpsq_f32 牛顿迭代免除法（1~2 步） 1/x

ARM 基线无 vexp 指令——所以 softmax/sigmoid 必须自带向量化 exp。代码里的 neon_exp_ps
用 x/ln2 拆整数/小数部，2^ix 直接拼 float 指数位，rel err ~1e-3，足够推理用。这正是
NCNN/MNN 在 requantize_arm.cpp、CommonOptFunctionNeon.cpp 里做归一化/激活的同类手法。

八、NEON 工程师能力清单（收官自检）

  • 原理层：说清 SIMD 比标量快在哪、编译器向量化的边界、AoS vs SoA、对齐。
  • 算子层：3x3 直接 / im2col / Winograd / FFT / 稀疏(BSR) / softmax / 层归一化 / 激活 / 距离，均能写 NEON 并标量化对拍。
  • 性能层：-fopt-info 读报告改码、perf/simpleperf 找热点、IPC/cache-misses 闭环。
  • 深度层：手写汇编、寄存器分配、指令调度(ILP)、Cortex-A 微架构(端口/带宽)、GEMM 微内核 walkthrough。
  • 演进层：SVE2 VLA+谓词一份内核跨 X2→X4/Neoverse；理解 NCNN(手写 NEON) vs MNN(委托 KleidiAI) 的后端分野。
  • 工程层：跨平台（ARM NEON + x86 SSE2 镜像）、正确性对拍优先、用 perf 验证而非拍脑袋。

一句话收尾：NEON 不是”记指令”，而是把计算重排成”连续、对齐、多条独立累加器链”，再用 ILP 喂满端口、用分块/预取喂饱带宽——上面的每个实例，都是这句话的具象化。L3 主线到此完整；后续支线只剩 CUDA 合并访问铁律（之前暂存）可接。

neon_l4_cmsis_dsp — CMSIS-DSP 库 API 语义可移植复刻（L4 工业扩展）

定位：本文补全 P2 neon 的「CMSIS-DSP」专题（L4 工业扩展层）。CMSIS-DSP 是 ARM Cortex-M 官方 DSP 库，提供 mat_mult / FIR / biquad / RFFT / PID 等算子。本沙箱无 ARM 目标、也未链入该库，因此可移植复刻其 API 语义并对拍一个独立参考，验证「库函数到底在算什么」。Cortex-M 真跑时只需把本文件实现替换为 #include "arm_math.h" 链接 CMSIS-DSP，调用处无需改动（这正是 CMSIS-DSP 的 API 设计价值）。

〇、动机：为什么是 CMSIS-DSP

场景 CMSIS-DSP 的角色
Cortex-M MCU（无 OS） 官方优化、可预测延迟的定点/浮点 DSP 原语
电机 FOC / 音频 Codec arm_pid_f32 闭环、arm_fir_f32 滤波、arm_biquad_* 均衡
传感器融合 arm_mat_mult_f32 坐标变换、arm_rfft_fast_f32 频谱分析
嵌入式「一处写多端编译」 同一份算法源码，x86 调试 + ARM 部署，仅后端库替换

本篇聚焦：把 5 个高频 API 的算法语义讲清、跑通、对拍，而不是调用 ARM 的汇编实现（那需要真硬件）。

一、原理

1. arm_mat_mult_f32 — 矩阵乘（行主序后乘）

C = A·B，维度 M×K · K×N → M×N，行主序 A[i*K+k]、B[k*N+j]。最朴素的 3 重循环，但 API 契约（维度顺序、主序、in-place 禁止）是 CMSIS 工程化的关键。

2. arm_fir_f32 — 流式 FIR（延迟线）

state[] 长度 = numTaps，state[0]=x[n]、state[1]=x[n-1]…，每步整体右移一位后累加 Σ h[k]·state[k]。零初史 → 等价于直接卷积。

3. arm_biquad_cascade_df1_f32 — 二阶节级联（Direct Form I）

每节系数 [b0,b1,b2,a1,a2]（约定 a0=1），每节状态 [x1,x2,y1,y2]。差分方程：

S 节级联：前节输出作后节输入。级联而非单高阶是为了数值稳定性与系数复用（与 neon SME / cali BA 同构：贡献逐节累加进输出）。

4. arm_rfft_fast_f32 — 实 FFT（N=8 演示）

基-2 DIT：位反转重排 + 3 级蝶形 + CMSIS 特有的打包输出 out=[Re0, Re(N/2), Re1,Im1, Re2,Im2, Re3,Im3]（只存实信号的共轭对称一半）。

5. arm_pid_f32 — 增量式 PID（含前次输出）

CMSIS 用 A0/A1/A2 形式：

⚠ 关键语义：y[n-1]（前次输出）参与递推，使该式构成积分而非纯差分。Kd=0 时退化为增量式 PI：y[n]=y[n-1]+(Kp+Ki)·e[n]-Kp·e[n-1]，逐拍累加积分项 Ki·Σe。

二、算法步骤（本篇复刻）

  1. 声明 5 个 arm_* 函数，签名/维度契约对齐 CMSIS-DSP。
  2. 各自实现可移植标量语义（x86 本机可跑）。
  3. 对每个函数构造独立参考实现（朴素 A·B / 直接卷积 / DF1 差分 / 朴素 DFT / 手算 PI）。
  4. 5 项断言对拍；ARM_CMSIS_DSP_LINKED 宏切换「语义复刻 / 真库」信息打印。

三、与仓库主线的关系

  • 与 L4.3 跨平台 SIMD 抽象：CMSIS-DSP 是「ARM 端 API 契约」，L4.3 是「后端抽象层」——二者叠加即「一处写、ARM/x86 双端编译」（本篇 x86 跑语义复刻，L4.3 跑宽度抽象）。
  • 与 L4.1 bf16 / L4.2 SME2：CMSIS-DSP 的 arm_mat_mult_f32 是 M 维累加，与 ΣᵢJᵢᵀΩᵢJᵢ（KF/LS 法方程）、SME ZA 外积同属逐外积累加 → SPD 系统范式。
  • 与 cali/Jacobian BA：biquad 级联的「逐节贡献累加」与 BA 的 Σᵢ JᵢᵀJᵢ 块累加同构。

四、代码走读（neon_l4_cmsis_dsp.cpp）

  • arm_mat_mult_f32：3 重循环，行主序索引（L22–32）。
  • arm_fir_f32：延迟线 shift + 累加（L38–47）。
  • biquad_section + arm_biquad_cascade_df1_f32：每节原地更新状态（L53–67）。
  • cfft8 + arm_rfft_fast_f32：位反转 + 3 级蝶形 + 打包（L73–101）。
  • arm_pid_f32：含 y1 前次输出的积分递推（L107–114）。
  • main：C1–C5 五组对拍（L130–211）。

五、验证（受管 Python 算法镜像 + C++ 控制流镜像，各 5/5 PASS）

六、自检（真实踩坑，已修）

  1. CMSIS arm_pid_f32 含前次输出 y1（关键）：初版写成 y=A0·e+A1·e1+A2·e2，漏掉 y1 → C5 退化成纯差分、与手算 PI 偏差大。修正后加 y1 递推，验证 Kd=0 ⇒ 增量式 PI 与 ΣKi·e 逐拍一致。
  2. biquad 状态切片副本 bug（Python 镜像侧）：初版 biquad_section 用 state[4*sec:4*sec+4] 切片副本，修改不回写级联 → C3 FAIL。改为传偏移 off 原地更新真 state。
  3. RFFT 打包约定：CMSIS 输出跳过 Re3/Im3 之后（共轭对称），只取 Re0,Re4,Re1,Im1,Re2,Im2,Re3,Im3——对拍只验 DC/Nyq/bin1/bin2 5 项即可。

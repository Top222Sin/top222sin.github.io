L4 SME/SME2 矩阵扩展 —— ZA 阵列 + 外积累加编程模型

定位：本篇是 P1 neon 矩阵线的「矩阵扩展」收口。承接 neon_l3_sve_kernels 的
SVE/SVE2 行点积 GEMM，把分解方式从「行点积」换成「外积」，引入 ZA 二维寄存器阵列
与 fmopa/smopa/bmopa 外积累加指令；并与 neon_l2_int8_gemm 的 int8 量化、
neon_l4_bf16 的 BF16/FP16 路径互引，点明 SME2 在推理后端（NCNN/MNN KleidiAI）
中的「sme2_mla/sme2_dot 档」落点。

一、为什么 SME/SME2

SVE/SVE2 的 GEMM（见 neon_l3_sve_kernels §一）按 行点积 分解：

$$
C[i][j] = \sum_{k} A[i][k]\cdot B[k][j]
$$

向量寄存器存 8 行的累加器，沿 K 维用 svmla 累加。SME 把分解方式换成 外积：

$$
C = \sum_{k=0}^{K-1} \text{outer}(A_{[:,k]},; B_{[k,:]}) ,\qquad
\text{outer}(u,v)[i][j] = u[i]\cdot v[j]
$$

每次 fmopa 取一列 A 与一行 B 做外积，累加进二维 ZA 瓦片。两种分解算同一个 GEMM，但 SME 把累加器从「若干向量寄存器」升级为「一张 SVL×SVL 的 2D 阵列」——算子数据复用率更高，是矩阵乘的「专用加速单元」。

ZA 硬件事实（ARM A64 指令集手册 / SME PRD）：SVL=128 时，ZA0.S 是一个 4×4
的 fp32 瓦片（S = SVL/32 = 4 lane）。整个 ZA 阵列是 SVL×SVL 的二维寄存器组，
通过水平/垂直切片 svld1_hor_za32 / svld1_ver_za32 读写。SME 在 streaming 模式
下运作，需 __arm_streaming / __arm_preserve_za 函数属性声明。

SME2（第二代） 在 SME 之上加 multi-vector 输入（Z+Z 拼成 256-bit 块，一条 mopa
抵两条 fmopa），并增 fp8 外积；同样走 ZA 外积累加模型，是推理后端的最高吞吐档。

二、指令语义（外积累加 = 三种精度）

指令 输入 累加器（ZA） 语义
fmopa fp32 列 × fp32 行 fp32 瓦片 za[i][j] += a_col[i] * b_row[j]
smopa int8 列 × int8 行 int32 瓦片 同上，int8 外积累加进 int32（防溢出）
bmopa bf16 列 × bf16 行 fp32 瓦片 bf16 外积累加进 fp32（累加精度=fp32）

一个 M×N GEMM = **K 次 fmopa**（一次吃一列 A 与一行 B 的外积），结果累加进 ZA。
本 demo 取单瓦片 M=N=4（适配 ZA0.S 4×4）、K=6 步外积，三种精度各自闭环。

三、代码走读（neon_l4_sme2.cpp）

本文件给三层，结构与 neon_l3_sve_kernels 同构：

  1. 标量参考 GEMM：三重循环 gemm_fp_ref / gemm_i8_ref，x86 本机可跑，作对拍基准。
  2. 可移植 ZA 外积累加模型（始终编译）：za_fmopa / za_smopa / za_bmopa 精确复刻
    「一列 ⊗ 一行 → 累加进瓦片」语义，x86 上也能对拍（本机无 ARM 时的确定性验证）。
  3. ARM 真 SME 内核（__ARM_FEATURE_SME 守卫）：__arm_streaming 属性 + svfmopa_za32_f32_m /
    svsmopa_za32_s8_m / svbmopa_za32_bf16_m，外积累加进 ZA tile（读出需遍历瓦片切片，给骨架）。

矩阵用 确定性公式填充（A[i,k]=(i*K+k)*0.1-1.0），C++ 与 Python 校验端逐位一致，
无 RNG 依赖——这是无 C++ 编译器环境下做 bit-exact 复核的关键（见下「验证」）。

四、你会看到什么（11 项对拍，确定性可复现）

受管 Python 3.13.12 镜像 C++ 控制流（float32 语义 faithful 复刻），11 项检查全 PASS。
除 F3 外均逐位一致（err=0）；F3 为 float32 重排噪声量级（见下），非严格 0：

# 检查 结果
A 外积分解 C=Σ_k outer(A[:,k],B[k,:]) == 标量 GEMM err=0
B fmopa 累加 ZA == 标量 GEMM（K 次 fmopa） err=0
C smopa int8 累加 ZA == int GEMM（int8→int32） err=0
D bmopa bf16 累加 ZA == bf16 标量 GEMM（bf16→fp32） err=0
E1 SME(fmopa 外积) == SVE2(行点积) err=0
E2 SVE2(行点积) == 标量 GEMM err=0
F1 fmopa 调用次数 == K（外积步数） OK
F2 ZA 瓦片边长 S=SVL/32=4 OK
F3 fmopa 乱序累加近似不变（外积可交换，fp32 噪声） err≈6.0e-8（< 1e-5 tol）
F4 ZA 读出 == GEMM C[0][0] err=0
F5 bmopa 路径与 smopa 路径各自自洽 err=0

最值得记的洞察：E1/E2 证明「外积分解（SME）」与「行点积分分解（SVE2）」算同一个
GEMM——这正是 SME 不改变结果、只改变算子数据复用方式的理论根基；F3 证明外积累加在 fp32
下近似可交换（重排 K 步累加仅引入 ≈6e-8 舍入噪声，远小于 GEMM 量级），意味着调度器可自由
重排 K 步 fmopa 的发射顺序而不影响结果精度（误差远低于 GEMM 本身精度，非严格 0）。

五、互引 / 落点

  • 承接：neon_l3_sve_kernels 的 SVE2 行点积 GEMM（§一）→ 本篇把分解换成外积 + ZA。
  • 精度谱：smopa（int8→int32，承接 neon_l2_int8_gemm 的 int8 量化主线） /
    bmopa（bf16→fp32，承接 neon_l4_bf16 的 BF16 路径）/ fmopa（fp32 基线）。
  • 真实后端：MNN cmake/KleidiAI.cmake 拉取 kai ukernel 的 sme2_mla/sme2_dot 档；
    NCNN gemm_int8.h 在 I8MM/SDOT 之上，新核（V9-A+SME2）改用 SME2 mopa。
  • 跨域：ZA 外积累加与 [[KF_demo]] 里的「信息矩阵按因子累加」（[[kf_l3_factor]]）同构——
    都是「把贡献逐个累加进一个矩阵」的范式，一为 GEMM、一为 SLAM 因子图批优化。

参考：ARM A64 指令集手册 SME/SME2 章；MNN cmake/KleidiAI.cmake；Arm KleidiAI ukernel 文档。

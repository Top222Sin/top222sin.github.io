neon_demo 内容审查报告

审查对象：02jd/neon_demo/（README.md + 6 篇课程 .md + 13 个 .cpp + _diagrams.html + images/ 23 张 SVG）
审查日期：2026-08-18
审查维度：ARM NEON/SVE/SVE2 架构事实、微架构数字（延迟/吞吐/端口）、指令语义、算法正确性（卷积/Winograd/FFT/GEMM/稀疏/量化）、文档一致性
说明：本 demo 以”.cpp 注释即讲解 + md 详述 + 内联 SVG”为形态；本报告通读了全部 6 篇 md（约 94KB），并核对了可静态验证的 ARM 架构/微架构事实。

〇、总体结论

  • 整体质量极高：6 篇 md（L3 汇编 / 微架构 / GEMM / SVE2 / SVE 三件套 / 实例大全）覆盖 ARM 向量化最深的角落，我核验的架构与微架构事实几乎全部正确——这是 8 个知识库中硬件/体系结构准确度最高的一个：
    • AAPCS64 保存约定（V0–V7/V8–V15/V16–V31）、AArch32 寄存器、SDOT 语法、svld1/svmla/svwhilelt 语义全部正确；
    • 微架构表（A53/A57/A72/A73/A75/A76/A77/A78/X1 的 FMLA 吞吐/延迟、A76=2 管×4 周期=8 MAC/cyc、int8 sdot=32 MAC/cyc、A78 内存带宽提升）与 ARM 官方指南一致；
    • GEMM 分块/打包工作集（8KB+4KB 进 L1）、微内核三档 vs 端口数、Winograd 9→4 乘、FFT SoA 蝶形、BSR/2:4 结构化稀疏、neon_exp 位技巧、vrsqrte 牛顿——全部正确。
  • 未发现确定性硬错误；有 2 处架构版本标注不精确（SVE2 篇表格）、1 处代码片段小瑕疵（SVE 三件套篇）与 1 处结构说明（7 个 cpp 无配套 md）。
  • 方法说明：本机无 C++ 编译器且非 ARM 环境，NEON/SVE 内核无法编译运行；结论基于 ARM 公开架构文档与指令语义的静态核验。

一、发现的问题（⚠️ 均为轻微，无 ❌）

W1. ⚠️ neon_l3_sve2.md —— 架构版本表两处不精确

第 25–35 行表格：

  • **Neoverse-V1 标 “Armv9.0 + SVE2”**：V1 实际是 Armv8.4-A + SVE（第一代 SVE，非 SVE2）；Neoverse V2 才是 Armv9.0-A + SVE2。表格把 V1 与 V2 混为一谈（V1 用 SVE、V2 用 SVE2，向量长度同为 256-bit 但指令集代际不同）。
  • Cortex-X1 标 “Armv8.2”：此条经独立复核为误判，已撤销——ARM 官方 Cortex-X1 Core TRM r1p1 明确 “Full implementation of the Armv8.2-A”，X1 基础架构确为 Armv8.2-A（额外实现 8.4 的 dotprod 扩展），md 表格写 8.2 正确。详见第六节。

影响：不影响”SVE2 是 Armv9 标配 / A76/A78/X1 无 SVE”这一核心论点，但学习者按此表记忆架构版本会出错。建议按官方白皮书修正 X1 与 V1 两行。

W2. ⚠️ neon_l3_sve_kernels.md —— requantize 伪代码小瑕疵 + 编译旗可疑

  • 第 176–180 行：第 179 行算出 i8 = svqxtnb(...) 后，第 180 行却写 svst1b_s32(pg, out, i32)（存的是 i32 而非刚算出的 i8）——i8 变量未使用，片段自相矛盾。应改 svst1b_s8(pg, out, i8)（或说明”以 int32 低字节承载 int8”的意图）。
  • 第 69/104 行编译旗 -march=armv8.2-a+i8mm+dotprod+sve+sve2+fp16：经核对 MNN 仓库 cmake/KleidiAI.cmake 实际内容，该 flag 并非实摘——KleidiAI 实际分两档：NEON 档 armv8.2-a+i8mm+dotprod+fp16，SME2 档 armv8.2-a+sve+sve2。md 把两档合并了。sve2 需要 Armv9 基础，与 armv8.2-a 组合不合法/被拒绝——此条经独立复核为误判，已撤销：GCC 10+/Clang/armclang 均接受 armv8.x-a+sve2（SVE2 可作为 Armv8 可选扩展启用），且 KleidiAI.cmake 的 SME2 档生产环境实际就用 armv8.2-a+sve+sve2。详见第六节。

W3. 📋 结构说明（非错误）：7 个 cpp 无配套 md

neon_demo.cpp / neon_l2_gather_prefixsum.cpp / neon_l2_int8_gemm.cpp / neon_l1_lut.cpp / neon_l1_mat3x3.cpp / neon_l1_optinfo.cpp / neon_l2_profiling.cpp 共 7 个 cpp 只有代码（注释即讲解），无 .md 与 _diagrams.html——与兄弟仓库”每知识点三件套”约定不一致（README 已说明这些是”参考手册”，属有意为之）。若要保持知识库统一形态，建议为这 7 个补齐 md，或在 README 中明确”代码即文档”的例外清单。

二、已核验正确的内容（✅ 重点）

1. 架构 / ABI 事实（全部正确）

  • AArch64 32×128-bit V 寄存器；AArch32 32×64-bit D / 16×128-bit Q ✓
  • AAPCS64：V0–V7 与 V16–V31 调用方保存、V8–V15 被调方保存 ✓（ncnn”免保存区”策略合理）
  • sdot Vd.4s, Vn.16b, Vm.4b[idx] 语法（1 条=16 次 int8 MAC）✓

2. 微架构数字（与 ARM 官方指南一致）

声明 核验
A53/A55 1 FMLA/cyc（latency 4~6）；A57/A72 2/cyc；A73 1/cyc；A75 2/cyc；A76 2/cyc × latency 4；A77 3/cyc；A78 2/cyc；X1/X2/X3 4/cyc ✅
A76 发射宽 8 μop/cyc、双 NEON 管、FMLA 延迟 4/吞吐 2、VADD 延迟 2 ✅
A76 fp32 fmla = 8 MAC/cyc；int8 sdot = 32 MAC/cyc ✅
A76 L1D ~32B/cyc；A78 相对 A77 内存带宽大涨（load +50%/store 翻倍） ✅
工作集 MR=8/NR=4/KC=256 → A 8KB + B 4KB 进 64KB L1D ✅

  • svcntw() 运行时向量长度、VLA 编程模型、svwhilelt_b32 谓词、svld1/svmla/svst1 带谓词语义 ✓
  • HWCAP_SVE 双路分发、独立 TU + -march=armv9-a+sve2 编译策略 ✓

4. 算法与实例（全部正确）

  • GEMM 分块/打包（GotoBLAS 式）、微内核 4×4/8×4/16×4 vs A76(2管)/X1(4管) 三档对应 ✓
  • 3×3 直接 vext 滑动（ncnn conv3x3s1_neon 同款）；im2col+GEMM；Winograd F(2,3) 9→4 乘 ✓
  • FFT 基-2 蝶形 + 复数 SoA（4 lane = 4 只蝴蝶）✓；BSR 4×4 / 2:4 结构化稀疏 ✓

  • ncnn/MNN 源码落点（gemm_arm.cpp:2455、gemm_int8.h:10018、convolution_3x3_winograd.h 三变换、requantize_arm.cpp、MNN KleidiAI 分档）与本工作区备份一致 ✓

L4.4 CMSIS-DSP 语义复刻（neon_l4_cmsis_dsp）

L4.5 音频 DSP 核（neon_l4_audio_dsp）

  • 验证 5/5 PASS：peaking DC=1 且中心频增益=10^(dB/20) / 压缩器稳态幅度=thr+(lv-thr)/ratio / overlap-add==直接全卷积 / 重采样对线性斜坡精确 / LP@Nyquist≈0·HP@DC≈0。

L2.5 误差校验方案（Error check）⭐

L1 让你”能跑通五个标定”。L2.1–L2.4 让你”知道误差从哪来”。但标完之后，怎么用一句话回答”这套参数到底准不准”？ 本篇给出一套可落地的量化指标，并在合成数据上闭环对拍。

一、为什么要专门做误差校验

标定算法（无论是 OpenCV 的 calibrateCamera 还是自写的 solveHandEye）都会返回一个”解”。但：

  • 重投影误差 0.3 px 不代表末端引导误差 0.3 mm——两者量纲和单位都不同。
  • 一个小的系统性残差（如边缘径向残差偏大）比一个大的随机残差更危险：它意味着模型本身就错了（畸变阶数不够、板不平、相机非理想针孔）。
  • 不同环节（内参 / 手眼 / TCP）的误差会层层传递，需要各自的指标分别监控。

本 demo 把四个环节的误差指标化，全部用合成数据 + 真值对拍，跑完即出 PASS/FAIL。

误差校验的”分工”（每个指标回答什么）

工程认知：四类指标缺一不可——只看 RMS 会被过拟合骗（L2.1），只看真值对拍需要合成数据（真机没真值），只看自洽会被”都错但自洽”骗（噪声大时 AX=XB 残差小但 X 偏）。

二、四类指标

① 内参误差：逐图重投影误差

calibrateCamera 返回的全局 RMS 是所有观测点重投影残差的均方根（RMS = sqrt(Σ‖eᵢ‖²/N)，按点聚合而非简单逐图平均）；逐图统计能暴露”某一帧异常”。本 demo 同时报均值 / 最大 / 总体 RMS，并断言 RMS<2px && max<3px（示例阈值，实际应按图像分辨率/视场/应用容差标定）。

② 手眼误差：AX=XB 一致性残差 + 真值比对

手眼解 X 必须使所有相对运动满足 A_i · X ≈ X · B_i。定义一致性残差：

  • 一致性残差（不依赖真值）：验证你解出来的 X 内部自洽。
  • 真值比对（需合成真值）：X_est 与 X_gt 直接比，给出”绝对误差”。
    本 demo 同时打印两者，证明”自洽”≠”正确”的边界（噪声大时两者都会涨）。

③ TCP 误差：多点一致性

四点法求出的 x（TCP）应满足：任意法兰位姿 R_i,t_i 下，尖点都落在世界同一点：

本 demo 用 8 个姿态求 x，再算最远两点尖点距离，断言 <1mm。

④ 系统性 vs 随机残差：按半径分箱 ⭐（本篇核心）

这是区分”模型错”与”纯噪声”的关键手法：

  1. 计算每检测角点到主点 (cx,cy) 的归一化半径 r = ‖p-(cx,cy)‖ / R_max。
  2. 分箱：中心 r<0.35 vs 边缘 r>0.7。
  3. 比较两组重投影误差：
    • 随机噪声（模型对、只有检测噪声）→ 中心与边缘误差相近（均匀）。
    • 模型错（如真实 6 参畸变却只标 4 参）→ 边缘误差远大于中心（系统性，呈径向趋势）。

随机噪声”中心≈边缘”的适用条件

该结论只在同方差像素噪声 + 角点检测精度与位置无关 + 分箱样本充足的仿真/理想条件下成立；真实场景中边缘角点常因畸变、模糊、斜视而随机误差更大——“中心≈边缘”应作为合成同方差噪声下的基线判据，实机应用需谨慎。

工程价值：这是”诊断”而非”验收”——比值大说明换模型（加畸变项），比值≈1 说明加帧/降噪。把”该换模型”和”该加数据”区分开，是标定调试的核心技能（注意：主点偏移通常表现为整图偏置残差场而非单纯径向趋势，诊断要结合残差矢量图，不只看半径分箱）。

三、系统性 vs 随机：工程意义

现象 含义 处置
残差大但中心≈边缘 纯随机噪声（角点检测、机器人读数） 加帧 / 降噪，无法靠换模型改善
边缘 ≫ 中心 径向系统性残差（畸变阶数不足 / 板不平 / 主点偏） 换更全的畸变模型、查标定板平整度
某方向系统性偏大 切向/薄棱镜项或相机非正 加切向参数、检查相机安装
单图异常大 该帧检测/读数坏点 进 L3.2 鲁棒剔除

四、代码走读（cali_l2_error_check.cpp）

  • 顶部复用 solveHandEye（Park–Martin 式单位四元数分离求解；不是 Daniilidis 对偶四元数，术语见 L1.5/L2.2 注记）。
  • ① calibrateCamera → 逐图 projectPoints 残差（mean/max/std）。
  • ② 合成 X_gt，配 A_i=G_i⁻¹G_{i+1}、B_i=T_iT_{i+1}⁻¹（眼在手上配对方向），解 X_est 后算一致性残差 + 真值误差。
  • ③ 四点法解 x，算多点尖点最大距离。
  • ④ radialTest(lambda)：参数化真实畸变 dreal 与是否加随机噪声，分箱报中心/边缘误差，C++ lambda 实现可复用。

五、工程落点（真实项目）

  • easy_handeye：标定后输出 hand-eye error（AX=XB 残差）——就是本 demo 的指标②。
  • Halcon calibration report：每图残差 + 总体 RMS——指标①的行业版。
  • 机器人产线验收：端到端”够取验证”（L3.1）才是最终指标——本 demo 的指标是”中间体检”，L3.1 是”期末考”。
  • 与 UR5e 仿真项目：手眼标定后，用”机器人照着标定结果去抓一个已知点”验证——误差 <1mm 才上线（L3.1 的够取验证就是它）。

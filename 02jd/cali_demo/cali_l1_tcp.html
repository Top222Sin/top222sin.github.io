L1.4 TCP 标定（Tool Center Point）

在内参、手眼之前，得先知道”工具尖究竟在法兰的什么位置”——否则所有作业坐标都差一个工具偏移。

一、什么是 TCP

TCP（工具中心点）是工具坐标系原点在法兰（tool0）系下的坐标 x：

它可能是焊枪尖、夹爪中心、吸嘴……是机器人”真正去够”的那个点。

为什么 TCP 是”标定”不是”设置”

工具是机械安装的，安装误差（夹具公差、人工装夹）让 TCP 与 CAD 名义值差几毫米——直接拿 CAD 值用，末端误差就是这几毫米。四点法用”碰同一个固定点”的几何约束反推真实 x，把安装误差实测出来。

二、四点法（求位置）

让工具尖以 4 个以上、互不共轴的姿态去碰空间中同一个固定点 P。每姿态记录法兰位姿 (R_i, t_i)，则：

最少姿态数与退化：未知 x 有 3 个分量，数学上 3 个姿态（堆叠 (R₂−R₁), (R₃−R₁)）在旋转轴非平行时即可满秩求解——“4 点”是工程惯例（冗余 + 抗噪），不是严格最小条件。同轴旋转时 (R_i−R_1) 的秩通常为 2（非 1）：沿公共旋转轴方向的 x 分量不可观（(R_i−R_1)·e_axis=0），垂直方向两分量仍可约束。工程要求：姿态绕 ≥2 个不同轴转、转角足够大（数值条件好），并检查系数矩阵秩/条件数——这是”退化”的雏形（L2.3/L2.4 系统讲）。

四点法为什么要求”姿态多样”（代数原因）

工程结论：四点法的核心不是”4 个点”，是”4 个旋转多样的姿态”——示教时让工具尖在保持碰尖的同时，法兰摆出不同的俯仰/横滚/偏航组合（L2.4 的蒙特卡洛实验量化了这一点，直接判据是系数矩阵条件数）。

六点法（补姿态，按控制器约定）

四点只定位置。再加 2~3 个参考方向可定工具坐标系姿态（Z 轴 = 工具接近方向，X/Y 按右手系补齐）——具体”哪个点定哪个轴”取决于机器人控制器的示教约定（UR 的 TCP 标定流程、KUKA 的 TOOL 标定各有规定），没有统一的”从 P0 指向 P1 即 Z 轴”的通用公式。示教器里的”TCP 标定”通常 = 多点定位置 + 参考方向定姿态。

四、代码走读（cali_l1_tcp.cpp）

  • 造真值 x_gt，反算各姿态 t_i = P - R_i·x_gt，使尖都落在同一点 P。
  • 仅用 (R_i, t_i) 反估 x：堆叠 (R_i - R_1)x = t_1 - t_i，cv::solve(SVD) 求解。
  • 无噪声 → 误差应≈0；加 1 mm 噪声 → 误差与噪声同量级（演示鲁棒性）。
  • 同时校验”所有姿态下 R_i·x + t_i 都≈P”（一致性）。

五、与手眼标定的关系

TCP 是”法兰↔工具”的标定，手眼是”相机↔法兰”的标定。两者都是求一个固定的刚体变换，且都怕姿态退化。L2.4 会讲它们如何联合。

链路与依赖（TCP 不是手眼求解的数学前置）

关键澄清：经典手眼标定的输入是 T_gripper2base（法兰/tool0 的 FK）+ T_target2cam（PnP）——TCP 数值不参与手眼求解。TCP 影响的是视觉引导执行（像素→工具→基座的坐标链末端）：TCP 错了，机器人”够”的目标点就偏。工程上先标 TCP（独立、纯机械）是流程惯例（统一工具坐标系便于采集与复现），不是数学依赖——先手眼后 TCP 也能算，只是后续够取验证会混入 TCP 误差。

六、工程落点（真实项目）

  • UR 示教器：Setup TCP 就是四点法（Move → 碰尖 → 记录，4 次不同姿态）——你的 UR5e 项目如果装工具，这一步是标配。
  • KUKA/ABB：TOOL_DATA 标定同样基于多点法；带激光/接触式测头的自动 TCP 标定是同一数学。
  • 焊接/点胶机器人：焊枪尖、胶嘴中心都是 TCP——更换工具后必须重标（工具磨损也会漂移）。
  • 与 08robot：UR5e + 末端相机/夹爪的作业里，TCP 是”视觉引导够取”（L3.1 validation）的坐标基准。

七、自检

  • 把 6 个姿态改成”都绕 z 轴转不同角度”，看 cv::solve 是否退化（误差暴涨或解漂移）。
  • 把姿态数降到 3，看方程欠定（体会 ≥4 的必要性）。
  • 挑战：为什么四点法对”法兰平移噪声”比对”旋转噪声”更敏感？（平移噪声直接进 t_i，旋转噪声经 R_i·x 放大——x 越大旋转噪声放大越狠）

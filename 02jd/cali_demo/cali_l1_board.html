L1.2 标定板（Calibration board）

标定板是”相机看到的世界坐标”的唯一来源。它的精度决定了整个标定链的上限。

一、三类主流标定板

类型 OpenCV 检测函数 优点 缺点 / 适用
棋盘格 Chessboard findChessboardCorners 角点定位极准、最常用 角点非唯一纹理，需全板可见
圆点阵 Circular grid findCirclesGrid（对称/非对称） 圆心亚像素稳定、抗模糊 需高对比圆
Charuco detectCharucoBoard(aruco) 部分遮挡也能用、自带 ID 依赖 aruco 模块、打印要求高

非对称圆点阵（asymmetric） 打破 180° 旋转对称歧义，使板位姿解唯一（对称阵检测存在方向二义性），机器人手眼标定里更受推荐。本 demo 用对称阵演示检测原理。

为什么非对称板位姿唯一（二义性来源）

对称棋盘/圆点阵在旋转 180° 后看起来完全一样——检测器会随机返回两个方向之一，导致该帧外参相差 180° 旋转。手眼标定（L1.5）里这种”翻转帧”就是坏数据：

工程结论：手眼标定/双目标定强烈建议非对称板或 Charuco——省掉”翻转帧剔除”这个麻烦。

二、检测流程（棋盘格）

亚像素角点是标定精度的命门：像素级角点误差会直接变成内参/手眼误差。

亚像素优化的原理（为什么能到 0.1px 级）

cornerSubPix 利用”角点处灰度梯度与图像到角点向量正交”这一性质迭代：

核心洞察：亚像素定位把”一个像素的离散角点”优化到”连续位置的局部最优”——利用的是角点邻域全部像素的梯度信息（信息量远大于单点）。这就是”像素级检测”和”亚像素级标定”之间的那座桥。

三、最关键的映射：角点 → 3D objectPoints

角点本身是 2D 像素，但标定需要它在板系下的 3D 坐标：

squareSize 必须用真实物理单位（mm）。如果格子实际是 25 mm 却填成 1，Recovery 出的内参会差 25 倍——这是新手最常见的坑。

squareSize 的量纲影响（为什么 K 不变但公制结果错）

工程铁律：objectPoints 的单位 = 你要的输出单位。若下游要 mm 级结果，squareSize 填 mm；要 m 级，填 m——单位必须贯穿整条链一致。手眼标定后若发现”距离全差一个比例”，先查 squareSize（这是”系统性错误不报错”的典型案例，L2.5 的误差校验里用公制对照抓它）。

四、代码走读（cali_l1_board.cpp）

  • 用 rectangle 合成一张无畸变棋盘图，findChessboardCorners + cornerSubPix 找回角点，与”理想内交点”比对，亚像素后误差应 < 2 px。
  • 圆点阵同理，用 findCirclesGrid + 对称网格，圆心误差同样 < 2 px。
  • 第 3 段演示 objPoints 的生成（含真实 squareSize_mm），即送进 calibrateCamera 的 3D 输入。
  • 全过 → [PASS]。

五、实践要点（来自相机标定 guide）

  • 打印/粘贴要平整、不反光；相机对焦清晰（离焦会让角点模糊、误差暴涨）。
  • 采集姿态要覆盖全视场 + 多距离 + 多倾斜，别只拍正对板的一堆图。
  • Charuco 适合现场”板子被手/机械臂挡住一部分”的场景。

姿态多样性的物理理由（为 L2.1 埋伏笔）

一句话：标定板的姿态多样性 = 内参方程组的”可观测性”（L2.3 的退化思想在单目标定里的体现）。

六、工程落点（真实项目）

  • OpenCV 标定工具：opencv_interactive-calibration（交互式采集）、calibrateCamera 的文档示例——全部基于本 demo 的”棋盘检测 + objectPoints + 标定”流程。
  • ROS camera_calibration 包：cameras.yaml 的输出就是 K + 畸变（本 demo 内参标定的产物格式）。
  • Kalibr（视觉惯性标定）：用自定义棋盘/圆点板 + 多相机，产线级标定工具。
  • 机器人手眼标定套件：eye-in-hand 现场标定通常用非对称圆点板（本 demo 建议的）挂在机器人可达区域。

L3.3 自动/在线标定系统

前 12 篇都是”单个算法怎么写”。这一篇把它们编排成一个会自检、会报警、会出报告的系统模块——这才是产线真正要的东西。

一、系统的样子

CalibSystem 把 L1/L2 的全部环节串成一条自动化链，并加上 “质量闸门” 与 “再标定触发”：

代码里对应：

  • makeCapture()：生成一组”采集”（机器人各姿态下看到的标定板 + 上报的法兰位姿）。
  • runPipeline()：依次跑内参（calibrateCamera）→ 手眼（solvePnP+对偶四元数解 X）→ TCP（四点法）→ 误差校验（重投影 RMS、AX=XB 残差、TCP 一致性），产出 CalibReport。
  • 质量闸门：ok = RMS<2px && 手眼<0.5°/1mm && TCP<1mm；任一超阈 → needsRecalib=true。

系统设计的两大原则（模块化 + 闸门化）

工程洞察：自动系统的价值不在”算法更准”，而在”把算法串起来 + 不让坏数据流过“——单环节再准，闸门缺失也会被一帧坏数据毁掉（L3.2 的教训）。

二、在线再标定触发（本篇核心）

标定不是一次性的。温漂、负载变化、机械磨损都会让参数慢慢失效。系统用同一套误差校验指标做监控：

  • 周期性用当前参数做误差校验（或端到端够取验证，见 L3.1）。
  • 指标越过阈值 → 自动 needsRecalib=true，机器人暂停该视觉任务、重新采集标定。
  • 本 demo 用 driftDeg 参数模拟”机器人上报位姿带 1.5° 温漂”——注意这是单元测试注入（固定旋转偏移），不代表真实温漂的全部机理（关节零点漂移/热变形/负载挠曲/随时间变化的非刚性误差）；它验证的是”检测逻辑：位姿误差超阈→触发再标定”，不能宣称验证了真实温漂检测。

再标定触发的决策树（什么时候重标）

工程结论：再标定不是”全部重来”——按诊断结果做最小重标（单环节 or 全量）省时间且避免引入新误差。漂移曲线的趋势分析（L3.4 的报告入库）能提前预测”该维护了”。

报告的可追溯性（ISO 质量体系视角）

工程细节：报告不只是给人看——落库做趋势分析是自动系统的进阶价值（L3.4 pipeline 的”报告入库”扩展点）。质量体系（ISO 9001/13485）要求标定可追溯，报告就是追溯载体。

四、可扩展方向

  • 多相机/多机器人统一标定：把 Capture 扩成多设备，共享一个世界系。
  • 增量更新：温漂不大时，只在新数据上做 LM 精修（L3.2 信息加权），不必全量重标。
  • 报告入库：把 CalibReport 落库，做长期漂移曲线与可追溯性（ISO 质量体系常用）。
  • 主动运动规划（D-最优）：L3.2 已铺垫”采样最优设计（D-最优）”概念，但本篇”auto_system 仅蜻蜓点水”。完整落地见 L4.3 自标定/主动标定——用观测矩阵 AᵀA 的行列式/奇异值量化”信息量”，证明同 z 轴旋转→亏秩退化、异轴旋转→满秩，并给出”三组异轴旋转比两组 det 更大”的主动运动规划准则，把 auto_system 的补齐为可执行的规划章。

五、代码走读（cali_l3_auto_system.cpp）

  • 顶部复用 solveHandEye（对偶四元数）与变换工具。
  • makeCapture：用真值 Xgt/K/d 投影生成检测角点；driftDeg>0 时给管线位姿叠加小旋转模拟温漂。
  • runPipeline：内参 → 逐帧 solvePnP 得 T_target2cam → 配相对运动解手眼 → 四点法解 TCP → 质量闸门。
  • 主函数跑两个场景，断言”健康通过、温漂触发”。

六、工程落点（真实项目）

  • easy_handeye + 产线集成：采集→求解→发布 tf 全自动，加”复测闸门”就是本 demo 的自动系统。
  • UR/协作臂的标定 App：URCap 里有”自动 TCP 标定”——四点法自动跑 + 报告。
  • 汽车产线视觉工位：相机标定自动化 + 定期复测（防温漂）——质量闸门+再标定触发是标配。
  • 与 08robot：UR5e + 相机的手眼标定脚本化（本 demo 的 runPipeline）——从手动标定升级为”一键标定 + 报告”。

七、下一步

进 L3.4 全流程工具链（capstone）：一条龙跑完，并故意注入退化数据验证检测+告警。

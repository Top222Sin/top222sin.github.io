L2.4 TCP 标定深入

L1.4 让你”能求出 TCP”。L2.4 讲清：求出来的值有多准、什么情况下会突然不准、以及它和手眼标定的先后关系。

一、误差传播（蒙特卡洛）

TCP 求解的输入是法兰位姿读数（来自机器人正运动学）。位姿读数噪声（平移 + 旋转）与触碰点测量误差会传到 TCP。本 demo 用蒙特卡洛（300 次/档，平移噪声 0.5/1/3 mm）验证：在仅含平移噪声的仿真条件下，TCP 估计误差随输入噪声单调增大。注意：真实 TCP 精度还受机器人绝对定位误差、姿态读数噪声、触碰测量误差、工具挠曲、温度漂移等系统误差限制——“TCP 精度上限 ≈ 机器人重复定位精度”只在”其他误差可忽略 + 姿态条件良好”时近似成立。

误差传播的定量（扰动界 vs 标准差）

工程结论：想提高 TCP 精度，两条路——① 更高精度的位姿来源（激光跟踪仪等外部测量）；② 改善姿态几何（降低条件数，L2.3 的退化思想）。姿态多样性是免费的精度提升。

二、共面退化（⚠ 和 L2.3 同源）

四点法本质是”球心拟合”，系数矩阵 A = [(R_i-R_1)]（来自 (R_i-R_1)x = t_1-t_i）。关键是法兰旋转要多样：若旋转 (R_i) 多样性不足，(R_i-R_1) 秩亏，球心沿该方向不可观 → A 病态（条件数暴涨）→ TCP 误差放大。实践中”法兰位置共面”常伴随旋转单一，但直接判据是旋转多样性/系数矩阵秩，而非位置共面本身。

  • 避免：让工具尖触碰同一点时，法兰要摆出不同高度/不同倾斜，使法兰位置在 3D 里散布开（≥4 个不共面姿态）。

“共面”为什么是表象（直接判据是旋转）

工程铁律：别纠结”位置共不共面”，直接看 cond(A)（本 demo 的 solveTCP 返回它）——条件数大就补姿态，不管位置看起来多散。

三、与手眼标定的关系

  • 数学依赖：经典手眼标定的输入是法兰 FK 位姿 + T_target2cam（PnP）——TCP 数值不参与手眼求解（若控制器 API 返回的是 TCP 位姿而非 tool0 位姿，则需先解出法兰位姿，此时 TCP 误差会进入手眼输入）。
  • 流程惯例：通常先标 TCP（工具），再标手眼（相机↔法兰）——统一工具坐标系便于采集与复现，是工程流程建议而非数学前置。
  • 端到端影响：视觉引导链 像素 → camera → X⁻¹ → flange → TCP⁻¹ → base 的坐标方向必须写清（X 是 T_flange_cam 还是 T_cam_flange 决定用不用逆）；像素反投影还需要深度/平面约束，不能由像素直接得 3D 点。
  • 联合优化：高精度场景可把 TCP 与手眼一起迭代优化（L3 鲁棒/自动系统会触及）。

四、代码走读（cali_l2_tcp_deep.cpp）

  • solveTCP() 复用四点法，并额外返回 A 矩阵条件数。
  • 实验1：三档噪声蒙特卡洛，报告 TCP 均误差。
  • 实验2：非共面 vs 共面，对比 A 条件数与 TCP 误差。
  • 断言：噪声越大误差越大；共面条件数 ≫ 非共面且误差显著放大。

五、工程落点（真实项目）

  • UR 示教器 TCP 标定：实际就是四点法 + 条件数提示（”姿态变化不够”警告）——本 demo 的 cond(A) 检查就是它内部的逻辑。
  • 激光跟踪仪辅助标定：外部测量（Leica/API）把”碰点”精度提到 0.01mm 级——TCP 精度上限随之提升。
  • 接触式探头标定：机器人自动探针碰参考球，多姿态自动采——流程自动化 + 条件数监控。
  • 与 UR5e 仿真项目：UR5e 换工具（夹爪/相机支架）后重标 TCP，是手眼标定前的必备步骤。

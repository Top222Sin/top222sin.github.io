L3.1 验证方案（Validation）⭐

L2.5 回答”参数准不准（残差层面）”。L3.1 升级为：标完这套参数，机器人按它干活，实际偏差多少？ 这是标定真正要兑现的承诺。

一、为什么需要端到端验证

重投影误差 0.3 px 看起来很美，但：

  • 它是内参+外参的混合残差，不直接对应机器人末端偏差。
  • 真实工况下，误差会沿 内参 K → 手眼 X → TCP 整条链放大/耦合。
  • 客户/产线要的是一句话：”用这套参数引导机器人到目标，偏差 < X mm”。

所以验证必须端到端：用估计参数驱动一次”看—算—动”闭环，量实际偏差。

残差层面 vs 端到端（为什么中间指标不够）

工程结论：中间指标”全 PASS”不代表端到端”能干活”——距离/几何把角度误差放大成位置误差。这就是为什么 L3.1 的够取验证是”出厂标准”。

两级验证的界定（重要）：本文的”投影验证 + 够取验证”属于模型链验证（用估计参数做前向/反投影计算，仿真闭环）；真正的机器人端到端验证还需包含：机器人执行、TCP 运动、外部测量实际到达点、时间同步等——合成数据只能证明”模型链在给定噪声模型下自洽”，不能替代实机验收（L3.4 同理）。

二、两类验证指标

① 投影验证（已知 3D 目标 → 像素）

已知世界点 P（如标定板上某角点的真实坐标），用估计参数 K_est, X_est 把它投成像素 u_est，与相机实际观测到的像素 u_true 比较：

它等价于”把标定结果拿去重投影一个全新的已知点”，比用标定帧自身的重投影更严格（不沾训练集）。

② 闭环够取验证（像素 → 够到点）⭐（本篇核心）

模拟一次视觉引导抓取：

  1. 相机看到目标像素 u（由真值链生成，当作”检测到的像素”）。
  2. 系统用估计参数 K_est, X_est 把 u 反投影到已知高度平面 z=z_t（u 本身无深度，靠已知目标高度补）。
  3. 指挥 TCP 移动到该 3D 点。
  4. 比较到达点与真值目标的 3D 偏差：

本 demo 用两组标定质量对比：

  • 好标定：手眼旋转扰动 ≈0.3°、平移 ≈0.5 mm，焦距偏 0.5%。
  • 差标定：旋转 ≈3°、平移 ≈5 mm，焦距偏 5%。

结果应显示：好标定两类误差都小（<2 px / <2 mm），差标定的误差明显更大（>2×）。

够取验证的误差源分解（为什么好标定 <2mm）

工程洞察：够取误差 ≈ 手眼旋转误差×距离 + 平移误差（一阶近似）——旋转误差被距离放大，这就是为什么手眼标定的验收阈值（如 L2.5 的 0.5°，需结合工作距离/目标容差确定，非脱离工况的固定值）通常很严苛。

三、工程含义

验证结果 解读 处置
投影 & 够取误差都小 标定可用，进入产线 记录为基线，定期复测
投影小但够取大 手眼/外参误差被内参”掩盖” 查 L1.5/L2.2 手眼标定
两者都大 标定整体失败 重标，查 L2.3 退化 / L3.2 坏帧
多次复测漂移 温漂/负载漂移 触发 L3.2/L3.3 在线再标定

诊断树（怎么读验证结果）

工程价值：端到端验证不只是”过/不过”——它是诊断工具：投影 vs 够取的分裂模式直接指向出错环节（这也是为什么两个指标都要测，缺一个就失去诊断力）。

四、代码走读（cali_l3_validation.cpp）

  • projectPx()：完整链 world → (inv(G·X)) → cam → 像素。
  • backprojPlane()：像素 u 经 K_est⁻¹ 得相机系射线，用 T_cam2base_est 转到基座系，与 z=z_t 平面求交得 3D 点。
  • validate()：对 N 个目标分别算投影误差与够取误差的均值。
  • 主函数：造好/差两组 X/K，调用 validate，断言好标定误差小、坏标定误差明显更大。

五、工程落点（真实项目）

  • 产线验收标准：”视觉引导抓取重复精度 ±1mm”——就是用 L3.1 的够取验证测出来的。
  • easy_handeye：标定后建议做”验证序列”（新姿态集上测手眼残差）——就是本 demo 的投影验证。
  • UR+相机集成：Vision Guide 应用里的”验证点”流程 = 本 demo 的够取闭环。
  • 与 UR5e 仿真项目：UR5e 视觉抓取的出厂测试 = 放一个已知工件，机器人”看-算-够”，量偏差——L3.1 的完整落地。

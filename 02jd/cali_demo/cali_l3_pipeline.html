L3.4 全流程工具链（capstone）

这是 cali_demo 的收口篇：把 L1/L2/L3 所有环节串成一条龙可运行的标定工具链，并内置”退化检测闸门”，用注入退化数据验证它真的能拦下坏采集。

一、链路总览

每个环节都用合成数据 + 真值对拍，跑完打印完整报告与 PASS/FAIL。

为什么”前置闸门”放在内参后、手眼前

工程洞察：闸门的位置 = “数据可解性检查点在依赖它的计算之前“。手眼求解器在退化数据上会”返回一个数但不具意义”——所以必须在它之前拦截（L2.3 的核心方法工程化）。

二、两个场景（验证”有用”与”安全”）

场景 运动类型 期望结果
① 多样运动 旋转+平移随机散布 全流程 PASS，各指标在阈值内，前向验证误差 <2 px
② 纯平移（退化注入） 所有相对运动只有平移 退化闸门在求解前拦下，链路安全终止并告警

场景②对应 L2.3 的”纯平移退化”：相对运动无旋转分量，AX=XB 系数矩阵秩亏（条件数爆炸），手眼 X 不可观。本篇把 L2.3 的可观测性判据（σmax/σmin）直接做成流水线闸门——这正是工程上”退化自适应”的最小闭环。

三、为什么退化要”前置拦截”

手眼求解器（哪怕是我们自实现的 Park–Martin）在退化数据上会返回一个数但不具意义（残差可能很小，但解与真值偏差巨大）。所以必须在求解之前用可观测性判据拦截，而不是靠事后残差。这与 L3.2/L3.3 的”质量闸门”思路一脉相承。

为什么”事后残差”拦不住退化（关键论证）

工程铁律：退化必须”事前”拦（可观测性判据），不能”事后”查（残差不可靠）——这是 L2.3 到 L3.4 一以贯之的核心教训。残差只能验证”自洽”，条件数才能验证”可解”。

四、端到端验证（接 L3.1）

链路末尾复用 L3.1 的”前向投影验证”：用恢复的 K/X 把已知 3D 点投成像素，与真值像素比，给出整条链的像素级误差。它比逐环节残差更严格——任一段错通常会在最终像素上暴露（但注意：参数误差可能在特定测试点上相互抵消，单一场景/平面/视场不能保证所有错误都暴露；更严谨的是多工作距离、多视场位置的验证点）。**严格说这是”模型链前向一致性验证”**——真正的机器人端到端验收还需执行+外部测量（L3.1 的界定）。

整链验证的”验收闭环”（pipeline 的最终形态）

工程价值：pipeline 的”终极验收”不是环节指标之和，而是端到端的前向投影误差——它把所有环节的误差耦合进一个最终指标，一票否决（L3.1 的投影验证工程化）。

五、代码走读（cali_l3_pipeline.cpp）

  • 复用 solveHandEye（对偶四元数）、degCondition（SVD 条件数）。
  • makeCap(pureTrans)：生成采集；pureTrans=true 时所有帧同旋转、只变平移 → 退化。
  • run()：内参 → 逐帧 solvePnP → 配对相对运动 → 先算 degCondition，超阈直接返回 deg=true → 否则解手眼/TCP → 前向验证 → 出报告。
  • 主函数跑两场景，断言”健康 PASS、纯平移被检出退化”。

六、到这里，cali_demo 全 17 篇闭环

  • L1（7 篇）：坐标与刚体变换 / 标定板 / 内参 / TCP / 手眼（眼在手上·眼在手外）/ 单目基线 / 双目标定基础。
  • L2（6 篇）：内参深入 / 手眼数学 / 退化 / TCP 深入 / 误差校验 / 双目校正与深度。
  • L3（4 篇）：验证 / 鲁棒 / 自动系统 / 全流程工具链。
  • 全部 .cpp 自带合成数据 + 真值对拍 + PASS/FAIL，无需真机即可验证算法正确性。

下一步建议

把某个 .cpp 的”合成真值”换成你真实的机器人 FK + 相机 solvePnP 输出，即可直接落地为产线标定脚本（参考 L3.3 的 CalibSystem 框架）。

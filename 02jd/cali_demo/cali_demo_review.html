cali_demo 内容审查报告

审查对象：02jd/cali_demo/（README.md + 17 篇课程 .md + 17 个 .cpp + _diagrams.html + images/*.svg）
审查日期：2026-08-18
审查维度：数学公式与算法正确性、OpenCV API 约定、坐标系/配对方向一致性、合成数据自洽性、文档间一致性、声明与实现一致性

〇、总体结论

  • 整体质量较高：针孔模型、畸变模型、AX=XB、视差→深度、四点法 TCP、退化分析等绝大多数公式与 OpenCV 惯例正确；「合成真值 → 反估 → 对拍」的闭环设计严谨，17 篇 md/cpp/html/images 三件套齐全（18 个 md = README + 17 篇课程，cpp 17 个，无缺件）。
  • 确定性错误 3 处（其中 1 处直接影响求解器正确性）。
  • 不一致/表述问题 7 处（不影响结论、但会误导学习者或自相矛盾）。
  • 方法说明：本机无 C++ 工具链与 OpenCV，未做编译运行验证；所有结论基于逐行静态核验与解析推导（含反例验证）。

一、确定性错误（❌ 建议必须修正）

E1. ❌【严重】cali_l2_handeye_math.cpp 的 solveTsai + 同名 .md —— Tsai–Lenz 旋转线性系统数学上不成立

位置：cali_l2_handeye_math.cpp 第 46–56 行；cali_l2_handeye_math.md 第 24 行表格（Tsai–Lenz 行）。

错误内容：实现（及文档描述）把旋转求解写为堆叠线性系统

然后 SVD 取最小奇异向量作旋转向量 r_X。这与经典 Tsai–Lenz 公式不符（正确形式见下）。

反例证伪：取 R_A = Ry(30°)，R_B = Rx(30°)，R_X = Rz(90°)，可直接验证 R_A·R_X = R_X·R_B 成立（这是 AX=XB 的合法真值），但代入后：

  • skew(R_A − R_B)·r_X ≠ 0（计算得 (−0.5, 0.5, 0) × (0,0,π/2) = (π/4, π/4, 0) ≠ 0）
  • (R_A + R_B)ᵀ·r_X ≠ 0（计算得 (−π/4, π/4, √3π/4) ≠ 0）

即真值 r_X 根本不是该系统的零向量——该线性系统不刻画 AX=XB 的旋转解。solveTsai 在无噪声真值数据上也会解出错误旋转，md 中”三种自实现方法旋转误差 <1°、且与 OpenCV 高度一致”的断言不可信（Park–Martin 与 GN 分支不受影响，但该断言整体无法成立）。

正确形式（经典 Tsai–Lenz，OpenCV CALIB_HAND_EYE_TSAI 同款）：用旋转向量 P_A = rotvec(R_A)、P_B = rotvec(R_B)，满足 P_A = R_X·P_B，由此得线性系统

建议：solveTsai 改为上式；md 表格同步修正，并重新编译验证。

E2. ❌【中】cali_l1_frames.md —— 变换记号 T_A2B 的定义与其示例、坐标链公式自相矛盾

位置：cali_l1_frames.md 第 25 行。

错误内容：

记号约定：T_A2B 表示 B 在 A 下的位姿（把 B 系坐标变到 A 系的矩阵）。例：T_target2cam = 标定板在相机系下的位姿。

按定义句 T_A2B = B 在 A 下，则 T_target2cam = cam 在 target 下；但紧随的示例说 T_target2cam = 标定板（target）在相机（cam）系下的位姿——两者相反。而第 42 行坐标链 T_target2base = T_gripper2base · T_cam2gripper · T_target2cam 及全库（OpenCV 惯例）均采用”T_A2B = 把 A 系坐标变到 B 系（A 在 B 下）”的读法，与示例一致、与定义句矛盾。

正确说法：T_A2B = 把 A 系坐标变换到 B 系的矩阵，即 A 系在 B 系下的位姿。例：T_target2cam = 把标定板系坐标变到相机系 = 标定板在相机系下的位姿 ✓（示例对，定义句错）。

影响：学习者按定义句推导会得到与示例/坐标链相反的矩阵（相差一次求逆），属于会实际误导读者的记号错误。

E3. ❌【中】cali_l2_error_check.md —— “眼在手外配对方向”标注与 L1.5/L2.2 矛盾

位置：cali_l2_error_check.md 第 81 行（代码走读 ②）。

错误内容：

② 合成 X_gt，配 A_i=G_i⁻¹G_{i+1}、B_i=T_iT_{i+1}⁻¹（眼在手外配对方向），解 X_est…

同一公式在 cali_l1_handeye.md（L1.5）与 cali_l2_handeye_math.md（L2.2）中均明确标注为眼在手上的配对；且 cali_l2_error_check.cpp 第 69 行的数据生成 T.push_back(inv44(Xgt)*inv44(G[i]))（target2base = I）正是眼在手上的生成式。即 md 标注与自身 cpp 数据生成、以及库内其他两处文档全部相反。

影响：误导读者把”眼在手上”的数据流程当作”眼在手外”理解；应改为”（眼在手上配对方向）”。

二、不一致与表述问题（⚠️ 建议修正）

W1. ⚠️ cali_l2_intrinsics_deep.cpp / .md —— “4 参数”实为 OpenCV 默认 5 参数模型

代码第 77 行变量名 k4、打印与 md 均称”4参数”，但 calibKerr(..., 0, 5, ...) 用的是 OpenCV 默认 5 参数畸变模型（k1,k2,p1,p2,k3）。对照实验实为”5 参 vs 8 参 rational”。calibKerr 的 dcnt 参数也从未被使用（死参数）。建议改标”5参数(默认)”。

W2. ⚠️ cali_l1_intrinsics.md / cali_l2_intrinsics_deep.md —— “一般 k1,k2,p1,p2 足够；广角/鱼眼才加 k3” 不准确

OpenCV 的标准 5 系数模型（calibrateCamera 默认）就包含 k3；k3 并非”广角/鱼眼才用”，常规标定普遍保留 5 参（k1,k2,p1,p2,k3）。鱼眼用的是完全不同的 fisheye 模型，与该表述混淆。建议改为”常规 4–5 参足够；高阶项（k4–k6 / rational）在样本少时易过拟合”。

W3. ⚠️ cali_l3_pipeline.md —— “全 14 篇闭环”与 README”17 篇”矛盾

第 51–55 行称”cali_demo 全 14 篇闭环”，且列 L1 为”五个标定”（漏算 cali_l1_monocular、cali_l1_stereo）、L2 为 5 项（漏算 cali_l2_stereo_rect）。实际共 17 篇（L1×7 + L2×6 + L3×4，与 README 及文件数一致）。建议改”全 17 篇”并补全列表。

W4. ⚠️ cali_l1_board.md —— 非对称圆点阵”同样面积提供更多信息”表述不准确

非对称圆点阵（asymmetric circles grid）相对对称阵的真正优势是打破 180° 旋转对称歧义（对称阵检测存在方向二义性，非对称排布可唯一确定位姿），对机器人手眼标定尤其重要；并非严格意义的”信息更多”。建议改为”非对称排布消除 180° 对称歧义、位姿解唯一，手眼标定更受推荐”。

W5. ⚠️ cali_l2_tcp_deep.md —— 共面退化机理表述不精确

第 27 行”若所有法兰位置共面，球心沿该平面法向那一维不可观”。四点法退化更本质的原因是姿态（旋转）多样性不足导致系数矩阵 (R_i − R_1) 秩亏（以及用于球心拟合的采样点几何退化）；”法兰位置共面”本身不是直接判据（位置由 t_i = P − R_i·x 派生）。建议补充”关键是旋转多样性/系数矩阵秩”，否则读者会得到错误的可操作结论。

W6. ⚠️ cali_l3_validation.cpp —— T_cam2base / T_base2cam 命名颠倒

第 75 行注释与变量名 Tcb_true = inv44(G * Xtrue) 实为 base→cam（inv(G·X) = T_base2cam），代码数学正确、命名颠倒，projectPx/backprojPlane 中的 T_cam2base 均应为 T_base2cam。建议改名以免读者误解（库内 handeye/pipeline 处命名一致，仅此处例外）。

W7. ⚠️ cali_l1_frames.md —— “求逆…用 SVD 数值求逆，本 demo 用后者更稳” 说法牵强

对刚体 4×4 矩阵，闭式 [Rᵀ, −Rᵀt; 0 1] 精确且保持刚体结构；SVD 数值求逆对正交部分虽在数值精度内等价，但并无”更稳”的依据，且一般会破坏严格刚体结构。作为教学说明建议改述为”两种均可，闭式更直观、SVD 通用性更强”。

六、独立复核结论（2026-08-18，numpy 数值复算）

对以上结论做了独立数值复核，结果与报告一致；仅 W6 一处为误判，特此更正：

E1（严重）经数值验证成立 ✅

用 numpy 复算：

  • 反例证伪：取 R_A=Ry(30°)、R_B=Rx(30°)、R_X=Rz(90°)，先验证 R_A·R_X−R_X·R_B 范数 = 8.1e-17（确为 AX=XB 合法真值）；代入代码系统 [skew(RA−RB);(RA+RB)ᵀ]·r_X 范数 = 3.68 ≠ 0 —— 真值根本不满足该系统，求解器对任何数据都解错旋转。
  • 合成数据对拍：按 demo 同款数据（seed 20260817，眼在手上配对）复现，代码版 solveTsai 旋转误差 = 67.3°；改用精确对偶四元数闭式（对应 OpenCV TSAI / Park–Martin）误差 = 0.000°。
  • 重要补充：经典 Tsai–Lenz 旋转向量形式 skew(P_A+P_B)·P'_X = P_B−P_A 仅为小角度近似；其残差随旋转幅度单调增长（~1 rad 时单对残差约 0.13，累积解偏差十几度）。demo 相邻相对运动旋转幅度 ~1 rad，直接套该近似式仍会 FAIL。已采用精确闭式修复，确保在该 demo 数据上 PASS。

W6 为误判（已复核不成立）❌→✅

报告称 cali_l3_validation.cpp 第 75 行 Tcb_true = inv44(G * Xtrue) “实为 base→cam（命名颠倒）”。复核：G = base2gripper、Xtrue = gripper2cam，故 G*Xtrue = base2cam，其逆 inv44(G*Xtrue) = cam2base；变量名 T_cam2base 与之一致，命名正确，无需修改。报告此处将 inv(base2cam) 误算为 base2cam，系复核笔误。

其余 E2/E3/W1–W5/W7 均成立 ✅

已按报告建议逐条修正（见各文件最新版本）。

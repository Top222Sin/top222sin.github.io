L3 补充（NEON 线 · 第1站）：ncnn 怎么用 ARM NEON 手写卷积 / 矩阵乘

这是继「CUDA / CUTLASS / NCCL」GPU 主线之后，开辟的 CPU 侧对照线：读 ncnn 的 src/layer/arm/，看工程师如何用手写 ARM NEON intrinsic（甚至 aarch64 内联汇编）把卷积和矩阵乘榨干。GPU 有 Tensor Core / shared memory，CPU 只有 128-bit NEON 向量 + L1/L2 cache —— 但算法骨架高度同构：寄存器分块 + FMA 原语 + 摊薄访存。

读 real source（已拉到 _ncnn_src/，Tencent/ncnn@master）：
convolution_arm.cpp · convolution_im2col_gemm.h · convolution_1x1.h · convolution_3x3.h · arm_usability.h

§0 为什么读这一站

  • GPU 卷积靠 Tensor Core 把 D=A·B+C 压成一条 mma；CPU 没有 Tensor Core，靠 NEON 的 128-bit 寄存器（float32x4_t，一次 4 个 float）做向量乘加。
  • ncnn 是移动端推理标杆，其 ARM 卷积实现是「手写 SIMD 优化」的范本：把高抽象层的卷积，逐层下探到 im2col+GEMM / 1×1-as-GEMM / 直接 3×3 / Winograd 四条路径，每条都用 NEON 手写微核。
  • 与前面 CUDA 线对照，你会看到 “同一个数学（卷积=GEMM），两套硬件原语”：GPU 的 wgmma/mma vs CPU 的 fmla/vfmaq_laneq_f32。

§1 调度器：conv 怎么选哪条路径

convolution_arm.cpp 的 forward 里先 reshape 权重，再按 kernel 尺寸 / 通道数 / opt 开关 选 kernel（convolution_arm.cpp:204-262）：

条件 选中路径 实现函数
use_winograd && 3×3 && s1 && dilation1 && num_in/out≥8 Winograd (F(2/3/4/6) 系列) conv3x3s1_winograd23/43/63 (convolution_arm.cpp:489-499)
(use_sgemm && prefer_sgemm) || 1×1 im2col + SGEMM convolution_im2col_gemm (convolution_arm.cpp:562)
通用 3×3 / 5×5（pack4 布局） 直接 NEON conv3x3s2_pack4_neon / conv5x5s1_pack4_neon (convolution_arm.cpp:579-597)

prefer_sgemm 的判据（convolution_arm.cpp:223）：

→ 当问题规模超过 L2 缓存、或通道数很大时，im2col+GEMM 反而比直接卷积更 cache 友好（因为 GEMM 有高度优化的分块微核）。这点和 GPU 上「大矩阵用 GEMM、小卷积用直接/Winograd」的直觉一致。

§2 统一原语：fmla / vfmaq_laneq_f32

ncnn 全部手写 ARM 卷积/矩阵乘，最后都落到同一个 NEON 原语：

  • vfmaq_laneq_f32(acc, a, b, lane) ≡ acc += a * b[lane]：把 B 的第 lane 个标量广播 到与 A 同宽的 4 路向量相乘，累加到输出寄存器。
  • aarch64 汇编写法 fmla v18.4s, v17.4s, %Z.s[0]（内联汇编，convolution_1x1.h:134）：v17 = 4 路输入向量，v18 = 输出累加寄存器，%Z.s[0] = 一个权重标量。

为什么用 lane 广播？ 一次 vld1q 把 4 个输入像素装进一个 float32x4_t；权重那一列（K 维）只需 load 一次，用 4 个 lane 分别广播即可喂给 4 路输出累加器 —— 一次访存权重，服务 4 路输出，这正是 NEON 上摊薄访存的核心技巧。

§3 (A) 直接 3×3 卷积 —— conv3x3s1_neon

要点：

  1. 核预打包成 3 个「错位向量」 _k00/_k03/_k06（convolution_3x3.h:51-57），把本应 9 次乘累加压到 6 次 FMA，利用滑动窗口相邻输出像素共享输入。
  2. 一次处理 2 输出通道 × 2 输出行 × 4 输出列 = 16 个输出点 的块（见 _sum0/_sum1/_sum0n/_sum1n 四组），再 vaddvq_f32 水平归约。
  3. 本仓库镜像 cuda_l3_neon_conv_gemm.cpp:neon_style_conv3x3 用清晰的 9-MAC 4-lane 版还原同一结构（ncnn 的 6-FMA 打包优化在注释里说明），与朴素实现对拍 maxdiff=0。

§4 (B) 1×1 卷积 = GEMM —— conv1x1s1_neon

函数：convolution_1x1.h:4。1×1 卷积没有空间窗口，本质就是矩阵乘：
out[H·W][outch] = in[H·W][inch] × W[outch][inch]。

ncnn 用 8 输出通道 × 8 输入通道 分块（对应 convolution_1x1.h:20 的 outch >> 3 和 :57 的 q += 8），内层用 fmla 的 lane 广播一次服务 8 个输出通道：

→ 一个输入通道的 4 路向量 v17，被复用到 8 个输出通道的累加器；size & 3 的余数在 convolution_1x1.h:98 处理。这就是「GEMM 的微核」：循环 K（输入通道），每个 K 用 lane 广播把 1 个输入值摊到 8 路输出。仓库镜像 neon_style_conv1x1 用 8×8 分块 + 余量处理还原，对拍 maxdiff=1.3e-15。

§5 (C) im2col + SGEMM 的 8×12 寄存器分块微核

当走 GEMM 路径时，ncnn 先 convolution_im2col_gemm_transform_kernel（convolution_arm.cpp:261）把权重 reshape，再把输入 convolution_im2col_pack_A_tile（convolution_im2col_gemm.h:4，内部用 transpose8x8_ps —— arm_usability.h:596 —— 做 8×8 转置打包进连续内存），最后调 GEMM 微核：

函数：convolution_gemm_transB_packed_tile（convolution_im2col_gemm.h:178）。输出分块：ii += 8 行（:194）、jj += 12 列（:206） —— 一个微核一次算 8×12 = 96 个输出，全部驻留在 NEON 寄存器（intrinsic 版 24 个 float32x4 = 96；aarch64 内联汇编版 v8–v31 共 32 个寄存器 = 128 floats 容纳 8×16 或 8×12 块，convolution_im2col_gemm.h:266 起的 fmla 循环）：

要点：

  1. 8×12 寄存器分块把输出暂存在 96 个 float 寄存器里，K 循环里反复复用已 load 的 A/B，把访存摊到极低。
  2. 同一 vfmaq_laneq_f32（= §2 的原语）贯穿 3×3 / 1×1 / SGEMM 三种 kernel —— ncnn 手写 NEON 的「单一内核」。
  3. 仓库镜像 neon_style_sgemm_8x12 还原该 8×12 分块 + K 主循环（标量版 lane 广播），对拍 maxdiff=1.3e-15。

§6 与 CUDA/CUTLASS 线的对照

维度 ARM NEON（ncnn，本站） CUDA / CUTLASS（前序 L3）
向量宽度 128-bit float32x4（4 lane） 32-bit×32 线程 / warp；Tensor Core 8×4×8
核心原语 fmla / vfmaq_laneq_f32（标量 lane 广播） mma.sync / wgmma（整块矩阵乘加）
矩阵乘方式 寄存器分块 GEMM（8×12 / 8×8） 同样寄存器/共享内存分块，但由 MMA 指令完成乘加
数据搬运 cache（L1/L2）+ 预取 prfm shared memory + cp.async
1×1 卷积 = GEMM，8×8 分块 CPU 寄存 = GEMM，CUTLASS Gemm 分块 + Tensor Core
直接 3×3 错位核向量 6-FMA + vaddvq 无直接对应（GPU 多走 im2col/GEMM 或 Winograd）
拓扑/通信 单核 + 多核 omp；无 P2P NVLink/P2P/NCCL 多卡

一句话：GPU 把「乘加」交给 Tensor Core 硬件单元，CPU 把「乘加」交给手写的 NEON fmla 流水线；两者都靠寄存器分块 + 复用 + 摊薄访存把峰值算力吃满。读 ncnn 的 ARM 代码，等于读「没有 Tensor Core 时，卷积/矩阵乘该怎么手写」的标准答案。

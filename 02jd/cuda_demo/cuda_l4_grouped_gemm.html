L4（工业扩展）· grouped GEMM：异构 M/N/K 分组矩阵乘 + launch 开销摊销

本文件是 cuda_l4_grouped_gemm.cpp 的配套讲解。图示：images/fig24_grouped_gemm.svg（四联图），浏览器完整预览 cuda_l4_grouped_gemm_diagrams.html。
一句话：一个 step 里常要算 N 个形状各异的 GEMM（MoE 多专家、长尾 kernel）——逐次 cublasGemm 要 N 次 launch，host 端开销被放大；grouped GEMM 用「一次 launch 处理整批异构 GEMM」把 launch 开销按 N 倍摊销。本篇用确定性模型验证其正确性，并量化 launch 收益。

0. 这一站解决什么

前面 L3.2（TensorCore）/ L3.1（fusion）/ L4（Graphs）都围绕「单条计算流」优化。但大模型推理里有个典型场景：一个 MoE step 要对十几个专家各算一个 GEMM，每个专家的形状还不一样。

朴素做法：循环调 N 次 cublasGemm（N 次 kernel launch）。每次 launch 的 host 端开销 ~5µs，N=256 时就 1.28ms 纯花在派发上——而每个 GEMM 本身可能很小。这正是 P2 里「grouped GEMM / persistent kernel」要解决的。

grouped GEMM 的解法：把整批异构 GEMM 打包，一次 launch 算完（cuBLAS 的分组 API / cublasGemmBatchedEx）。launch 次数从 N → 1，开销按 N 倍摊销。

1. 原理

  • 每组 g 有独立 (M_g, N_g, K_g)；grouped_gemm 遍历所有组，计算 C_g = A_g · B_g。
  • 正确性不变量：grouped 的整批输出，必须逐组等于「逐组独立参考 GEMM」——形状异构、甚至退化（K=1 / 1×1）也要对。
  • 收益模型：两种路径计算量完全相同（都是 Σ 2·Mᵢ·Nᵢ·Kᵢ FLOPs），差异只在 launch 次数。朴素 = N 次 launch，grouped = 1 次 launch → launch 开销按 N 倍降低，总墙钟必然更低。

与 L4 Graphs 的对称：Graphs 把「一条 kernel 链」重放摊销 launch；grouped GEMM 把「一批异构 GEMM」合并摊销 launch。两者都砍「launch 维度」的浪费。

2. 算法步骤

数据用确定性公式填充（A[i*K+k]=(i*K+k)*0.1-1.0），host 端 double + 固定累加序，保证与 Python 镜像逐位一致。

3. 与主线关系

  • L3.2（TensorCore）/ L2（GEMM tiling）：grouped GEMM 的每个小组仍是普通 GEMM，复用前面所有 GEMM 优化；只是调度层从「N 次调用」变成「1 次批量」。
  • L4（CUDA Graphs）：都是「砍 launch 浪费」——Graphs 重放一条链，grouped 合并一批异构 GEMM，互为对称补完。
  • 跨域同构：grouped 的「一批贡献累加进整批结果」≡ cuSPARSE CSR 累加 ≡ neon SME ZA 外积累加（都是「把多个子问题的结果拼成一个大结果」）。
  • 应用汇合：MoE 多专家前向是 grouped GEMM 最热场景，与 Hopper（L4）的「大模型推理后端」主线直接咬合。

# 检查 结果
1 grouped == 逐 group 参考（异构 M/N/K, max|Δ|） <1e-9 PASS
2 重跑确定性（两次逐位一致） <1e-12 PASS
3 退化形状(K=1 / 1×1)正确 <1e-9 PASS
4 总 FLOPs == Σ 2·Mᵢ·Nᵢ·Kᵢ PASS
5 launch 开销按 N 倍摊销 (1 次 vs N 次) PASS

数值由 host 端 double 复现；受管 Python 3.13.12 算法镜像 + C++ 控制流镜像双复核，5/5 PASS。本沙箱无 GPU/nvcc，真机 cublasGemmBatchedEx/分组 API 与 persistent kernel 片段由 __CUDACC__ 守护。

6. 自检（踩坑与纪律）

  • launch 收益不要夸大：两种路径计算量相同，grouped 省的是 launch 开销，不是 计算。模型里 T_compute 两项相等，只比 launch 项——断言 launch_speedup == NG（launch 次数比）与 T_total_grouped < T_total_individual，不谎称总提速 = N 倍。
  • 异构形状必须逐组比对：初版只比一个组易漏「形状切换」逻辑；改为遍历所有组 + 单独 edge 组（K=1 / 1×1）兜底退化形状。
  • double 固定序：与 Python 镜像同公式同序，规避 float32 非可结合陷阱（项目 memory §五）。

7. 兄弟仓库互引

  • Least_squares_method_demo / neon_demo：CSR 累加 / SME ZA 外积累加 ≡ grouped「整批结果拼装」范式。
  • cuda_l4_cuda_graphs：同属「砍 launch 浪费」，Graphs 重放链、grouped 合并批，对称互补。
  • cuda_l4_hopper_tensorcore：MoE 多专家是大模型推理热点，grouped GEMM 是 Hopper 后端必经之路。

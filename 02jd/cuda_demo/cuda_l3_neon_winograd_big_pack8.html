0. 为什么是这两块

第 2/3/4 站已经把 Winograd F(2,3)、Depthwise 逐通道、INT8 定点讲完了。这一站把大块和多通道打包补齐，构成 ncnn ARM 后端 3×3 卷积的完整覆盖：

  • ⑤a F(4×4,3×3)：ncnn 真机大量使用的 tile——一次算 4×4 输出，比 F(2,3) 的 2×2 更能摊薄变换开销，乘计数从 144 降到 36（4.00×）。
  • ⑤b F(3×3,3×3)：ncnn 不实现这个 tile（只用 F(2,3)/F(4,3)/F(6,3)），我们从双线性条件出发数值构造一个合法 Winograd 变换，作为「库里没有就自己造」的范例，乘计数从 81 降到 25（3.24×）。
  • ⑥ Depthwise pack8：MobileNet/EfficientNet 的逐通道卷积，把 8 个通道塞进一对 float32x4 寄存器同时算，是 ncnn 在 depthwise 上的标准向量化手法。

⑤a Winograd F(4×4,3×3) —— 直接采用 ncnn 真实常数

5a.1 直觉：大块更划算

一个 6×6 输入块（含 1 圈 padding）产生 4×4 输出（stride=1）。

  • 直接法：每个输出像素 3×3=9 次 MAC → 4×4×9 = 144 次 MAC。
  • Winograd：输入/核投到 Winograd 域，做 6×6 = 36 次逐元素乘（Hadamard），再反变换回来。

乘计数降到 144/36 = 4.00×。相比 F(2,3) 的 2.25×，大块把变换的固定开销摊到更多输出像素上，所以 ncnn 在通道数较大时优先用 F(4,3)（甚至 F(6,3)）。

5a.2 三段变换（与 convolution_3x3_winograd.h 逐常数对应）

Winograd 恒等式写成矩阵：输出块 Y = Aᵀ · ( (G·g·Gᵀ) ⊙ (Bᵀ·d·B) ) · A，其中 d 是 6×6 输入块、g 是 3×3 核。每个输出像素 Y[j][l] = Σ_i Aᵀ[j][i]·(G g Gᵀ)[i]·(Bᵀ d B)[i]。

⑤b Winograd F(3×3,3×3) —— ncnn 没有，我们自己造

5b.1 为什么 ncnn 不 ship F(3,3)

F(m,r) 的 tile 把 (m+r-1)×(m+r-1) 输入块映射到 m×m 输出。F(3,3,3,3) 意味着 5×5 输入 → 3×3 输出，降乘 81→25（3.24×）。ncnn 选择 F(2,3)/F(4,3)/F(6,3) 覆盖不同的输出块尺寸，3×3 输出通常由 F(2,3) 的 2×2 块拼出来，所以没有单独的 F(3,3) tile。但这不意味着它不存在——任何满足双线性条件的 (Bᵀ,G,Aᵀ) 三元组都能用。

5b.2 双线性条件：Winograd 是否合法的充要条件

一个变换是「真·Winograd 最小滤波算法」当且仅当对所有 j∈[0,m), k∈[0,r), l∈[0,n)：

左边是把输入/核/输出变换”打开”后的系数；右边是克罗内克 δ——只有 l == j+k 时为 1，否则为 0。这正说明该变换等价于「先做线性卷积（δ(l,j+k) 直接就是卷积的系数关系）、再投影回输出」。

我们用 ncnn 的 F(2,3) 三元组喂给这个 checker，得到 0 violations——证明 checker 本身正确；再用于 F(3,3)，残差即衡量构造质量。

5b.3 为什么 Vandermonde 直推不行

直觉上”在若干点 α_i 上求值”能构造多项式变换，但 evaluate-at-points 表达的是普通函数插值，不是线性卷积。直接套 Vandermonde V[i][j]=αᵢʲ、VR[i][k]=αᵢᵏ、Vinv[j][i]=αᵢʲ/Wᵢ 会得到 maxdiff ~ 5e2 的错误结果——它算的不是卷积。必须用数值法去找一个非平凡的一致三元组。

5b.4 ALS（交替最小二乘）+ 联合 Gauss-Newton 求解

变量：Aᵀ(3×5)、G(5×3)、Bᵀ(5×5) 共 55 个自由度，约束 45 个（欠定，解存在）。

  1. 交替最小二乘：固定另两个，把其中一个对应的 45 个方程（每个约束对当前矩阵是一组线性方程）用正规方程 + 微正则(λ=1e-9) 解出。三类矩阵轮流更新，约 200 轮后残差停在 ~1e-5。
  2. 联合 Gauss-Newton 精修：把 45 个双线性残差 r_e = Σ_i Aᵀ[j][i]G[i][k]Bᵀ[i][l] - δ(l,j+k) 对全部 55 个参数同时做牛顿步 δ = -(JᵀJ+1e-12I)⁻¹ Jᵀ r，60 轮内把残差压到 1.69e-15（机器精度）。
  3. 齐次再平衡：解存在尺度歧义 Aᵀ→sAᵀ, G→tG, Bᵀ→uBᵀ (stu=1)，把三者量级统一到 5.4983，避免某矩阵过大/过小。

最终 2D 卷积对拍（15×15 / 16×14 / 12×18 / 9×9 / 20×20）maxdiff ≈ 3e-15，即基本精确的合法 Winograd F(3,3)。完整脚本见 _solve_w33.py，交叉验证见 verify_neon_winobig_pack8.py。

5b.5 算法步骤（与 5a 同构，仅尺寸 5）

驱动 conv3x3_winograd33：输出 3×3 块为锚，对应 5×5 输入邻域 (oy-1..oy+3, ox-1..ox+3)。

⑥ Depthwise 3×3 的 pack8 多通道向量版

6.1 为什么 depthwise 要单独写 + 打包

Depthwise 卷积：每个输入通道只对应用一个 3×3 核、产一个输出通道，无跨通道累加。MAC 数 = 9·C·H·W，比普通 3×3（9·C·C·H·W）少 C 倍——本就是省钱的操作，必须配上一个同样省寄存器/指令的向量化写法。

ncnn 的 pack8 把通道按 8 对齐打包（outch = div_up(C,8)*8）。每个输出位置用一对 float32x4（共 8 个 lane）同时承载 8 个通道的 3×3 累加——一条 NEON fmla 就推进 8 通道。

convolutiondepthwise_3x3_pack8.h 网络拉取失败（HTTP 000），本实现基于标量 convolutiondepthwise_3x3.h 的 repack(_k012x/_k345x/_k678x, 行 36-42) + ext/fmla 滑窗(行 71-115) 与 ncnn pack8 习惯忠实重建；Python 对拍误差 0.0。

6.2 算法结构（host 标量等价，逐 pack）

数值上严格等于逐通道 naive depthwise：只是把 8 个独立通道的 3×3 累加并到同一组寄存器/循环里。NEON 真机把 acc[8] 换成 float32x4 v0,v1，inv[8] 换成 float32x4，fmla 一次算 4 通道 ×2。

6.3 与 CUDA/CUTLASS 线的对照

维度 Depthwise pack8 (NEON) CUDA 对照
数据复用 8 通道打包进 2 寄存器 类似 “channel packing” / ldg128 一次取 4 个 float
乘加 fmla (float32x4×2) ffma / mma 张量核（INT8/FP16）
适用 MobileNet/EfficientNet 同结构网络在 GPU 上的 depthwise kernel

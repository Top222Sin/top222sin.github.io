一、理解编程模型：kernel、grid/block/thread、SIMT

对应笔记本：01CUDA基础学习.docx → L1 能跑（入门） → 1、理解编程模型：kernel、grid/block/thread、SIMT
配套代码：cuda_l1_programming_model.cpp（向量加 + 索引演示两个 kernel，注释即讲解）
双轨：本篇以 CUDA 为主，OpenCL 对照见第四节。

一、Kernel 是什么

Kernel = 在 GPU 上被成千上万个线程”同时各跑一遍”的函数。

  • 用 __global__ 声明（CUDA）；OpenCL 用 __kernel。
  • 它由 CPU（host） 调用一次，却在 GPU（device） 上被无数线程并行执行。
  • 你写的 kernel 里是”一条线程的逻辑“——比如 C[i] = A[i] + B[i]；GPU 负责把它复制成 N 份、让 N 个线程各用各的 i 跑。
  • kernel 没有返回值（void），结果通过写入 device 指针（或 shared/local 内存）带出来。

二、三层层次：Grid / Block / Thread

CUDA 把”并行”组织成三层金字塔：

层级 是什么 能做什么 怎么编号
Thread 单个执行单元，跑一遍 kernel 算 1 份数据 threadIdx.x/y/z
Block 一组线程（最多 1024 个，CC 相关） 线程间可共享 shared memory、可 __syncthreads() 同步 blockIdx.x/y/z
Grid 所有 block 的集合 一次 kernel 启动的全部并行工作 gridDim.x/y/z

2.1 为什么是三层

  • Thread 是算力的最小粒度的执行。
  • Block 给”需要协作”的线程一个共享上下文（shared memory + 同步），比如做归约、矩阵分块。
  • Grid 是这一次 launch 的全体，网格可以很大（上百万线程）。

2.2 维度

三者都可以是 1D / 2D / 3D（dim3 类型）。矩阵常用 2D：blockIdx.x/y、threadIdx.x/y。
本篇先用最容易懂的 1D。

2.3 全局索引公式（必背）

一维时，第 i 个线程的全局下标：

  • blockDim.x = 每 block 线程数（启动时定，CUDA 里是 blockSize）
  • gridDim.x * blockDim.x = 总线程数

三、SIMT：和 SIMD 到底差在哪

SIMT = Single Instruction, Multiple Threads（单指令多线程）。

3.1 核心机制

  • GPU 硬件把 32 条连续线程 编成一个 warp（NVIDIA 固定 32；AMD 叫 wavefront，大小由设备/实现决定，常见 32/64）。
  • 一个 warp 内的 32 条线程，未发散时同一条指令驱动全部 lane（SIMT 调度），但各用各的数据（各自的寄存器、各自的 i）。
  • ⚠ “锁步”是教学近似：Volta 及以后架构引入独立线程调度（Independent Thread Scheduling）——发散的分支不再严格串行化整个 warp，而是按线程独立调度；__syncthreads() 的语义也基于此。编程时不能依赖隐式锁步：需要跨线程同步时显式用 barrier/shuffle/协作原语。
  • 这就是”单指令、多线程”：一条指令流，多份线程上下文。

3.2 SIMT vs SIMD（考试/面试常问）

SIMD（如 NEON/SSE/AVX） SIMT（CUDA/OpenCL）
编程视角 显式向量：float32x4_t，手动管 4 个 lane 写标量线程代码，硬件自动组 warp
谁管”并行” 程序员（用 intrinsics 编排 lane） 硬件调度器（Automatic）
分支 整条向量同一条指令 warp 内可分支发散（见下）
粒度 数据级（1 条向量指令） 线程级（成百上千线程）

一句话：NEON 是你手动把 4 个数塞进一个向量；CUDA 是你写”一条线程怎么算”，硬件自动把 32 条线程绑成 warp 一起跑。（OpenCL 的 wavefront/sub-group 大小与执行模型由设备决定，与 NVIDIA SIMT 是”实现相关”的对照，非完全等同。）

3.3 分支发散（divergence）—— SIMT 特有的坑

如果同一个 warp 内的线程走了 if/else 的不同分支：

warp 不能同时跑两条路，只能串行化：先让偶数线程那一半执行、奇数那一半禁用，再反过来。两条分支都执行 → 吞吐减半。

  • 避免：让 warp 内（连续 32 线程）走同一分支；用 i 的块级而非线程级条件。
  • OpenCL 的 wavefront 发散同理。

3.4 为什么 SIMT 适合 GPU

GPU 有上千核心，但控制逻辑极简——把”取指/译码”在 warp 级别共享，32 线程共用一套指令，省下的晶体管全砸在 ALU 和显存带宽上。这正是 GPU 算力碾压 CPU 的根本。

四、OpenCL 对照（你这次要双轨学）

同一个向量加，OpenCL 概念与 CUDA 一一对应：

CUDA OpenCL 说明
__global__ void k() __kernel void k() kernel 声明
<<<grid, block>>> 启动 clEnqueueNDRangeKernel(..., gws, lws) gws=总线程，lws=block 大小
blockIdx.x get_group_id(0) 第几个 block / work-group
threadIdx.x get_local_id(0) block 内第几个 thread / work-item
blockDim.x get_local_size(0) block 大小
全局下标 blockIdx.x*blockDim.x+threadIdx.x get_global_id(0) 全局编号
warp（32） wavefront（32/64） SIMT 执行单元，概念完全一致

OpenCL 的”一次启动”叫 NDRange（N-Dimensional Range），global_work_size / local_work_size 正好对应 CUDA 的 gridDim*blockDim / blockDim。底层 SIMT 模型完全相同，差异主要在 API 与跨平台运行时。

五、第一个 kernel 代码走读

配套 cuda_l1_programming_model.cpp 里有两个 kernel：

  1. vecAdd —— 经典向量加。i = blockIdx.x*blockDim.x+threadIdx.x 取全局下标，if(i<n) 做边界保护（总线程常比 n 多）。
  2. indexDemo —— 把每个线程的 (全局i, blockIdx, threadIdx) 写进数组，host 端打印，直观看到 16 个元素被 4 个 block × 4 线程编号铺开。

<<<gridSize, blockSize>>> 就是”把 kernel 按这个网格铺到 GPU”。编译需 nvcc，沙箱无 GPU 故仅作教材；逻辑与真机一致。

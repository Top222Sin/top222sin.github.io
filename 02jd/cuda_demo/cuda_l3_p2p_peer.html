L3 补充：GPU 直接通信 P2P + cudaMemcpyPeer

这是 L3「多 GPU / NVLink / NCCL 通信」收官站的最后一环。L3.4 讲了 NCCL 会「自动选 transport：NVLink > PCIe P2P > RDMA > socket」——本篇把这条选择背后最底层的物理基础（peer access）讲透：没有它，NCCL 的 P2P 通道根本起不来，所有流量都得 staged 绕 host。

§0 为什么这是 L3 的最后一环

L3 主线：kernel fusion/pipeline → Tensor Core/混合精度 → cooperative groups/dynamic parallelism/PTX → 多 GPU/NVLink/NCCL。
NCCL 让多卡像一台大机器，但它能在 GPU 间直接搬数据，前提是 CUDA 的 peer-to-peer（P2P）机制先就位。P2P = 一块 GPU 直接读写另一块 GPU 的显存，绕过主机内存、不经 CPU。本篇即这条「物理地板」。

§1 P2P 是什么：绕过 host 的 GPU↔GPU 直连

传统跨卡搬运（无 P2P）：

两次 PCIe 穿越 + 一次 CPU 内存拷贝，CPU 全程参与，**~10–20 µs、带宽受 PCIe 与 host 内存双重限制**。

GPUDirect P2P：

  • 延迟降到 PCIe P2P ~3–5 µs / NVLink ~1–2 µs，端到端降 30%–70%，CPU 彻底卸载。
  • 是单机多卡训练（AllReduce 梯度同步、TP 激活搬运、MoE token 路由）的物理支柱；没有 P2P 多卡训练慢一个数量级（来源：NVIDIA GPUDirect 文档 / cuda-handbook ch9.2 / 实测 p2pBandwidthLatencyTest）。

§2 CUDA P2P 原生 API 流程（四步）

两个坑（实测必踩）：

  • 坑① 映射非对称：gpu0→gpu1 的 enable 不自动给 gpu1→gpu0 开权限，要双向各调一次。
  • 坑② 不与其他 op 并发：P2P memcpy 要求先把两卡在飞任务全部排干，且拷贝期间不能起别的 kernel/拷贝；普通的 cudaMemToDevice 异步拷贝则没有这个限制。P2P 拷贝更像一把「独占总线」的临界区。

启用硬条件（CUDA Handbook ch9.2 / NVIDIA）：

  • UVA（统一虚拟地址，Fermi+/64-bit Linux 或 Win+TCC）；
  • 两卡在同一 I/O hub / 同一 PCIe Root Complex（同 NUMA 最佳）；
  • SM 2.x+，驱动较新。跨 NUMA（SYS）拓扑默认禁用 P2P。

§3 cudaMemcpyPeer vs cudaMemcpy(D2D)

cudaMemcpyPeer(dst,1,src,0,n) cudaMemcpy(dst,src,n,cudaMemcpyDefault)
设备号 显式传 dstDev/srcDev 不传，UVA 从指针值反推「谁家的内存」
无 UVA 时 ✅ 可用（老/受限环境兜底） ❌ 不能（指针无法定位设备）
直连能力 能直连就直连 与 MemcpyPeer 一致（能直连就直连）

关键点（CUDA Handbook 9.2.1）：CUDA 能在任意两卡间拷贝，哪怕不支持直连——不行就 staged 绕 host。有直连映射时两者都走直接 P2P，不落 host。cudaMemcpy3DPeer 是 3D 变体。

§4 拓扑决定一切：nvidia-smi topo -m 读法

图例（来源 NVIDIA + 实测）：

  • NV / NV12 = NVLink（最佳，H100 单向 ~450 / 双向 900 GB/s）
  • PIX = 同一 PCIe switch（全速 PCIe P2P）
  • PHB = 同一 PCIe host bridge（经 CPU/系统内存，P2P 受限）
  • NODE = 同一 NUMA 节点（NVLink 或 PCIe 直连，可 P2P）
  • SYS = 跨 NUMA（默认禁用 P2P，只能 staged）
  • X = 自身

带宽阶梯（单向聚合，教学近似）：NV 450 > PIX/NODE 32(PCIe Gen4) > PHB 16 > SYS 12 GB/s。
→ 训练框架要做到「同节点内 TP、跨节点 DP」正是为了让最频繁的 TP 通信留在 NV/PIX 域内，避开 SYS。

§5 GPUDirect 家族（不只 P2P）

技术 干什么 绕过什么
GPUDirect P2P GPU↔GPU（PCIe/NVLink） 主机内存
GPUDirect RDMA 网卡 NIC ↔ GPU 直连（跨节点） 主机内存 + CPU
GPUDirect Storage NVMe SSD ↔ GPU 直连 主机内存 + 文件系统
GPUDirect Async 异步控制上述全部 CPU 参与

RDMA 是 L3.4「跨节点 RDMA > socket」的底层：IB 网卡直接读写 GPU 显存，MPI_Send 从 GPU 内存抓取、远端 NIC 直接写远端 GPU，数据路径零 CPU 拷贝（来源：NVIDIA GPUDirect 文档）。

§6 NCCL 如何骑在 P2P 上（与 L3.4 闭环）

  • NCCL 初始化时 cudaDeviceCanAccessPeer 探测拓扑，自动选 transport：
    同节点 NVLink > PCIe P2P(PIX/NODE/PHB) > SHM(共享内存兜底)；跨节点 RDMA > Socket。
  • NCCL 的 P2P transport = peer mappings（cudaDeviceEnablePeerAccess）+ IPC（cudaIpcGetMemHandle / cudaIpcOpenMemHandle，跨进程共享 GPU 指针）。
  • 排查环境变量：NCCL_DEBUG=INFO 看通道里的 P2P/CUMEM 或 P2P/IPC（P2P 生效）、SHM（共享内存兜底，慢）、NET/Socket（最差）；NCCL_P2P_LEVEL=NVL 强制只用 NVLink；NCCL_NET_GDR_LEVEL=5 跨节点开 GPUDirect RDMA。
  • 闭环：L3.4 的「NCCL 自动选路」＝本篇 peer access 机制的结果；L3.4 的 ring/busbw 模型跑在 P2P 直连的物理带宽上。

§7 数值自检（纯 C++ 可跑）

g++ -O3 -std=c++17 cuda_l3_p2p_peer.cpp -o p2p && ./p2p 输出：

  • model_topology()：4 卡矩阵，标记 NV/NODE 对可 P2P、SYS 对必须 staged。
  • p2p_vs_staged(1 GB)：搬 1 GB——绕 host 102.5 ms vs PCIe P2P 31.25 ms（3.3×） vs NVLink 2.22 ms（46×）。
  • verify_p2p_copy()：模拟 GPU0 显存 → GPU1 显存，1024 float 逐字节一致 → PASS。
  • nccl_transport_select()：列出 transport 优先级与排查环境变量。

（__CUDACC__ 守护段给真机骨架：enable_peer_access 双向 enable + real_p2p_copy 用 cudaMemcpyPeerAsync 排进 stream；真机需 nvcc + 多卡硬件。）

§8 编译运行

一句话收束 L3

fusion 减少「搬多少」→ cp.async+pipeline 减少「搬时干等」→ Tensor Core 把算力堆密 → cooperative groups/dynamic parallelism 重组并行结构 → NCCL 把多卡织成一台机器 → P2P/peer access 是这台机器「卡间不绕 host」的物理地板。 至此 L3 架构级主线全部完成。

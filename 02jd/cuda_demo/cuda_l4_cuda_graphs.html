L4（工业扩展）· CUDA Graphs：把整条 kernel 链固化成「可重放图」

本文件是 cuda_l4_cuda_graphs.cpp 的配套讲解。图示：images/fig20_cuda_graphs.svg（四联图），浏览器完整预览 cuda_l4_cuda_graphs_diagrams.html。
一句话：推理/训练里「同一条 kernel 链被 launch 成千上万次」时，per-launch 的 host 端开销会主导；CUDA Graphs 把这条链捕获成一张图，之后每次重放只付一次 cudaGraphLaunch 的代价。

0. 这一站解决什么

前面 L3.1（cuda_l3_fusion_pipeline）讲了 fusion 消除「中间张量落全局的带宽往返」——那是「数据搬运」维度的浪费。
但还有另一类浪费也是工业高频痛点：launch 开销。

  • 每个 kernel <<<grid,block>>> 启动，CPU 都要做：参数打包 → 依赖检查 → 入队到 GPU 命令流。单次约 3–10 µs（文献量级，本 demo 模型取 5 µs）。
  • 推理服务里一个 step 往往是 几十个 kernel（normalize → matmul → bias → activation → …），一天跑 上百万 step → 纯粹的 launch 派发时间就能吃掉可观的墙钟。
  • 这些 kernel 的「结构」每一步都一样，变化的只是数据指针/标量——可每次都重新派发一遍，纯属重复劳动。

CUDA Graphs 的解法：第一次把这条链（含 kernel、依赖、拷贝、事件）「录」成一张有向无环图，之后只重放这张图。重放一次 cudaGraphLaunch 就把整条链派发出去，host 端开销从 N·K·L_stream 降到 C_capture + N·L_graph。

与 fusion 的分工：fusion 省「带宽」、Graphs 省「launch」——两者都是「让昂贵算力别空转」，但砍的是不同的浪费维度。这正是 L3.1 那句话的对称补完。

其中 C_capture 是一次性建图开销（约几十~几百 µs，被 N 次重放摊薄），L_graph 是单次图派发（约 1–3 µs，因为一图打包 K 个 kernel 只一次派发）。

1.3 加速比与渐近上界

关键直觉：K 越大（每图 kernel 越多）、N 越大（重放越频繁），收益越大；渐近上界只取决于 K 与两种派发开销之比。本 demo 模型 L_stream=5µs, L_graph=1µs：

  • K=4：上界 4×5/1 = 20×；N=100/1k/10k 实测 10.0× / 18.2× / 19.8×。
  • K=20：上界 100×；N=1k 实测 90.9×。

这正是「多小 kernel 反复 launch」场景最划算——和 fusion 一样，受益方都是推理里大量细碎算子。

2. 正确性：图重放 == 逐次 launch（且 == 闭式解）

教学用一条 4-kernel 链（一个 step）：y = C·(A·y + B) + D（线性依赖 k0→k1→k2→k3）。

  • stream 路径：N 次，每次把链从头跑一遍（每 kernel 一次 launch）。
  • graph 路径：把链「捕获」成图（节点 + 依赖，本 demo 用一个最小图抽象 + Kahn 拓扑排序忠实模拟），然后重放 N 次。

两者在 N=1000 下结果逐元素完全一致（max|diff| = 0），且都与闭式解 y_N = (AC)^N·y0 + (CB+D)·(1-(AC)^N)/(1-AC) 一致（误差 ~1.1e-16，即机器 epsilon）。

这说明：graph 不是「近似加速」，而是「语义等价 + 派发更省」——捕获时记录的依赖保证了重放顺序与逐次 launch 完全相同。

5. 工程要点（闭坑）

  1. 静态图不能改数据——但可廉价更新节点参数：cudaGraphExecKernelNodeSetParams(graphExec, node, &params) 改输入指针/标量即可，无需重新 capture。这是让 Graphs 用于「每 step 形状/指针不同」的推理服务的命门（真机片段③）。
  2. 捕获开销一次性：C_capture 只在第一次建图时付，被 N 次重放摊薄；N 太小时（如只跑几次）反而不划算——要用 nsys 看真实 break-even。
  3. 控制流也能进图（CUDA 12+）：cudaGraphConditionalHandle + cudaGraphAddWhileNode 把 if/while 固化进图，避免为分支反复 capture。
  4. 诚实边界：Graphs 省的是 launch 开销，不是 GPU 计算本身。若瓶颈是 compute-bound（见 L2.3 Roofline），上图也不会让 kernel 算得更快——它只削掉「派发」这段 host 端时间。

7. 下一步 & 兄弟仓库互引

  • cuda 内部：接 cuda_l3_fusion_pipeline（L3.1）——fusion 省带宽、Graphs 省 launch，两站合起来是「推理 step 的 host/GPU 双维度优化」主线；接 cuda_l3_multigpu_nccl（L3.4）——多卡场景下 graph 还能跨 stream 编排 H2D/K/D 依赖。
  • 跨 demo：Graphs 是「把一个固定计算流程固化、反复执行」的思想，与 ctrl_l4_mpc（control，L4 滚动时域每步求解同一 QP）、cali_l4_* 的「固定标定流程反复跑」同构；ls_l4_lasso 的可重放近端梯度迭代也是「同结构反复执行」的另一例。

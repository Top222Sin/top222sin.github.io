L4（工业扩展）· compute-sanitizer 调试：捕获 OOB / 未初始化 / 数据竞争

本文件是 cuda_l4_compute_sanitizer.cpp 的配套讲解。图示：images/fig23_sanitizer.svg（四联图），浏览器完整预览 cuda_l4_compute_sanitizer_diagrams.html。
一句话：真实 kernel 的 bug 大多不在编译期暴露——越界写、读未初始化共享内存、跨线程数据竞争，全是运行时才炸。compute-sanitizer 靠「插桩内存访问」抓这三类；本篇在 CPU 上复刻一台极简 device 模拟器 + sanitizer，把三类 bug 精准抓出，fixed 程序干净通过且数值 == 参考。

0. 这一站解决什么

前面的 demo 都默认「kernel 写对了」。但工业里的真实痛点是：编译期零报错，跑起来结果随机错 / 偶发越界 / 多卡结果不一致。根因通常是三类运行时 bug：

  • OOB（越界访问）：索引算错、缺 if(i<N) 保护，写到分配内存外。
  • uninit（读未初始化）：__shared__ / 全局内存先读后写，读到垃圾值。
  • race（数据竞争）：多个线程写同一地址却没用 atomic / 没同步。

compute-sanitizer（前 cuda-memcheck）就是干这个的——它在运行时插桩每一个内存访问，记录越界、未初始化读、竞争。本篇用纯 C++ 复刻这套诊断逻辑，做到无 GPU 也能验证「sanitizer 能抓到该抓的、放行该放行的」。

1. 原理：插桩访问原语

核心是把裸访问换成插桩原语，每调用一次都做检查：

  • oob：访问越出 [0,N) / 共享数组 → 标记。
  • uninit：读一个从未被写过的元素 → 标记（不区分全局/共享，逻辑一致）。
  • race：记录每址「上次写的 tid」；若不同 tid 在没有 barrier 间隔的情况下写同址 → 标记。**atomic 是有意的并发写，不报 race**——这正是 compute-sanitizer 对原子操作的判定。

2. 算法步骤（三个 buggy + 一个 fixed）

NT=8 线程顺序执行（SIMT 简化模型）。barrier() 对应 __syncthreads()，清空「上次写者」记录，使同步后的写不误判为竞争。

3. 与主线关系

  • L2.1（内存层次 / 合并 / bank conflict）：bank conflict 本质是「多线程访问同 bank 不同字」的共享内存冲突——与 race 同源（并发访问同一存储），compute-sanitizer 的 racecheck 能顺带暴露同类问题。
  • L3.3（PTX/SASS 反汇编）：sanitizer 是「运行时」诊断，SASS 分诊是「静态」诊断，两者互补（E 系列 review 已建立）。
  • L4（Hopper）：稀疏 TC / FlashAttention 的分块里若有越界或竞争，sanitizer 是第一道闸门。
  • 跨域同构：插桩「记录每址上次写者 + 同步点清空」与 LS/KF 的「固定种子对拍」一样，都是「用确定性回放暴露非确定 bug」的纪律。

# 检查 结果

2 sanitizer 捕获未初始化读(uninit)：buggy 标记 PASS

数值由 host 端复现；受管 Python 3.13.12 算法镜像 + C++ 控制流镜像双复核，5/5 PASS。本沙箱无 GPU/nvcc，真机 compute-sanitizer --tool memcheck/racecheck/initcheck 与 CUDA kernel 片段由 __CUDACC__ 守护。

6. 自检（踩坑与纪律）

  • race 误判 vs 漏判：初版 race 只在「异 tid 写同址」就报——但同一线程重复写自己上次写的址应是合法的（例如迭代累加）。正确规则：记录「上次写者 tid」+ barrier() 清空；只有异 tid 且未同步才报。已落实。
  • atomic 不报 race：fixed 用 gatomic 表示 atomicAdd，是有意并发写，sanitizer 放行——这也是真机 compute-sanitizer 对原子的判定（否则满屏误报）。
  • clean() 是三标志的合取：buggy 程序只要命中任一即 !clean()，fixed 必须三全 false 才算干净。

7. 兄弟仓库互引

  • Least_squares_method_demo / KF_demo：固定种子 RNG 对拍，与「sanitizer 确定性回放」同属「暴露非确定 bug」纪律。
  • cuda_l3_cg_dp_ptx：SASS 静态分诊 vs sanitizer 运行时诊断，互补。
  • neon_demo：NEON 多线程写同向量通道类似 race，标注化访问顺序即可规避。

衔接：L2 工业线已见过 CUTLASS 的 TensorOp 与 tiny_wmma_gemm；L3.1 讲了取数流水线；本站在「指令/精度」层面把它讲透。

0. 为什么需要 Tensor Core

普通 CUDA Core 做 FMUL+FADD 一次一个标量乘加。矩阵乘法 D = A·B + C 是「一堆乘加」，且乘加比极高（每个输出元素 = K 次乘加）。

NVIDIA 从 Volta (SM_70) 起在芯片里塞了专用单元 Tensor Core，一条指令直接算一个小矩阵块的乘加：

关键约束（混合精度的由来）：输入用低精度（fp16/bf16/int8/tf32），累加用高精度（fp32）。低精度 → 数据量小、单元能在同样面积/功耗下塞更多 ALU、吞吐高；高精度累加 → 避免 K 次加法把舍入误差放大。

1. Tensor Core 概念与吞吐

  • 每个 TC 指令处理的「块」很小（如 fp16 的 16×16×16 = 一个 warp 一次算 256 个乘加）。要算大矩阵，用很多 warp、很多 TC 指令拼。
  • 吞吐数量级（公开规格示例）：V100 fp32≈15.7 TFLOPS，但 fp16 TC≈125 TFLOPS（≈8×）；A100 fp16 TC≈312 TFLOPS、tf32 TC≈156 TFLOPS。
  • 为什么快：① 低精度 ALU 更密；② 输入带宽需求减半（fp16 2 字节 vs fp32 4 字节），对 memory-bound 的 GEMM 也直接受益；③ 乘加合一，无「先乘存寄存器再取来加」的开销。

代码 throughput_model() 用 V100/A100 示例规格打印理想加速比（fp16≈8×、tf32≈8×）。

2. WMMA fragment API（CUDA C++，头文件 mma.h）

最上层的编程接口，按「矩阵片（fragment）」思考。一个 16×16×16 的 fp16 GEMM 核心：

  • 「形状」即一条 mma.sync 指令的 warp 级 tile。常见可用形状：
    • fp16/bf16：16×16×16、32×8×16、8×32×16
    • tf32：16×16×8；int8：16×16×32
  • 累加器精度：fp16/bf16/tf32 输入 → fp32；int8 输入 → int32。

真机骨架见 cuda_l3_tensorcore.cpp 的 __CUDACC__ 段 wmma_gemm_kernel（已含 load/mma/store 三段，并注释可接 L3.1 的 cp.async 取数）。

3. MMA PTX（WMMA 编译后的底层指令）

逐段解读：

  • mma.sync：sync = 协作，整条 warp（32 线程）共同完成一次矩阵乘加；非协作的 mma（无 sync）是每线程各算各的（老架构 SIMT 思路）。
  • m16n8k16：指令形状。注意是 n8——一个 16×16×16 的 warp tile 由两条 m16n8k16 拼成（N 方向前后各 8 列，对应 d0,d1 与 d2,d3）。
  • f32.f16.f16.f32：累加器、A、B、累加器 的 dtype → fp32 累加 + fp16 输入（混合精度）。
  • 寄存器组：{a0..a3} 等是一组寄存器（具体编号由编译器/ABI 分配），mma.sync 从指定寄存器读操作数、写回指定寄存器。

4. CUTLASS 如何封装（连接 L2 + L3.1 + station4）

CUTLASS 把 TC 做成模板的一层。要点（已备份 _cutlass_src/）：

层 文件:行 作用
派发到 TensorOp default_mma.h:190（OperatorClass TensorOp 特化）/ :213（InstructionShape） 按 Operator::kTensorOp 选 TC 路径
warp 级 TC MMA warp_mma_tensor_op.h:167（class MmaTensorOp）/ :206（InstructionShape = ArchMmaOperator::Shape） 一个 warp 的 TC 乘加，含 FragmentA/B/C（:294-296）
取数流水线 mma_multistage.h（L3.1 已讲：cp.async + kStages 双缓冲） 把 A/B 操作数异步搬进共享
输出算子 epilogue（station4 已讲：EVT 访客树） 把累加结果做 bias/激活/写回

→ 这正是 **L2 的「三级 GemmShape」里最内层的 InstructionShape**（如 <16,8,16> fp16 / <16,8,8> tf32）+ L3.1 的 kStages cp.async 取数 + station4 的 EVT epilogue，拼成完整 TC GEMM。也呼应工业线第 2/3 站 tiny_wmma_gemm<BM,BN,BK,STAGES>（WMMA + 环形缓冲主循环）。

一句话：MMA 指令形状对所有 GEMM 系算子固定，差异只在「取数流水线」与「输出算子」——这一贯主线至此收口。

5. 混合精度纪律（精度 / 带宽 / 吞吐的三角）

低精度不是免费午餐，要守几条纪律：

格式 位宽 指数/尾数 用途 注意
fp32 32 8e / 23m 基准、累加 —
fp16 16 5e / 10m 训练/推理主流 动态范围小 → 需要 loss scaling（把梯度放大到 fp16 可表示区间）
bf16 16 8e / 7m 训练（尤其大模型） 指数同 fp32，范围大，通常不需 loss scaling
tf32 19(存为 fp32 占位) 8e / 10m Ampere 上 fp32 代码的零改动提速路径 尾数砍到 10 位，范围同 fp32
int8 8 — 推理 需量化 + scale 因子（对称/非对称）

纪律要点：

  1. 乘低精、加高精：输入/权重低精度，累加 fp32（或 int32），否则 K 次加法放大舍入误差。
  2. 范围比尾数更致命：fp16 的最大问题是「表示不下大数/小数」，故训练常用 bf16 或加 loss scaling；tf32 因范围同 fp32 所以「把 fp32 代码换矩阵乘就提速」最省心。
  3. 带宽红利：fp16/bf16 输入让取数量减半——对受带宽限制的 GEMM 直接提速（呼应 L2.3 compute/memory-bound）。

代码 report_memory() 量化：fp16 输入把输入字节从 2·(M·K+K·N)·4 降到 ·2，即 2×↓（同 verify 用的 32³ 规模）。verify_mixed() 用 host 模拟 fp16 量化确认结果 ≈ 纯 fp32（误差在 fp16 精度内）。

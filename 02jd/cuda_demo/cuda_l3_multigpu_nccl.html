真实文档/源码锚点见各节（NCCL 为开源库，本文引用其官方 API 文档与架构博客，未逐行搬源码）。

§0 为什么这是 L3 的收官：把前面所有东西放大到「一整张卡」

前面三站已经把「单卡内」的并行榨干了：

  • L2.4 共享内存归约：一个 tile（warp / block）内把 N 个数相加。
  • L3.1 pipeline / fusion：用计算去藏访存，让 SM 别空转。
  • L3.2 Tensor Core + 混合精度：一层 GEMM 用低精度输入 × fp32 累加吃满算力。
  • station 4 EVT：CUTLASS 把「输出算子」做成可组合树，但那棵树只在一张卡内的多个 CTA 之间。

当一张卡的 HBM / 算力到顶，自然的下一步是把多张卡当成一个更大的「虚拟 GPU」。
这一站的三件事是同一根线的延伸：

单卡内（已学） 跨多卡（本站）
L2.4 shared 归约 跨卡归约：一个 GPU 就是上一个「tile」
L3.1 用计算藏访存 用计算藏通信（comm-compute overlap）
L3.2 张量并行切 GEMM 把一层 GEMM 切到多卡 + NCCL 求和（fp32 累加）

多卡不是新概念，是把并行结构放大到网卡/交换机的尺度。

§1 四种并行形态：什么时候要通信、通信多频繁

把「模型」映射到「多卡」，有四种经典切法（以 transformer 一层为例）：

形态 切什么 通信量 必须待在？
数据并行 DP 每卡一份完整模型，切 batch 每步一次全量梯度 AllReduce 无所谓（一步一次）
张量并行 TP 把一层的权重矩阵切开（列/行并行，Megatron 风格） 每层多次 AllReduce/ReduceScatter NVLink 域内（最频繁）
流水线并行 PP 把不同层分到不同卡，micro-batch 流水 相邻卡点对点传激活 节点内/跨节点都行
模型并行 MP 单算子放不下一张卡（如超大词表） 视结构 视结构

直觉：TP 通信最频繁（每层前向/反向都要 AllReduce），所以 TP 一定圈在 NVLink 域内；
DP 每步才同步一次，容忍跨节点；PP 只在相邻 stage 间传激活。
这就是分布式训练里「同节点内 TP、跨节点 DP」的由来——每一次跨链路的通信都要掉一级带宽悬崖（见 §3）。

§2 PCIe vs NVLink vs NVSwitch：带宽悬崖

GPU 之间怎么连，决定了通信的上限。这是一张「悬崖图」（每级差一个数量级左右）：

互连 单向带宽 / 总双向 备注
HBM（本卡显存） 数 TB/s 顶点
NVLink 5.0（B200, 2024） 100 GB/s / 1.8 TB/s 18 链路
NVLink 4.0（H100, 2022） 100 GB/s / 900 GB/s 18 链路
NVLink 3.0（A100, 2020） 50 GB/s / 600 GB/s 12 链路
NVLink 2.0（V100, 2017） 25 GB/s / 300 GB/s 6 链路
PCIe Gen5 ×16 64 GB/s / 128 GB/s 通用地板
PCIe Gen4 ×16 32 GB/s / 64 GB/s 主流服务器
PCIe Gen3 ×16 16 GB/s / 32 GB/s 老机器
100G 以太网 ~12.5 GB/s 跨机
InfiniBand NDR 50 GB/s 跨机首选

（来源：NVIDIA NVLink 技术博客 developer.nvidia.com/blog/upgrading-multi-gpu-interconnectivity；NVLink 代际表 www.intuitionlabs.ai/articles/nvidia-nvlink-gpu-interconnect）

关键洞察：

  1. NVLink 是 NVIDIA 专用、绕过 CPU 的 GPU-GPU 直连，带宽比 PCIe 高一个数量级，延迟 ~1μs。
  2. NVSwitch（DGX H100：4 片交换芯片接 8 张 H100）把「点对点 NVLink」升级成全连接 mesh——任意两卡同时以 900 GB/s 互通，没有最慢的环链路。这是 ring AllReduce 性能的关键（见 §4）。
  3. PCIe 是「通用地板」：它是给 CPU 挂设备的树形总线，GPU 之间走 PCIe 还要争用存储/网卡，跨 PCIe switch 的有效带宽常常只剩理论值的一半（8–12 GB/s）。
  4. 所以：TP 必须待在 NVLink 域内；否则每层通信立刻掉进 PCIe 悬崖，算力全空转。

§3 NCCL：把集合通信做成「自动选路」的库

NCCL（NVIDIA Collective Communications Library）是 GPU 集合通信的事实标准，API 仿 MPI。

3.1 初始化（两种写法）

注意：ncclCommInitRank 会隐式与其他 rank 同步，必须从不同线程/进程调用，或用 ncclGroupStart/End 包住；单线程循环里逐个调会死锁（见 NCCL 文档）。

3.2 集合原语（把 §1 的通信落到 API）

原语 语义 用在
ncclAllReduce(send, recv, count, type, op, comm, stream) 各卡 send 求和 → 每卡 recv 都一样 DP 梯度同步
ncclBroadcast root 的数据 → 所有卡 初始参数广播
ncclReduce 各卡求和 → 仅 root loss 聚合
ncclAllGather 各卡贡献一段 → 每卡拿到拼接全量 TP 收集分片
ncclReduceScatter 求和后按卡切分 → 每卡只拿 1/N Megatron TP（列/行并行接缝）
ncclSend / ncclRecv 点对点 P2P PP 相邻 stage 传激活
  • redOp：ncclSum / ncclProd / ncclMax / ncclMin / ncclAvg
  • type：ncclFloat16/32/64、ncclBfloat16、ncclInt8/32/64…
  • 关键：ncclAllReduce 在 fp16/bf16 输入上仍用 fp32 累加求和——这正是 §L3.2 混合精度的「低精度输入 × 高精度累加」在多卡尺度的回响。

3.3 异步 + 与计算重叠（= L3.1 的跨卡版）

ncclAllReduce(..., stream) 把通信排在某个 CUDA stream 上、立即返回。
于是可以把它和计算 kernel 放在不同 stream，让 GPU 边算边传：

官方博客原话：「This leaves the bulk of the GPU free to execute compute tasks concurrently with the communication.」——把 §L3.1 的 overlap 思想直接放大到跨卡。
想最大化重叠，可把 NCCL 放在高优先级 stream，让它插进计算 grid 的缝隙。

§4 Ring vs Tree：AllReduce 的两条算法，对应带宽 vs 延迟

AllReduce = 让每张卡都拿到「所有卡数据的归约结果」。两条经典算法：

4.1 Ring AllReduce（带宽最优，大消息首选）

把数据切成 N 块，环上跑两阶段：

  • scatter-reduce（N−1 步）：每步 rank r 把「块 (r−step)」累加发给 (r+1)；N−1 步后，每卡持有一块的完整归约。
  • all-gather（N−1 步）：把已完整的块沿环覆盖式扩散，N−1 步后每卡拿全量。

每卡线上搬运的字节数（bus bytes）：

代码 ring_allreduce_host() 用分块环算法在 CPU 上模拟，与朴素求和对拍 PASS（N=4, K=256）。这正是 L2.4 跨线程归约的「跨卡放大版」——把「一个 tile」换成一个 GPU。

4.2 Tree AllReduce（延迟最优，小消息首选）

  • reduce up：叶子→根，log N 步求和。
  • broadcast down：根→叶子，log N 步下发。
  • 好处：步数仅 log N，小消息延迟更低；且在 NVSwitch 上可做 in-network reduction（SHARP）——交换机内部直接求和，不占 GPU 带宽。

NCCL 按消息大小/拓扑自动选 Ring 还是 Tree（NCCL_ALGO 可强制）。

4.3 busbw vs algobw（衡量是否压满链路）

代码 report_bandwidth() 输出（N=8, K=1 GB）：

链路（单向） bus_bytes/GPU t(ms) algobw busbw
NVLink 4.0 (450 GB/s) 1.750 GB 3.89 257.1 GB/s 450.0 GB/s（压满）
PCIe Gen5 (64 GB/s) 1.750 GB 27.34 36.6 GB/s 64.0 GB/s
PCIe Gen4 (32 GB/s) 1.750 GB 54.69 18.3 GB/s 32.0 GB/s

→ NVLink 用满时 busbw≈450 GB/s，是 PCIe Gen4 的 ~14×；大 N 时 algobw → link/2（环算法每块走 N−1 跳）。

§5 comm-compute overlap：用计算藏通信（= L3.1 跨卡版）

数据并行一步 = 本地前向/反向（compute_ms）+ 梯度 ring AllReduce（comm_ms）。

  • 不重叠：step = compute + comm
  • 重叠（通信排在另一 stream，藏进计算里）：step = max(compute, comm)

代码 report_overlap()（N=8, 模型梯度 14 GB, compute=100ms）：

链路 comm(ms) 不重叠 重叠 通信被藏比例
NVLink 450 GB/s 54.4 154.4 100.0 35.3%
PCIe Gen4 32 GB/s 765.6 865.6 765.6 11.6%

结论：模型越大 / 越偏通信，NVLink 与 PCIe 的差距越致命；
而 TP（每层通信）比 DP（每步一次）更需要 overlap + NVLink，否则算力全空转。
这把 §L3.1「用计算藏访存」和 §L2.3「compute-bound vs memory-bound」彻底闭环：
多卡扩展的瓶颈从「显存带宽」变成了「卡间带宽」。

§6 与前面所有站的闭环（一张网）

  • CUTLASS 3.x CollectiveEpilogue 能在一张卡内多个 CTA 之间做归约（输出算子树的一部分）；
    但一旦要跨 GPU，归约的边界就交给了 NCCL——这就是「卡内可组合输出算子」与「卡间集合通信」的责任划分。
  • 混合精度 fp32 累加：单卡 MMA 累加器是 fp32（§L3.2），NCCL AllReduce 的 redOp 同样用 fp32 累加——尺度变了，原则不变。

§8 编译运行

一句话收束：多卡把「并行结构」放大到交换机尺度——NVLink 决定带宽天花板，NCCL 自动选路 + 异步重叠把通信藏进计算，张量并行把一层 GEMM 切到多卡并用 fp32 累加求和；而它背后的每一条原理，都是 L2.4→L3.3 已经学过的东西在更大尺度上的回响。

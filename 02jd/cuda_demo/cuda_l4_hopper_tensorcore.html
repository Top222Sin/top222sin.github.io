L4 Hopper (SM_90) Tensor Core 主线：FP8 + TMA + 稀疏 + FlashAttention

配套 cuda_l4_hopper_tensorcore.cpp。四联图示：images/fig21_hopper_tensorcore.svg，浏览器预览 cuda_l4_hopper_tensorcore_diagrams.html。
衔接：L3.2 把 Tensor Core 讲到 Ampere sm_80 / fp16 / tf32 为止；本站在「工业扩展层(L4)」把这条线续到 Hopper sm_90 的四项关键扩展——大模型推理/训练的算力与显存主战场。

0. 为什么从 sm_80 续到 sm_90

L3.2 的吞吐模型已经点明：TC 用低精度输入换算力，Ampere 上 fp16 TC≈312、tf32 TC≈156 TFLOPS。但大模型时代三件事把天花板又抬高了一截：

  1. fp16 还不够省：权重/激活再压一档到 fp8（1 字节），操作数带宽直接再减半，TC 算力再翻番。
  2. 取数成为新瓶颈：GEMM 的 A/B tile 拷贝若仍占寄存器 / 占 launch，SM 在等数据。Hopper 用 TMA（Tensor Memory Accelerator） 把「取数」变成描述符驱动的异步 bulk 搬运。
  3. 权重天然可稀疏：训练/推理后的权重做 2:4 结构化稀疏，硬件稀疏 TC 直接跳过零项 → 再 2×。
  4. 注意力是显存怪兽：朴素 attention 物化 N×N 分数矩阵，峰值显存 ∝ N²。FlashAttention 用 online softmax 分块 把它压到 ∝ N。

这四条在 Hopper 上串成一条 GEMM 主线（见 §5）。

1. FP8 (E4M3) Tensor Core

FP8 有两个格式（NVIDIA）：

  • E4M3（4 指数 / 3 尾数，bias 7）：max normal = 240，尾数 3 位 → 相对精度 ~6%。前向（权重/激活）主力格式。
  • E5M2（5 指数 / 2 尾数，bias 15）：max = 57344，范围大 → 梯度路径。

代码 f32_to_e4m3() 用「生成 e4m3 全部可表示值 → 就近舍入」忠实模拟硬件量化（host 端替代 __nv_fp8_e4m3）。GEMM 仍是 fp8 乘 + fp32 累加——TC 的「低精度乘、高精度加」纪律不变。

  • A3：fp8(e4m3) GEMM 与纯 fp32 GEMM 最大 abs 误差 ≈ 3.0e-2（量级合理，fp8 尾数粗）。
  • A4：精度谱有序 **fp16 误差(3.9e-4) < fp8 误差(3.0e-2)**——fp8 只有 3 尾数位 vs fp16 的 10 位。
  • A5：fp8 操作数 1 字节 vs fp16 2 字节 → 内存/带宽再 2×↓。
  • A6：H100 fp8 TC ≈ 2× fp16 TC（989.4 → 1979 TFLOPS，公开峰值）；叠 2:4 稀疏 → 3958（≈4× fp16-dense）。

真机指令（#ifdef __CUDACC__ 守护）：mma.sync.aligned.m16n8k32.row.col.f32.e4m3.e4m3.f32——注意 k=32（fp8 1 字节，一次吞下更多 K）。e5m2 变体用于梯度。

2. TMA（Tensor Memory Accelerator）

TMA 是 Hopper 新增的 专用异步 bulk copy 引擎，把「global→shared 取数」从手写循环变成描述符驱动的硬件操作：

  • **描述符 CUtensorMap**：编码张量 dims / strides / swizzle / interleave。一次 cp.async.bulk.tensor 按描述符搬一个 box（子 tile）。
  • 2D strided copy：源张量行 stride 可 ≠ 连续，TMA 按描述符逐行 gather（代码 B1 验证 == 手工 strided 拷贝，逐元素一致）。
  • swizzle：硬件对 shared 地址做 XOR 重排（如 128B swizzle），破 bank conflict——值不变、仅布局（B2 验证可还原）。
  • multicast：一次拷贝把同一 tile 广播到 cluster 内多个 CTA（GEMM 里 A 要发给一行 CTA），B3 验证两 CTA 收到同一份。

关键收益：取数完全异步、不占寄存器、发射线程不阻塞——SM 在 TMA 搬数的同时做计算（呼应 L3.1 的 cp.async 思想，但搬的是整个 tile 而非 16B 粒度）。

真机：cuTensorMapEncodeTiled(...) 建描述符；cp.async.bulk.tensor.2d.shared::cluster.global.tile.box [dst],[desc],x,y;（或 tcgen05.ld/.st）。

3. 稀疏 Tensor Core（2:4 结构化稀疏）

2:4 结构化稀疏：每连续 4 个权重，恰好保留 2 个、剪 2 个；哪 2 个由 2-bit 元数据（6 种模式）编码。稀疏 TC 只读保留的 2 个、跳过 2 个零 → 2× 吞吐。

  • C1：稀疏路径 == 显式剪枝路径（逐位一致 err=0）——因为被剪位置在 A 中恰为 0，稀疏 TC 的「跳过」与「显式置零后做稠密 GEMM」数学上完全等价（同序累加）。
  • C2：元数据 2-bit 编码 6 种模式，可往返。
  • C3：压缩表示每 4 个恰好 2 值（= 保留的 2 个）。
  • C4：2:4 剪枝是 magnitude-aware——每组保留 |.| 最大的 2 个（最优 2:4 近似，误差最小）。

注意：稀疏 TC 给出 2× 是「假设权重已满足 2:4」的硬件加速；权重需先经 2:4 剪枝 + 元数据编码（训练可用稀疏感知方法，使剪枝误差可控）。mma.sp.sync.aligned.m16n8k16... + metadata 即稀疏 TC 指令。

4. FlashAttention（online softmax）

朴素 attention：算 S = QKᵀ/√d（M×N）→ 行 softmax → O = P·V，物化 N×N 的 S → 峰值显存 ∝ N²。

FlashAttention 用 online softmax 分块前向：流式处理 N 维，边算边维护 running max m 与 running sum l，对已有累加的 O 做 exp(m−m_new) 校正后并入新块——从不物化整张 S。

  • D1：FlashAttention == naive attention（fp32 容差内，maxdiff ≈ 8.3e-7；非严格逐位——online softmax 重排了归一化顺序，fp32 下差 ~1e-6 量级）。
  • D2：IO-aware 峰值显存 ∝ N（vs naive ∝ N²）；N=2048,d=64 时 naive S 矩阵 ≈16.7MB、flash 仅 O(M×d)+tile ≈0.5MB，比值≈33×。
  • D3：FLOPs 与 naive 相同（都 O(M·N·d)）——Flash 省的是显存/带宽不是计算量。
  • D4：分块不变（Br=8 vs 32 结果 maxdiff=0）——online softmax 跨块无缝续算，块大小只影响流水、不改数值。

真机骨架（Hopper）：cp.async.bulk.tensor 异步搬 K/V tile → wgmma.mma_async（Hopper 异步 warpgroup MMA）累加 S → 寄存器/shared 内做 online softmax rescale → 写回 O。全程 HBM 流量 ∝ N。

5. 四者如何串成 Hopper GEMM 主线（闭环 L3.2）

  • FP8 把「单点积」的字节/算力压到最低；
  • 稀疏 TC 在 FP8 之上再 ×2（权重半数本就是 0）；
  • TMA 让「喂数」不拖后腿（异步 + 不占寄存器 + 广播）；
  • FlashAttention 是这条主线在注意力算子上的集大成（IO-aware，显存 ∝ N）。

→ 与 L3.2 的「混合精度三角（精度/带宽/吞吐）」一脉相承，只是把每个顶点都推到 Hopper 工业极限。

L1.3 会调用 cuBLAS / cuDNN 等上层库

对应笔记：01CUDA基础学习.docx → L1 能跑（入门）→ 3、会调用 cuBLAS/cuDNN 等上层库
配套代码：cuda_l1_blas_cudnn.cpp（cuBLAS SAXPY + SGEMM + cuDNN 卷积，均带可验证数值）
图示：images/fig3_blas_cudnn.svg（浏览器完整预览见 cuda_l1_blas_cudnn_diagrams.html）

一、先想清楚：为什么 L1 就要学”调库”

前面 L1.1/L1.2 你亲手写了 SAXPY、向量平方、配了 launch_bounds。但工业级 CUDA 程序 80% 的工作量在调库，不是写 kernel：

你想做的事 手写 kernel 调上层库
矩阵乘 C=A·B 要管分块、shared mem、合并访问、寄存器（L2/L3 才到） cublasSgemm 一行，NVIDIA 工程师已调到极致
卷积 要管 im2col / Winograd / 直接卷积（超复杂） cudnnConvolutionForward 一行，算法自动挑
激活/BN/池化 自己写 + 调参 cuDNN 内置

结论：L1 必须会”把库当积木拼”——这是能跑通一个真实 DNN 推理/训练的最短路。手写 kernel 是 L2/L3 的进阶武器，用来补库没有的自定义算子。

二、cuBLAS —— 线性代数库（BLAS 的 GPU 版）

cuBLAS 是”列主序（column-major）”的，这点贯穿所有调用，后面 SGEMM 会专门讲陷阱。

2.1 通用三步（每个 cuBLAS 程序都有）

为什么有 POINTER_MODE？ cuBLAS 默认 POINTER_MODE_DEVICE：像 alpha 这种标量也要放在 device 上。你若在 host 写 float a=2; cublasSaxpy(...,&a,...) 而不切 HOST 模式，会读野指针崩。教学/快速代码直接切 HOST 最省心。

2.2 示例一：SAXPY（z = a*x + y）

对应 cuda_l1_blas_cudnn.cpp::demo_cublas_saxpy：

  • 参数顺序：(handle, n, &alpha, x, incx, y, incy)，incx/incy=1 表示”相邻元素步长 1”。
  • SAXPY 是纯向量顺序扫，与列主序/行主序无关，所以直接用即可。
  • 验证：x[i]=i, y[i]=2i, a=2 → y[i]=2i+2i=4i，检查 y[5]==20。

2.3 示例二：SGEMM 矩阵乘 C = A·B（重点陷阱）

对应 cuda_l1_blas_cudnn.cpp::demo_cublas_sgemm，手算验证：

陷阱：cuBLAS 是列主序，而 C/C++ 数组是行主序。直接把行主序矩阵塞进去会得到转置结果。

经典解法（不动数据、只动调用）：交换 A、B 的位置，并交换 M、N：

为什么这样是对的（直觉版）：cuBLAS 在”列主序视角”下算 C_col = (我们的B)·(我们的A)；经过列主序↔行主序的重新解读，恰好等价于行主序的 C_row = A_row·B_row。文件里用 2×3 × 3×2 的整数手算逐元素验证了 C=[58,64,139,154]。

想彻底避免这个坑？全程用列主序（存储时转置），那就能按直觉 cublasSgemm(..., d_A, M, d_B, K, d_C, M) 写。但 C 生态默认行主序，所以”swap 法”是实战最常用的写法。

三、cuDNN —— 深度神经网络库

cuDNN 用 “描述符（descriptor）”模型：先声明张量/核/卷积的形状与精度，再让库去算。比 cuBLAS 啰嗦，但把”形状、算法、精度”全显式化了。

3.1 卷积前向七步（对应 demo_cudnn_conv）

关于算法选择：上面直接指定 IMPLICIT_GEMM（最简单稳定）。cuDNN 8+ 推荐用 启发式 API cudnnGetConvolutionForwardAlgorithm_v7 + cudnnFindConvolutionForwardAlgorithm 在真实硬件上挑最快算法（不同 GPU/形状最优算法不同）。教学阶段用固定算法即可跑通。

四、何时用库、何时自己写 kernel（决策表）

场景 用 理由
标准矩阵乘 / 卷积 / 激活 / BN / 池化 cuBLAS / cuDNN 官方已极致调优，自己写难超越
自定义算子（特殊激活、稀疏、量化） 自己写 kernel（L2/L3） 库没有，或库路径太绕
想控制内存布局 / 融合多个算子 自己写 + 库混合 kernel fusion 省往返（L3）
跨平台（AMD/Intel） clBLAS / 手写 OpenCL cuBLAS/cuDNN 是 NVIDIA 专属

五、OpenCL 对照（双轨学习）

  • cuBLAS ↔ clBLAS：AMD 主导的 OpenCL BLAS，API 几乎一一对应（clblasSaxpy / clblasSgemm）。
  • cuDNN ↔ 无官方孪生：OpenCL 世界没有统一 DNN 库。常见做法：ROCm 的 MIOpen（HIP，非纯 OpenCL）、clDNN（旧 Intel）、或直接手写 OpenCL kernel。
  • 核心认知：调库的本质是”复用别人调好的 kernel + 他家的 launch 配置 + 他家的内存约定（如 cuBLAS 列主序）”。换平台要重新对齐这些约定——所以 NCNN/MNN 把”算法”和”后端适配层”分开：同一份算法，在 NEON / SVE2 / CUDA / OpenCL 各写一份后端，前端算子不变（你之前在 neon_demo 里深挖的就是这层）。

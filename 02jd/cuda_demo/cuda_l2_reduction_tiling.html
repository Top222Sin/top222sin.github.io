L2.4 自己写高效 kernel —— 共享内存归约 reduction / 矩阵乘分块 tiling

配套代码：cuda_l2_reduction_tiling.cpp
对应笔记本：01CUDA基础学习.docx → L2 能写高效 kernel → 4、共享内存归约 reduction、矩阵乘分块 tiling
这是 L2 的收官，也是第一个”真正高性能”的手写 kernel：它把前面三节一次性串起来——L2.1（shared 内存 / bank conflict / pad）、L2.2（occupancy）、L2.3（砍 DRAM 流量 → 往 compute-bound 靠）。

一、归约 reduction —— 把 N 个数求和

错误写法（先知道坑在哪）

  • 单线程 for 循环：完全没有并行，一个 SM 上只跑 1 个线程 → 浪费 99.9% 算力。
  • atomicAdd 全局求和：所有线程抢同一块全局地址 → 串行化，且 global 原子极慢。

正解：block 内 shared 树形归约

每个 block 把一段数据搬进 __shared__，在 block 内做二叉树归约：第 1 步 256 个变 128 个、第 2 步 128→64……直到 1 个，得到该 block 的 partial（部分和）；最后把所有 partial 合并。

  • 并行度 = block 数（成千上万个 partial 同时算）。
  • 全局访存天然合并（线程 tid 读 in[block*256+tid]）。
  • 缺点：归约本身是 memory-bound（AI≈0.5，1 次加对应 2 次取数），shared 不能改变 AI，但把”延迟/吞吐”用并行 + 片上复用彻底改善。

关键坑（呼应 L2.1）：shared 归约的 bank conflict

reduce_halving 用”交错寻址”：stride 减半，线程 tid 累加 s[tid]+=s[tid+stride]。

  • 当 stride=32 时，s[tid] 与 s[tid+32] 落在同一个 bank（bank(i)=i%32）→ 这一歩是 2 路 bank conflict。
  • 现代最佳实践（reduce_warp_shuffle）：树形归约末段改用 warp shuffle __shfl_down_sync，数据在寄存器间直接搬，完全不碰 shared 的 bank，彻底无冲突。

经验：归约的”无冲突”首选 warp shuffle（寄存器级），而非 pad shared。pad 是 L2.1 的通用手段，这里 shuffle 更干净。

二、矩阵乘分块 tiling —— 砍掉冗余的全局流量

朴素 matmul：每线程算一个 C[i][j] = Σ_k A[i][k]·B[k][j]

  • 每个 C[i][j] 要读 A 的第 i 行（K 个）+ B 的第 j 列（K 个）。
  • 所有输出一共把 A 的每个元素读了 N 次、B 的每个元素读了 M 次 → 朴素全局流量 ≈ 2·M·N·K 个元素级取数（加 M·N 写回）。这正是 L2.3 说的”memory-bound 根因 = 冗余 global 取数”。

分块后的真实流量（TILE 复用是核心）

⚠ 公式纠错：早期版本写”分块后全局流量 = M·K + K·N + M·N（每个元素取 1 次）”——错误：那只有当整个矩阵能一次装进 shared 才成立。实际 tile 化后 A 元素被 (N/T) 个 tile 复用、B 元素被 (M/T) 个 tile 复用，流量是 2·M·N·K/T（T 越大复用越多）。”下降 171×”是早期公式（把 2S³/S² 当 S/2=128 再凑数）的错误结论，正确值是 ~15.5×（S=256, T=16）——仍是大幅下降（一个数量级），但别把数字记错。

分块 tiled matmul：把数据”搬一次、用 TILE² 次”

把 A、B 切成 TILE×TILE 小块搬进 shared，blockIdx 对应 C 的一个 TILE，block 内 TILE×TILE 个线程协作：

  • 每轮取 A、B 各一个 TILE 进 shared → 每个全局元素只进 shared 一次，被 TILE×TILE 个线程复用。
  • 全局流量从 2·M·N·K 降到 M·K + K·N + M·N（每个元素取 1 次）。

量化这个收益（本文件 analyze_tiling()，CPU 可跑）

方阵 S=256（M=N=K）：

  • 朴素取数 ≈ 2·256³ + 256² ≈ 3.36×10⁷ 个元素
  • 分块取数 ≈ 3·256² ≈ 1.97×10⁵ 个元素
  • ▶ 全局流量下降 ≈ 15.5×（S=256, T=16），而 FLOPs 完全不变——tiling 把 memory-bound GEMM 的 DRAM 压力砍掉一个数量级。

重要且容易误解的一点：tiling 不改变算术强度 AI（FLOPs/原始数据字节不变），但它把”每个全局元素只取一次”——直接砍掉冗余 DRAM 流量。呼应 L2.3：对于 memory-bound 算子，优化的核心就是”减 DRAM 取数 / 提数据复用”。大矩阵 matmul 的 AI 本来就不低，真正的杀手是”重复取数”，tiling 一招解决。

关键坑（呼应 L2.1）：shared 里读 B 小块会撞 bank conflict

matmul_tiled 在 inner loop 读 b_tile[k][tx]：跨 warp 读同一列 → 2 路 bank conflict。
解决：把 B 小块转置存进 shared（matmul_tiled_transposed：存 b_tile[tx][ty]，读 b_tile[tx][k] 变行连续）→ 完全无冲突，结果数值一致。这与 L2.1 转置 pad 是同一类”算 bank 偏移”的功夫。

与 matmul_tiled 还有个等价手段：pad b_tile[TILE][TILE+1]（L2.1 的 pad 套路）。转置更省 shared、更常用。

三、把 L2 三节串起来（本节为什么是”收官”）

前面学的 在本节怎么用 体现在哪个 kernel
L2.1 shared / bank / pad 归约与 tiling 都用 shared；归约用 warp shuffle 避冲突，tiling 用 B 转置避冲突 reduce_warp_shuffle / matmul_tiled_transposed
L2.2 occupancy 适度 shared 用量（每 block 2 个 TILE² 数组）→ 不挤爆 shared → 好的 occupancy → sm__throughput 上得去 三者共享 __shared__ 预算
L2.3 减 DRAM 流量 tiling 把全局取数降 ~15×（S=256,T=16）→ memory-bound 的 DRAM 压力被砍；用 ncu 测 dram__throughput 应明显下降 analyze_tiling() 量化

一句话：L2.1 给你武器（shared），L2.2 给你约束（occupancy），L2.3 给你判据（bound 类型）；L2.4 让你第一次亲手用这些武器、在约束内、对着判据，写出真正高性能的 kernel。

四、代码走读（cuda_l2_reduction_tiling.cpp 主线）

  1. reduce_halving — 经典交错寻址树形归约，每 block 出一 partial；注释标出 stride=32 的 2 路 bank conflict。
  2. reduce_warp_shuffle — warp_reduce() 用 __shfl_down_sync 把末段归约搬到寄存器，无 bank conflict；每 warp 出 1 个和，再由第 0 warp 归约 8 个和。
  3. matmul_naive — 每线程一个输出，全局流量最大，作 baseline。
  4. matmul_tiled — TILE×TILE shared 分块，inner loop 读 b_tile[k][tx] 有 2 路 bank conflict。
  5. matmul_tiled_transposed — B 转置入 shared，读 b_tile[tx][k] 行连续 → 无冲突，数值与 naive 一致。
  6. **analyze_tiling()**（确定性、CPU 可跑）— 算出 S=256 时全局流量下降 ≈15.5×，并打印”三节串联”要点。
  7. **run_gpu_checks()**（真机段）— GPU 上对拍：归约 reduce_halving/reduce_warp_shuffle 与 CPU 求和一致；三种 matmul 与 cpu_matmul 一致。

编译运行（需真机）：nvcc -O3 -std=c++17 cuda_l2_reduction_tiling.cpp -o rt && ./rt

五、OpenCL 对照（概念完全同构）

CUDA OpenCL 备注
__shared__ __local 分块/归约同理
bank conflict local memory 同样 32 bank pad / 转置思路一致
__shfl_down_sync sub_group_shuffle(厂商扩展) warp 内寄存器搬运
__syncthreads() barrier(CLK_LOCAL_MEM_FENCE) 同步原语
blockIdx/threadIdx 2D get_group_id / get_local_id 2D 网格映射一致
occupancy compute unit 上 wavefront 驻留率 受 local mem 用量限制

归约/tiling 的”算法骨架”在所有 SIMT GPU 上通用，差异只在 API 与 bank 细节。

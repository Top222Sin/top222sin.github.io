L2.3 用 Nsight 做 profiling —— 区分 compute-bound vs memory-bound

配套代码：cuda_l2_profiling_bound.cpp
对应笔记本：01CUDA基础学习.docx → L2 能写高效 kernel → 3、Nsight Compute / Nsight Systems profiling，区分 compute-bound vs memory-bound
这是 L2 的第三道分水岭，也是把前面 L2.1（带宽/延迟）和 L2.2（occupancy）那些抽象概念第一次用真机数据量化的地方。前两节讲”为什么慢”，这一节讲”怎么用工具确认到底慢在哪、卡在算力还是带宽”。

一、两个工具定位：NCU（看 kernel 内） vs NSYS（看系统时间线）

很多新手只记得”跑个 ncu”，但两者职责完全不同：

Nsight Compute (ncu) Nsight Systems (nsys)
看什么 单个 kernel 的深层硬件指标（SM 算力利用率、DRAM 带宽、occupancy、各 stage 卡点） 整个程序的时间线（kernel 何时发射、CUDA API 耗时、CPU 与 GPU 是否重叠、有无空隙）
回答的问题 “这个 kernel 是被算力还是带宽卡住？哪一级 pipeline 最闲/最忙？” “GPU 有没有被喂饱？host 是不是在拖后腿？整段有没有空隙？”
类比 给一个函数做火焰图 + 微架构剖析 给整个程序做甘特图
典型用法 ncu --set full -k <kernel> ./exe nsys profile -o tl ./exe

经验法则：**先用 nsys 确认”GPU 有没有被充分利用、有没有空隙”，再用 ncu 钻进具体 kernel 看”卡在算力还是带宽”**。二者是”宏观时间线 → 微观指标”的递进关系。

二、核心判据：算术强度 AI 与 Roofline 模型

“compute-bound vs memory-bound”不是拍脑袋，而是一个数学判据：

算术强度 AI（Arithmetic Intensity）= 每搬 1 字节数据，能做多少 FLOP

把它和 GPU 的平衡点 ridge point 比较：

  • AI < ridge → 数据还不够算就被用完了 → 被显存带宽卡住 → memory-bound
  • AI > ridge → 算力先顶不住 → 被 SM 算力卡住 → compute-bound

这就是 Roofline 模型的本质：横轴是 AI（对数），纵轴是可达算力；左斜边是带宽屋顶（mem BW × AI），平顶是算力屋顶（peak FP），kernel 落在哪条边下，就受哪条边限制。

本文件用两个对照 kernel 把判据”算死”

① saxpy_memory_bound（内存密集）

② compute_bound（计算密集，纯 ALU 便于 CPU 对拍）

以 A100 量级（19.5 TFLOP/s，1.555 TB/s）为例：ridge ≈ 19.5/1.555 ≈ 12.5 FLOP/Byte。

  • saxpy 的 AI≈0.17 远小于 12.5 → memory-bound（Roofline 预言峰值 ≈ BW×AI ≈ 0.26 GFLOP/s，被带宽压死）
  • compute_bound(ITERS=64) 的 AI=16 大于 12.5 → compute-bound（可达算力主导，逼近 19.5 TFLOP/s）

关键点：AI 是比率，与数组规模 N 无关——cuda_l2_profiling_bound.cpp 里 analyze_kernels() 在 CPU 上就能确定性算出这两个数，沙箱无 GPU 也能把”谁 bound”讲清楚。

三、compute-bound vs memory-bound：ncu 里看哪些指标

真机跑 ncu 后，判断 bound 的”看板”是这几个：

指标（ncu 名） 含义 memory-bound 信号 compute-bound 信号
sm__throughput SM 算力利用率 低（算力没用满） 高（接近峰值）
dram__throughput DRAM 带宽利用率 高（显存被打满） 低
l1tex__throughput L1/纹理/共享吞吐 可能高（频繁取数） 低
sm__warps_active（=achieved occupancy） 实际驻留 warp 比 可能低（等显存→空转） 较高
gpu__time_duration kernel 时长 由访存量主导 由 FLOP 量主导

一句话判读：

  • dram__throughput 高 + sm__throughput 低 → memory-bound，优化方向是减少访存 / 合并 / 用 shared / 提 AI（这正是 L2.1 的内容）。
  • sm__throughput 高 + dram__throughput 低 → compute-bound，优化方向是减少 FLOP / 用更快的指令 / 换 Tensor Core / 算法降复杂度（L3 内容）。
  • 两者都低 → 多半不是算力/带宽问题，而是 occupancy 低 / 分支发散 / 同步等待（回到 L2.2）或 launch 配置 / kernel 太小（Nsight Systems 里看）。

四、Nsight Systems：看时间线，找 CPU/GPU 空隙与重叠

nsys profile -o tl ./exe 生成的甘特图里，关注三件事：

  1. GPU 绿条是否连续：中间有空白段 = GPU 在等（host 拷贝慢、host 计算拖后腿、或 kernel 启动开销大）。
  2. CPU 与 GPU 是否重叠：理想情况是 host 准备下一批数据的同时 GPU 在算。如果 host 段和 GPU 段完全串行 → 没用满双端。
  3. CUDA API（cudaMemcpy 等）占比：如果 cudaMemcpy 占了时间线一大段，说明数据传输成了瓶颈，该考虑 pinned memory / 异步拷贝 / kernel fusion（L3）减少往返。

这个层面和前面的”微架构 bound”互补：ncu 告诉你 kernel 内部卡在哪，nsys 告诉你整体有没有被喂饱。HPC 调优的正确顺序是：nsys 宏观确认 GPU 利用率 → ncu 微观定位 bound 类型 → 按 bound 类型选优化手段。

五、代码走读（cuda_l2_profiling_bound.cpp 主线）

  1. GpuSpec + ridge_point() — 把”峰值算力/带宽 → 平衡点”参数化，演示用 A100 量级；换成你的卡改两个数即可。判据方法与具体硬件解耦。
  2. 两个对照 kernel — saxpy_memory_bound（低 AI，memory-bound）与 compute_bound（ALU-heavy，高 AI，compute-bound）。后者刻意用纯 ALU而非 sin/cos，保证 CPU 参考可对拍到逐位一致。
  3. **analyze_kernels()**（确定性、CPU 可跑）— 算出两个 kernel 的 FLOPs/Bytes/AI，对照 ridge 点打印”memory-bound / compute-bound“判定与 Roofline 预言峰值。这是本文件的”教学内核”，沙箱无 GPU 也能验证判据。
  4. print_profiler_commands() — 直接打印真机 ncu（full / 关键指标两版）与 nsys 命令，照抄即跑。
  5. **run_gpu_checks()**（真机段）— 在 GPU 上真启动两个 kernel，用 CPU 参考对拍正确性（saxpy 与 compute_bound 均 PASS）。main 末尾默认不调用，真机取消注释即可。

编译运行（需真机）：nvcc -O3 -std=c++17 cuda_l2_profiling_bound.cpp -o prof && ./prof

六、OpenCL 对照（概念完全同构）

CUDA OpenCL 备注
Nsight Compute (ncu) rocprof(AMD) / Intel vtune / nvprof 旧 各厂商自有 kernel profiler
Nsight Systems (nsys) rocprof --timestamp / perf + tracy 时间线类工具需拼装
sm__throughput（算力利用率） WavefrontsEvents / ALU 利用率 算力屋顶
dram__throughput（显存带宽） MemoryBus 带宽计数 带宽屋顶
算术强度 AI / Roofline 同样适用 判据是体系无关的，GPU/CPU/加速器通用
occupancy wavefront 驻留率 CFL/used VGPRs 限制

Roofline / 算术强度这套方法是架构无关的，在 ARM NEON、CPU、各种加速器上同样成立——这也是为什么前面 NEON 线讲”数据复用 / 分块”本质也是在提 AI。

七、自检（合上文档能答，才叫掌握）

  3. 一个 kernel AI=2 FLOP/Byte，GPU 峰值 10 TFLOP/s、显存 1 TB/s，它是 compute-bound 还是 memory-bound？为什么？
  4. ncu 里哪两个指标”一高一低”能判定 memory-bound？哪两个能判定 compute-bound？
  5. 如果 ncu 里 sm__throughput 和 dram__throughput 都低，最可能是什么问题（至少说两种）？
  6. nsys 时间线里”GPU 绿条中间有空白”说明什么？你会从哪几个方向排查？

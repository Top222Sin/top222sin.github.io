L1.4 数值梯度与最速下降：雅可比的标量特例

一句话：当映射输出是标量（f: Rⁿ → R）时，它的雅可比就是梯度 ∇f（一个 1×n 行向量）。最速下降 x ← x − α·∇f 正是”沿雅可比反方向走”。

一、标量函数的雅可比 = 梯度

对 f(x,y) = (x−2)² + (y−3)² + 1，唯一极小在 (2,3)，最小值 1。其雅可比（梯度）为

∇f = [ 2(x−2) , 2(y−3) ]

梯度处处垂直于等高线，指向 f 上升最快的方向；所以 −∇f 指向下降最快的方向。

为什么梯度是”上升最快方向”（推导直觉）

结论：方向导数 = 梯度在 d 上的投影，投影最大当且仅当 d∥∇f。梯度方向是”局部最优方向”，但它只是局部的——山坡不是碗形时，最速下降会”之字形”慢走（见自检里的 (x−2)⁴ 例子）。

二、最速下降

迭代更新 x ← x − α·∇f，步长 α 控制每步走多远。demo 从 (0,0) 出发，200 步内收敛到 (2,3)，f→1。

步长 α 的权衡（工程关键）

工程结论：最速下降在条件数差（椭球状等高线）的问题上性能崩坏——这就是为什么现代优化用 Newton（乘 Hessian⁻¹ 预条件，L2.5 的 G-N/L-M 就是自动做这件事）。最速下降的价值在简单、鲁棒、只要梯度，适合规模大但条件好的问题（固定步长还需 Lipschitz 梯度保证收敛）。

中心差分 vs 前向差分的精度（为什么选中心）

工程铁律：数值梯度 h 有”甜点区”（太小舍入、太大截断）。双精度下中心差分误差平衡给出 h≈eps^(1/3)≈6e-6 量级，但实际最优 h 还依赖变量尺度与函数尺度——1e-6~1e-7 是常见起点，需按问题调整。这也是为什么大项目都用解析梯度或自动微分（L3.3）——数值梯度永远有 h 选择的拉扯。

六、工程落点（真实项目）

  • 深度学习训练：SGD/Adam 就是最速下降的现代改良（加动量、自适应步长）——L3.3 的反向传播负责高效算 ∇f，优化器负责”沿梯度走”。你的推理引擎（ncnn/MNN/ONNX Runtime）部署前的量化/剪枝敏感度分析常需要梯度信息。
  • Ceres Solver 的 NumericDiffCostFunction：就是把这个 demo 的”数值梯度 + 雅可比对拍”封装成库——手写雅可比之前先用数值梯度验证（Ceres 官方推荐的开发流程）。
  • 机器人参数标定：手眼标定/运动学标定（cali_demo）的误差函数对参数求梯度，最速下降是最朴素的起步求解器。
  • LLM 部署：模型压缩的梯度裁剪、敏感度分析（哪些层剪了不掉点）——本质上都是”损失对参数的雅可比”的工程应用。

七、自检

  • 把 α 调大到接近 1（本函数 Hessian=2I，α*=0.5 一步到位；α≥1 会越过极小点震荡）——体会步长 trade-off。
  • 把函数换成 f=(x−2)⁴（单变量），看梯度在 x→2 附近变平后最速下降为何”变慢”（梯度消失→每步走得少）；想看”之字形”应换二维不同曲率的椭圆二次函数（如 f=x²+10y²）。
  • 思考：为什么实际优化器都抛弃了”固定 α”？（等高线椭球 → 固定步长要么慢要么震荡，需要自适应——Adam 的 RMS 归一化就是干这个）

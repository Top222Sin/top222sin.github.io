内存与性能: Drepper 论文 + CSAPP 第 2/5/6/9 章精讲

内存与性能: Drepper 论文 + CSAPP 第 2/5/6/9 章精讲

论文: What Every Programmer Should Know About Memory, Ulrich Drepper, 2007(约 114 页)
教材: Computer Systems: A Programmer’s Perspective(CSAPP)第 2/5/6/9 章
视角: 模型部署 / 算子优化工程师。论文中的章节号、周期数、加速比、页表层级均以原文为准;CSAPP 部分按教科书公认结论写。

0. 结论先行(30 秒)

  • 内存墙是真实的:论文引 Intel 公布的延迟数据(§3.3.4),寄存器 ≤1 周期、L1d ~3 周期、L2 ~14 周期、主存 ~240 周期。一次主存访问 ≈ 几百条算术指令的时间,所以”少访问内存”往往比”少做计算”回报大得多。
  • 硬件缓存不能离开程序员配合(论文摘要原话)。同一条数据、两种访问顺序,论文实测矩阵乘转置后从 16,765,297,870 周期降到 3,922,373,010 周期,加速 76.6%(§6.2.1,Table 6.2)。
  • 三件事决定了访存成本:① 单位是 cache 行(64B) 不是字节;② 缓存容量远小于工作集(cache:内存 ≈ 1:1000,§3.1);③ 地址翻译(TLB/页表)和 NUMA 距离开销会再叠加一层。
  • 对部署/算子工程师的直接意义:张量布局(行主序/NCHW↔NHWC)、分块大小、对齐与 padding、NUMA 绑核、大页、软件预取——这些不是”玄学调参”,每一条都对应本节后面的一个具体机制。
  • CSAPP 是论文的”教材版”:同样的结论用更系统的组织讲一遍,把”是什么”补成”为什么”和”怎么算”(AMAT、地址三段划分、页表翻译)。

2. Drepper 逐层机制

2.1 RAM 与 DRAM 特性(§2)

  • SRAM vs DRAM:SRAM 快、贵、密度低 → 做缓存;DRAM 慢、便宜、密度高 → 做主存(§2.1)。
  • DRAM 按行列寻址:先发 RAS 激活整行到 row buffer,再发 CAS 选中列(§2.2.1–2.2.2)。同一行内的连续访问 = 命中 row buffer,快;跨行 = 先预充电再激活,慢。这就是”空间局部性”在硬件层的第一层解释。
  • CAS Latency(CL):从发 CAS 到数据可用的延迟,是内存时序参数里的关键项(§2.2.2)。
  • 刷新(refresh):JEDEC 规定每个 DRAM 单元必须每 64ms 刷新一次;一个 8192 行的阵列意味着控制器平均每 7.8125µs 就要发一条 refresh 命令,刷新期间该行不可访问(§2.2.3)。这解释了为什么”偶发的、看似随机的延迟尖峰”有时来自内存控制器而非程序。

记忆锚点:一次主存访问 ≈ 200–240 周期(§3.3.4 引 Intel 数据;§3.3 举例用”主存 200 周期 vs 缓存 15 周期”)。

2.2 Cache 结构与三种映射(§3.3.1)

一个缓存可用三个参数描述:$C = S \times E \times B$,其中 $S$ 为组数、$E$ 为每组行数(关联度)、$B$ 为行大小(字节)。论文以 4MB 缓存、64B 行说明:共 65,536 个缓存行。

  • 全相联(Fully Associative):任意行可放任意地址。需要为每行配一个比较器,4MB/64B 就要 65,536 个并发比较器,不现实;只用于极小的缓存(论文点名:某些 Intel 处理器的 TLB 是全相联,只有几十项)(§3.3.1)。
  • 直接映射(Direct-Mapped):每个地址只对应唯一一行,比较器只需 1 个,但地址分布不均时某些行被反复驱逐(抖动)。
  • 组相联(Set-Associative):折中方案,现代 L1/L2 主流。地址被切成标记 tag / 组索引 set / 块偏移 offset 三段,组内多路并行比对(§3.3.1)。

2.3 Cache 行、局部性与三类 miss

  • 访问单位是 cache 行:论文以 64B 行为例,地址低 6 位被清零,只把行粒度搬进 L1d(§3.2)。所以”随机访问 1 个字节”的代价和”访问一整行”相同——利用率低就是纯浪费。
  • 局部性:时间局部性(同地址很快复用)+ 空间局部性(邻近地址很快被用到)。论文说,正是”工作集有限但物理上不连续”这一点,才让缓存有意义(§3.1)。
  • 三类 miss(论文中的称呼,§3.5.2 明确列出 compulsory 与 capacity;conflict miss 见 §6.2.2 的 aliasing 讨论):
    • Compulsory(强制):首次访问,必 miss → 靠预取掩盖;
    • Capacity(容量):工作集 > 缓存 → 靠分块(tiling);
    • Conflict(冲突):多个地址映射到同一组 → 靠 padding / 换布局。
  • 缓存效果量级:论文的示范计算——同样 100 个数据元素各用 100 次,无缓存 2,000,000 周期,全命中 168,500 周期,改善 91.5%(§3.1)。

2.4 写策略与一致性(§3.3.3, §3.3.4)

  • 写穿透(write-through):写缓存的同时写回主存,简单但慢。
  • 写回(write-back):只标记脏行,驱逐时才写回;现代处理器主流(§3.3.3)。
  • 另有 写合并(write-combining)(用于显卡等设备内存,攒够一整行再写)与 不可缓存(uncacheable)(MMIO 地址,不能被缓存),由 x86 的 MTRR 配置(§3.3.3)。
  • 多核一致性:论文以 MESI 协议为例(§3.3.4),两条要点:脏行不会同时存在于别的缓存;干净副本可以存在于任意多个缓存。
  • 伪共享(false sharing):多个线程写同一缓存行内的不同变量时,写操作需要在各核心的 L1d 中取得独占状态,会发送大量 RFO(Read For Ownership)消息。论文实测开销为 390%(2 线程)、734%(3 线程)、1147%(4 线程)(§6.4.1,Figure 6.10)。对策:每个线程的数据各自对齐到独立缓存行。
  • 带宽不对称:论文实测写带宽远低于读带宽——Netburst 上读满 16 B/周期、而写只有 4 B/周期,超出 L2 后写掉到 0.5 B/周期(比读慢约 10 倍);Core 2 上读写差距甚至到 20×(§3.5.1)。优化”写”比优化”读”更值钱。

2.5 预取(§6.3)

  • 硬件预取器:触发条件是”识别到 ≥2 次同模式 miss”;能识别步长(stride),现代 CPU 可跟踪约 8–16 路流(§6.3.1)。关键限制:硬件预取不能跨页边界,因为跨页可能触发操作系统按需分页。
  • 软件预取:_mm_prefetch(p, hint),提示 _MM_HINT_T0/T1/T2/NTA 分别把行拉到 L1d / L2 / L3 / 非临时(不污染缓存)(§6.3.2)。指针非法时 x86 通常直接忽略,不报错。
  • 何时无效:随机访问的预取几乎无收益(论文的随机指针追逐实验,Figure 6.7 对比)。
  • 临界字优先(Critical Word First & Early Restart):论文指出主存按 64 位块连续传输、相邻块之间延迟 4+ 周期;若程序需要的字在行尾(第 8 个块),要多等约 30 周期;硬件可在程序指示后优先请求”临界字”。论文实测临界字在行尾时性能约慢 0.7%(§3.5.2)。

2.6 NUMA(§5)

  • 结构:内存分散在各节点,本地访问便宜、跨节点昂贵,差价用 NUMA factor 描述(§5.1)。
  • 远程代价(论文引 AMD 四路机器数据,§5.4,Figure 5.3):1-hop / 2-hop 读比 0-hop 读慢约 9% / 30%;2-hop 写比 0-hop 读慢 49%,比 0-hop 写慢 32%、比 1-hop 写慢 17%。带宽测试中远程读始终慢约 **20%**。
  • 对策:绑核 + 绑内存(线程与它读写的内存分配到同一节点)、first-touch 策略(由第一个触碰页的线程决定物理位置)。Linux 提供 /proc/PID/numa_maps 与 libNUMA 接口观察/控制(§5.4, §6.5)。

2.7 优化实战与工具(§6, §7)

  • 矩阵转置(§6.2.1):把 mul2 逐列访问改成先转置再顺序访问,消除每列上千次非顺序访问。Table 6.2:
版本 周期数 相对
原始 16,765,297,870 100%
转置后 3,922,373,010 23.4%(加速 76.6%)
分块(sub-matrix) 2,895,041,480 17.3%

论文同时给出:分块解决容量 miss,且缓存行大小可编译期硬编码(getconf LEVEL1_DCACHE_LINESIZE,分块边 $S_M = \text{CLS}/\text{sizeof(double)}$);最终从 318 MFLOPS 提升到 3.35 GFLOPS(§6.2.1)。

  • 分块 = 现代 GPU GEMM 的祖先:CPU 上靠硬件缓存隐式分块,GPU 上靠程序员显式管理 shared memory 分块,思想一致。
  • 工具(§7):oprofile 做硬件计数器采样(看 CPI、cache miss 事件);valgrind 的 cache 模拟器验证 cache 行为;页错误优化(大页/预分配/madvise)(§7.1, §7.2, §7.5)。

3. CSAPP 第 2/5/6/9 章:核心结论 × 部署价值

CSAPP 把论文里”是什么”补成”为什么”和”怎么算”。四章各自一句话:§2 看位,§5 看优化,§6 看缓存,§9 看虚拟内存。

3.1 第 2 章 信息的表示与处理——位是最低层的”货币”

  • 核心结论:整数用补码表示,溢出按模回绕;浮点用 IEEE 754(符号 + 阶码 + 尾数),半精度 5 位阶码 / 10 位尾数,单精度 8/23,双精度 11/52;小端机(x86-64)按低位字节在前的顺序存字节。
  • 与部署的关系:dtype 归一化(FP32/FP16/BF16/FP8/INT8)的底层就是这一章。FP16 尾数只有 10 位,机器精度 $\approx 2^{-11} \approx 4.9\times10^{-4}$;累加器用 FP32 能显著减小误差——这是 GEMM 累加精度的来源。低比特量化的”位模式”理解也在这里。跨端读写二进制张量时的小端假设,也是这一章的坑。

3.2 第 5 章 优化程序性能——延迟不是吞吐,并行才有意义

  • 核心结论:
    • 编译器只能在别名的存在被排除时做激进优化(C 里 restrict/const 帮它排除别名);有副作用的调用会挡住优化。
    • 循环展开 + 多路累加器能打破”单个累加器加法的延迟链”,把程序从延迟界限推向吞吐界限。
    • 分支预测失败惩罚约 数十周期量级(约 20,具体随微架构——待核),所以”数据驱动消除分支”(把分支换成查表/算术)有时比预测更划算。
    • Amdahl 定律:加速比受不可并行部分限制;把 90% 的部分无限加速,整体上限也只有 10×。
  • 与部署的关系:kernel 里”一条长依赖链”常常就是性能天花板——多路累加、K 维切分本质都是制造 ILP;手写 kernel 与编译器的差距,很大一部分是”编译器不敢展开”而人敢。

3.3 第 6 章 存储器层次结构——AMAT 与局部性

  • 核心公式:

$$
\text{AMAT} = T_{\text{hit}} + \text{miss_rate} \times T_{\text{miss_penalty}}
$$

  • 地址三段划分:[tag | set index | block offset](与论文 §3.3.1 一致),由 offset 定位行内字节、set 选组、tag 判命中。
  • 写策略:write-through / write-back × write-allocate / no-write-allocate(论文 §3.3.3 是同一套术语)。
  • 局部性:时间局部性 + 空间局部性,是”缓存友好代码”的全部原则来源(步长 1 的遍历 > 跨步遍历 > 随机遍历)。
  • 与部署的关系:AMAT 告诉你两件事——提高命中时间性价比有限,降低 miss rate / miss penalty 才是主战场。张量布局(NCHW↔NHWC)、算子融合减少中间张量往返、分块大小匹配 cache/共享内存,都是在压 miss rate。

3.4 第 9 章 虚拟内存——地址翻译、TLB、缺页、mmap

  • 核心结论:
    • 虚拟内存是”把 DRAM 当磁盘缓存”的一层抽象,提供独立地址空间、保护、简化加载。
    • 地址翻译:多级页表(x86-64 常见四级),页大小 4KB;论文指出在 4KB 页、每级 512 项时,4 个目录即可覆盖 2MB,1GB 连续内存需要 512 个一级目录(§4.2)。大页 2MB / 1GB 减少页表级数与翻译次数。
    • TLB:页表项的缓存。论文点名 Core 2 有 128 个 ITLB + 256 个 DTLB 条目(§4.3.1);普通页下 TLB 只能覆盖很小的范围,大工作集易 TLB thrashing。
    • 缺页(page fault):按需调页,代价巨大(比 TLB miss 高几个数量级,§6.2.4);mmap + 写时复制(COW) 是延迟复制的经典手段。
    • 页表遍历成本:论文计算最坏情况下每次地址翻译要 4 次(四级)串行内存访问,若只能用 L1d 缓存目录项,至少 12 周期且无法并行(§4.3)。这正是 TLB 存在的理由。
  • 与部署的关系:大页是”减少翻译开销 + 保证物理连续”的双赢,但需要在系统启动时预留(hugetlbfs),因为 2MB 大页要求 512 个连续 4KB 页,运行久了碎片化后很难凑齐(§4.3.2)。显存分配、UVA 统一寻址、GPU 页表也遵循同一逻辑。

3.5 延迟金字塔(把 §2.1 的记忆锚点可视化)

4. 从内存角度诊断性能的清单

按”先证伪、再定位、后修”的顺序问自己(每条都对应上面的机制):

  1. 是内存瓶颈还是计算瓶颈? 先算计算强度(FLOP/字节),对照机器 roofline;若落在带宽侧,以下才有意义。
  2. 访问单位用满了吗? 是否按 cache 行(64B)粒度使用?有没有”跨步/逐列/随机”访问(§6.2.1)?
  3. 命中率还是延迟? 用 perf/硬件计数器看 L1D 替换、DTLB miss、L2 行流入等事件(§7.1);CPI 突然从 ~1 跳到 ~3 或 >20,通常是对应层缓存放不下的信号(§7.1)。
  4. 工作集 vs 缓存:数据集是否超过末级缓存?超过就用分块,块大小对齐缓存行(§6.2.3)。
  5. TLB 是否被打爆? 大工作集 + 4KB 页 → 考虑大页(2MB)(§4.3.2, §6.2.4)。
  6. NUMA 亲和性:线程与内存是否在同节点?用 numactl 绑核绑内存,或检查 /proc/PID/numa_maps(§5.4, §6.5)。
  7. 多线程是否伪共享? 检查是否多个线程写同一 cache 行(390%–1147% 的开销不是小数),用 padding/对齐隔离(§6.4.1)。
  8. 写多还是读多? 写带宽常远低于读(可达 10–20× 差距),写密集算子尤其要避开”写后立即读同一批数据”(§3.5.1)。
  9. 预取有没有被利用? 顺序访问应让硬件预取器生效;跨页/随机访问则考虑显式 _mm_prefetch(§6.3)。
  10. 缺页/首次触碰:大内存区域首次访问会付缺页代价;预分配 + madvise/大页可缓解(§7.5)。

6. 记忆口诀

  • 延迟金字塔:”寄存器 1,L1 三,L2 十四,主存两百四,磁盘百万”(§3.3.4)。

  • 优化三件套:”对齐 + 局部性 + 分块”。
  • CSAPP 四章:”2 看位,5 看优化,6 看缓存,9 看虚拟”。
  • AMAT:”命中时间 + 失效率 × 失效惩罚”。
  • NUMA 一句:”线程和它的内存在同一个节点,才算本地访问”。

小结:Drepper 论文给了”硬件事实”(延迟、行大小、页表、NUMA 代价),CSAPP 给了”系统组织方式”(AMAT、地址划分、地址翻译)。对部署/算子工程师而言,两者的交汇点就是一句话——把数据搬进正确的地方、按正确的顺序用满它、并让线程离它的数据足够近。所有布局、分块、对齐、绑核、大页、预取技巧,都是这句话的工程化。

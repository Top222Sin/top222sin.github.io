深度学习编译器综述(2020)精讲: 分层抽象与优化图谱

深度学习编译器综述(2020)精讲: 分层抽象与优化图谱

论文: The Deep Learning Compiler: A Comprehensive Survey, Mingzhen Li, Yi Liu 等, arXiv:2002.03794v4 (2020)。
文中的分层定义、分类体系、对比表条目与实验数字均取自论文原文, 关键处标注了对应图表, 便于逐条回查。论文对各家编译器只做归一化描述, 不替任何产品背书。

0. 30 秒结论

  1. DL 编译器 = 前端 + 多层 IR + 后端。论文的核心主张: 它与传统编译器同构(前端/IR/后端), 唯一独特之处是为深度学习专门设计的多层 IR 与 DL 特有的优化。
  2. IR 只分两级: 高层 IR(图 IR, 硬件无关, 在前端)与低层 IR(算子 IR, 设备相关, 在后端)。XLA 的 HLO 兼作两级, 是唯一例外（综述原文）。
  3. 优化按作用范围分档: 前端为节点级 → 块级 → 数据流级; 后端为硬件特定优化 + 自动调优 + 优化内核库（综述原文）。
  4. 判断”从哪层下手”的钥匙: 硬件无关的收益在图级(融合/布局/内存规划), 硬件相关的收益在算子级(内建指令映射/分块/向量化/流水)。新硬件先问”谁能承载低层 IR”, 新模型先问”图 IR 能否表达它”。

1. 全景: 为什么需要一个”编译器”, 而不是一堆手写 kernel

库路线的天花板: 通用硬件上先靠 BLAS(MKL、cuBLAS)把卷积转成矩阵乘再调 GEMM; 硬件厂商再补 DL 专用库(MKL-DNN、cuDNN)覆盖卷积/池化/归一化/激活的前反向; 更上层如 TensorRT 提供图优化(层融合)与低位量化, 附带大量手写优化 kernel。问题是: 库总是落后于模型的发展速度, 也无法把 DL 芯片用满; 逐个硬件、逐个模型手工优化则是不可承受的工程负担。

编译器路线: 以各框架的模型定义为输入, 输出各硬件上的高效代码; 转换过程针对模型规格与硬件架构高度优化, 融入层/算子融合等 DL 特有优化, 并复用 LLVM 这类成熟工具链换取可移植性。论文选定五个代表实现: TVM、nGraph、Tensor Comprehension(TC)、Glow、XLA。

2. 分层抽象: 前端 / 图 IR / 算子 IR / 硬件后端

2.1 论文的骨架

  • 高层 IR(即图 IR): 表达计算与控制流, 硬件无关。设计挑战是抽象能力——能否捕获并表达多样的 DL 模型; 目标是建立控制流、算子与数据之间的依赖, 为图级优化提供接口; 同时携带丰富的编译语义信息、并为自定义算子留扩展口（综述原文）。
  • 低层 IR: 为硬件特定优化与代码生成而设计, 必须足够细粒度以反映硬件特征、表达硬件特定优化, 还要能对接 Halide、多面体模型、LLVM 等成熟工具链（综述原文）。
  • 前端: 把框架模型转成计算图并实现各种格式转换; 图优化同时借用通用编译器技术与 DL 专用优化。后端: 把高层 IR 转成低层 IR 并做硬件特定优化——既可降级到 LLVM IR 复用基础设施, 也可用”模型 + 硬件”的先验知识写定制 pass; 参数空间大, 靠自动调度(如多面体)与自动调优(如 AutoTVM)定配置, 最后用 JIT 或 AOT 编译（综述原文）。
  • 容易被忽略的细节: 论文明确说 XLA 的 HLO 同时是高层与低层 IR, 因为 HLO 细粒度到能表达硬件特定信息, 并可发射 LLVM IR。

2.2 高层 IR = 图 IR

表示形式 要点 代表
DAG-based 节点 = 原子 DL 算子(卷积/池化…), 边 = 张量; 无环, 不同于通用编译器的数据依赖图。简单, 但计算作用域定义缺失会带来语义歧义 TVM/nGraph/XLA/Glow/TC
Let-binding-based 用 let 给受限作用域的表达式命名, 建立变量映射表而非仅”变量间计算关系”, 消除语义歧义 TVM 的 Relay IR 同时采用 DAG 与 let-binding

张量计算的三种表示: ①函数式——只提供封装好的算子, Glow/nGraph/XLA 采用; HLO 是符号式编程的函数集合, 指令分三级 HloModule(整个程序)/HloComputation(一个函数)/HloInstruction(一个操作), 其覆盖范围从数据流级直到算子级。②λ 表达式——用索引公式描述计算, 由”输出张量形状 + 计算规则的 λ 表达式”定义算子, 即 TVM 的 tensor expression。③爱因斯坦记法——求和约定, 无需定义临时变量索引, IR 靠未定义变量的出现推断表达式(TC); 它要求算子可结合、可交换, 这一限制恰好保证归约可按任意顺序执行, 从而便于并行化。

实现层面: 数据以张量组织, 可直接给内存指针, 也可用 placeholder(带各维尺寸, 值稍后填入)把”计算定义”与”实际执行”分离。动态 shape 分别用 TVM 的 Any、XLA 的 None、nGraph 的 PartialShape 标记; 论文指出完整支持动态模型还需放宽边界推断与维度检查, 并额外保证内存有效性。布局描述逻辑索引到内存索引的映射(NCHW/NHWC、tiling、padding、striding): TVM/Glow 把布局作为算子参数, XLA 把布局表达为与后端硬件相关的约束, Relay 与 MLIR 则计划把布局并入张量类型系统。边界推断依计算图与已知 placeholder 递归/迭代求迭代器边界; TVM 中迭代器构成有向无环超图, 根边界确定后即可按 split/fuse/rebase 关系递归推其余。

算子层面: 论文重点讨论四类——广播(XLA/Relay 放松形状约束, 允许矩阵与向量逐元素相加)、控制流(Relay 用 if + 递归函数, XLA 用 while/conditional; 否则只能靠宿主语言或静态展开, 会损害效率)、导数(TVM/TC 支持自动微分, PlaidML 连自定义算子都能自动生成导数)、自定义算子(TVM/TC 编程负担最小: 描述计算与 schedule + 声明输入输出形状即可)。

2.3 低层 IR = 算子 IR

类别 核心思想 代表 论文点评
Halide-based 计算与调度分离; 内存引用与循环嵌套边界限制为与轴对齐的有界盒, 便于参数化并暴露给调优机制 TVM(把 Halide IR 改造为独立符号 IR: 去掉 LLVM 依赖、变量定义改为指针匹配即 SSA)、TC 无法表达非矩形等复杂模式(好在 DL 计算足够规则); 原版 Halide 输入形状无限, 移植到 DL 后端必须知道精确形状才能映射硬件指令
Polyhedral-based 用线性规划、仿射变换处理静态控制流的循环代码; 边界可为任意形状多面体, 可做 fusion/tiling/sinking/mapping TC、PlaidML(作为 nGraph 后端的 GPU 路线, 其 IR 名为 Stripe, 提出嵌套多面体模型) 灵活但难以与调优机制集成; 擅长深循环嵌套。常见工具链: isl / Omega / PIP / Polylib / PPL
其它私有 IR 自建低层 IR, 做硬件特定优化后降到 LLVM IR Glow(指令式, declare/program 两类函数, 操作数用 @in/@out/@inout 标注读写以判定可做的内存优化)、MLIR(引入 dialect 表达多抽象层, 已有 TensorFlow IR / XLA HLO / 实验性多面体 IR / LLVM IR / TFLite) MLIR 能新建 dialect 对接新低层编译器, 为硬件开发者铺路

代码生成: 多数低层 IR 最终降到 LLVM IR; 但直接喂 LLVM IR 常生成较差代码, 故有两条路线——①在 LLVM 之上的 IR 里做目标相关循环变换, ②给优化 pass 补充硬件目标信息。前者偏”面向前端用户”(TC、TVM、XLA、nGraph), 后者偏”面向后端开发者”(Glow、PlaidML、MLIR)。编译方案分 JIT(运行时生成, 可利用运行时知识)与 AOT(先生成全部二进制, 静态分析范围更大, 便于交叉编译与远程/自定义加速器执行)。

3. 优化技术图谱

3.1 前端(图级): 三种粒度

  • 节点级: Nop Elimination 消除输入不足的操作(只有一个输入的 sum、零宽度 padding); 零维张量消除删除输入为零维张量的操作(零维 A + 常量 B ⟹ 直接用 B; {0,2,3} 形状的张量无元素 ⟹ argmin/argmax 可删)。
  • 块级: 代数化简 = 代数识别 + 强度消减 + 常量折叠, 利用交换/结合/分配律化简一串节点。可作用于 DL 特有算子: GEMM 的”两个转置 + 相乘”可改为”换参数顺序相乘 + 一次转置”, 两次转置降为一次; 连续 transpose 可合并、恒等 transpose 可删、不搬数据的 transpose 可降为 reshape; 末两维归约的 4D ReduceMean 可替换为 AvgPool(如 Glow)。算子融合的收益是共享计算、消除中间分配、合并循环嵌套、降低启动与同步开销; TVM 把算子分四类 injective / reduction / complex-out-fusible / opaque 并据此定融合规则, TC 靠自动多面体变换; 论文直言”多广播 + 多归约的复杂块如何识别与融合”仍是问题。算子下沉把 transpose 之类沉到 BatchNorm/ReLU/sigmoid/channel shuffle 之下, 让相似操作聚拢, 创造更多代数化简机会。
  • 数据流级: CSE(公共子表达式复用)、DCE(删除结果或副作用未被使用的代码, dead store elimination 也归 DCE; CSE/DCE 通常放在其它图优化之后, 因为死代码多半由别的优化造成)、静态内存规划(in-place 共享 + 标准共享; 离线规划因此能用更复杂的算法, 已有面向端侧、以最小化激活内存峰值为目标的 memory-aware scheduling)、布局转换(只为张量挑最优布局并插入转换节点, 真正转换留到后端求值时做; GPU 上 NCHW 通常更快, 加速器偏好 tile 之类复杂布局, 端侧异构单元各有偏好, 而转换本身的开销不可忽略。有工作基于 TVM 在 CPU 上先把卷积布局改为 NCHW[x]c, 再用 cache line 大小、向量化单元大小、访存模式等硬件信息对 x 全局自动调优)。
  • 小结: 各家前端的数据表示与算子定义可以不同, 但硬件无关优化都收敛到节点/块/数据流这三层。

3.2 后端: 硬件特定优化

论文归纳五类: ①内建指令映射——把一组低层 IR 指令映射为硬件上已高度优化的 kernel; TVM 用可扩展的 tensorization 声明内建指令行为与降级规则, Glow 支持量化类映射(可估计各阶段数值范围并做 profile 引导的自动量化), Halide/TVM 还会把特定 IR 模式映射到各架构 SIMD 指令, 避开 LLVM 处理向量模式时的低效。②内存分配与取数——GPU 有共享内存(低延迟小容量)与局部内存(高延迟大容量)的层级; TVM 引入 memory scope 调度原语, 把计算阶段标为 shared 或 thread-local, 标记为 shared 时自动生成共享内存分配与协作取数并插入内存屏障; TC 通过扩展 PPCG 提供类似能力(memory promotion), 但只支持有限预定义规则。③内存延迟隐藏——GPU 上可由硬件(warp 上下文切换)自然完成; 对解耦访存-执行(DAE) 的类 TPU 加速器, 后端必须做调度与细粒度同步, TVM 的 virtual threading 让用户声明虚拟多线程上的数据并行, 再由编译器插屏障、把多线程操作交织成单条指令流以隐藏访存延迟。④循环类优化——循环融合、滑动窗口、分块(tiling)、循环重排(permutation)、循环展开(常与循环分裂配合); 其中滑动窗口”按需计算、即时存储、用完即弃”, 把两个循环的计算交织并串行化, 是并行度与数据复用之间的取舍; 分块尺寸是硬件相关的, 很多编译器靠自动调优决定; 循环重排在迭代间存在依赖时不安全。⑤并行化——Halide 用 parallel 原语指定并行维(并用 block/thread 标注映射 GPU), 还用 n 宽向量语句映射 SIMD; PlaidML 的 Stripe 提出嵌套多面体模型以识别分块与跨步的层级并行; Glow 把向量化交给 LLVM。论文的取舍结论: 完全由后端榨取并行可利用更多 DL 领域知识、性能更高, 但工程量更大。

3.3 后端: 自动调优

只有 TVM、TC、XLA 支持自动调优, 实现可拆成四个部件:

  • 参数化: ①数据与目标(输入形状; GPU 的共享内存与寄存器大小等约束); ②优化选项(调度方式与 tile size 等; TVM 兼顾预定义与用户自定义调度)。
  • 代价模型: 黑盒模型(只看最终执行时间, 好建但开销高、解较差, TC 采用)、ML 代价模型(统计预测并随新配置更新: TVM 用 GBDT, XLA 用前馈神经网络)、预定义模型(依赖对编译任务的完美建模, 运行开销小但每换模型/硬件都要重建)。
  • 搜索策略: 初始点与搜索空间确定; 遗传算法(TC)、模拟退火(TVM)、强化学习(Chameleon, 构建于 TVM 之上)。
  • 加速: 并行化——TC 的多线程多 GPU 策略(候选配置入队后在多 CPU 线程编译、在多 GPU 并行评测), TVM 支持交叉编译与 RPC(本机编译、多目标运行); 配置复用——TC 用编译缓存, 未命中才触发调优, TVM 把最优配置写日志文件并在编译时查表; 且 TVM 是逐算子调优(如各 conv2d 各自定)。

3.4 后端: 优化内核库

DNNL(前 MKL-DNN)、cuDNN、MIOpen 覆盖计算密集算子(卷积/GEMM/RNN)与带宽受限算子(BN/池化/shuffle), 支持可定制布局与 FP32/FP16/INT8/bfloat16 等精度; TVM、nGraph、TC 都能在代码生成时发出对这些库的调用。代价是: 先要把数据布局与融合风格转成库预定义的类型(可能破坏最优控制流), 而且编译器把库当黑盒, 无法跨算子优化(如融合)。结论: 计算能被特定高度优化原语满足时收益显著, 否则反被限制、性能次优。

从表里读出的三条结论: ①五家几乎不约而同选 Python/C++ + 两级 IR, 差异集中在前端范式(λ / 张量表达式 / 爱因斯坦记法 / 层级编程 / 图接口)与是否自带自动调优。②支持训练 ≠ 以训练为目标: 可训练支持普遍偏弱（综述原文）, 论文的总结是现有编译器主要解决”把模型高效部署到多样硬件”, 因此以推理为主要优化目标。③内核库与自动调优是两条替代路线: nGraph 不做自动调优而直接调优化库, Glow 认为 IR 已带足信息不需要额外调优, TVM/TC/XLA 则自建调优。

4.1 论文的实测结论

实验设置： 19 个 ONNX 模型(ResNet/DenseNet/VGG 属 full-fledged, MobileNet/MNASNet 属 lightweight); 版本为 TVM v0.6.0、nGraph 0.29.0-rc.0、TC(commit fd01443)、Glow(commit 7e68188)、XLA(TensorFlow 2.2.0); 每个模型跑 15 次, 前 5 次作预热, 报告后 10 次平均。硬件（综述原文表 2）: 平台 a = Broadwell E5-2680v4×2(28 物理核, 2.4GHz)+ Tesla V100 32GB(15.7 TFlops FP32); 平台 b = Skylake Silver 4110×2(16 物理核, 2.1GHz)+ Turing RTX2080Ti 11GB(13.4 TFlops FP32)。

论文给出的观察：

  • Glow 在 CPU 上最差, 原因是不支持线程并行、用不满多核; TVM/nGraph/XLA 都能用满 CPU 核。
  • nGraph 的卷积在 CPU 上更好, 得益于硬件(Intel CPU)与软件(编译器/库/运行时)的协同设计——它把优化子图交给 DNNL, 利用针对 Intel CPU 的细粒度指令级 JIT 优化; TVM 在 GPU 上更好(这几个编译器之中)。
  • 调优后的 TVM(200 次试验)在 CPU 与 GPU 上几乎全面最优, 尤其轻量模型(这些模型的经典算子 schedule 已被开发者设计好, 且 tophub 提供默认参数)。而调优 vs 不调优在 CPU 上差异可忽略, 在 GPU 上平均有 41.26× 加速——GPU 的线程与存储层次更复杂, 需要更细粒度的调度(tile/split/reorder), 自动调优在此才真正体现价值。
  • TC 的性能严重依赖最初编译的那个 kernel: 以 MobileNetV2_1.0 为例, 若先用 c1 层初始化调优, c1 表现很好, 但离 c1 越远后续 c*_b*_* 层越慢; 想要稳定性能需逐 kernel 单独调优。
  • Glow 在 1×1 卷积与深度可分离卷积上落后(论文推测与它常把这些卷积同 ReLU/BatchNorm 融合有关); CPU 上它靠 CPUConvDKKC8 优化(对特定模式卷积做分块 + 布局转换 + 向量化)才在模型末段变快。
  • XLA 的卷积会被”聚簇(clustered)” 到其它 kernel 中, 难以单独度量; 论文统计了聚簇/非聚簇数量（综述原文表 3）: MobileNetV2_1.0 在 V100 上 5 / 47、在 Broadwell 上 17 / 35; ResNet50 在 V100 上 0 / 53、在 Broadwell 上 53 / 0。只有被聚簇的 kernel 由 XLA 优化, 非聚簇的仍由 TensorFlow 优化。

方法学上的诚实提醒: 前端的图级优化与后端的算子级优化在现有编译器里紧耦合——前端优化会改动一串算子, 于是喂给后端的输入各不相同; 二者还常被协同设计(如 XLA 的 clustering)。因此单独评测某一项优化几乎不可能。论文的应对是构建通用基准框架: 提取目标层所需结构与参数(称为 model fragments), 重建为该编译器可接受的输入, 再度量优化后的性能, 从而同时得到端到端与逐层指标。

5. 硬件特化: 从 CPU/GPU 到 DLA/FPGA/ASIC

论文的分类依据是通用性： ①通用硬件通过软硬协同支持 DL 负载(GPU + Tensor Core); ②专用硬件用完全定制的电路把性能与能效推到极致(TPU 的 MXU/UB/AU、Inferentia 的 4 个 NeuroCore 与大容量片上缓存); ③受大脑启发的神经形态硬件(TrueNorth、Loihi, 后者引入 STDP)。

5.1 FPGA 代码生成器: 两种架构

FPGA 可重构, 因此填补了 CPU/GPU(高度可编程但费电)与 ASIC(省电但只服务固定应用)之间的空档。即便有 HLS(C/C++ 生成硬件设计, 省去大量 Verilog/VHDL), 把 DL 模型映射到 FPGA 依然复杂: 模型用框架语言描述而非裸机 C/C++, 且 DL 特有信息与优化难以利用。论文按生成的加速器架构分两类:

  • 处理器架构: 多个 PU(处理单元), 每个 PU 含片上缓冲与多个更小的 PE; 有虚拟指令集, 控制与执行调度由软件决定, 静态调度避开了冯·诺依曼执行(取指/译码)的开销。代码生成器用硬件模板 + 可配置参数自动生成设计, 参数可调意味着”扩展性”(高性能到低功耗的 FPGA 都能生成)与”灵活性”(支持不同层类型与参数的模型); PU 数、每 PU 的 PE 数、tilling size、batch size 是关键参数, 通常由设计空间探索(性能模型 + 自动调优)确定。代表: DNNWeaver、Angel-Eye、ALAMO、FP-DNN、SysArrayAccel。
  • 流式架构: 类似流水线, 几乎”每层一个硬件块”, 数据按层的顺序流过各块, 所有块以流水方式满载工作; 前提假设是片上内存与计算资源足以容纳整个模型, 于是深层/复杂层结构会成为部署障碍(可借 FPGA 的可重构性或动态控制流解决)。代表: fpgaConvNet、DeepBurning、Haddoc2、AutoCodeGen。

5.2 编译器与硬件的共生

论文强调低层 IR 的设计会反过来影响新加速器的设计: TVM 的 Halide IR 与 AWS Inferentia、XLA 的 HLO 与 Google TPU 都是成对演进的。换句话说, “先有芯片还是先有编译器”没有单向答案——低层 IR 就是软硬件之间的合同。

6. 未解问题与趋势

  1. 动态 shape 与前后处理: 动态模型的输入形状乃至模型本身在运行时变化(NLP 尤甚), 现有编译器支持不足; 前后处理目前多在 Python 解释器里执行, 可能成为瓶颈——把整段控制流纳入编译才能一并优化。
  2. 子图划分: 把计算图切成子图后可分别处理, 打开两个空间: ①集成图库优化(如 DNNL 与 nGraph 结合, 用 DNNL 的图优化加速 nGraph 生成的子图); ②异构并行——把不同子图同时派到不同硬件, 例如端侧设备的 ARM CPU + Mali GPU + DSP + NPU 全部用起来(原文此处写作 “Mail GPU”)。
  3. 量化: 框架里的量化基于固定方案与数据类型、对不同硬件的代码缺少定制, 放进编译器就能在编译期推导更高效的策略(Relay 提供量化重写流程, 可为多种方案自动生成量化代码)。两个挑战: 如何低成本实现新的量化算子(用 dialect 在基础算子上实现新算子以复用图级与算子级优化); 量化与其它优化的交互(在哪个阶段做量化、如何与算子融合协同)。
  4. 进阶自动调优: 现有调优只看单个算子, 而局部最优之和 ≠ 全局最优(相邻算子若用不同布局, 本可一起调优以免中间的内存搬运); 端侧兴起后, 优化目标不止执行时间, 还包括内存占用与能耗; ML 技术也能用在代价模型之外的阶段(如选编译选项与调度)。
  5. 多面体模型: 与自动调优结合是双向的——调优复用历史配置可降低多面体 JIT 编译开销, 多面体做自动调度可缩小调优搜索空间; 另一个难题是稀疏张量(如 CSF 格式用 a[b[i]] 这类间接索引导致非仿射下标与边界, 阻碍多面体的循环优化)。
  6. 统一优化: 各家编译器的图优化与硬件特定优化设计相似、各有所长, 却缺少共享最新优化的机制; 论文主张把优化统一起来, 既能复用最佳实践, 也能共同影响通用/专用加速器的设计。MLIR 是目前最有希望的方向(多层 IR 基础设施 + 跨层变换规范与工具 + 灵活 dialect), 难点是减少对精巧设计的依赖。
  7. 可微编程: 程序整体可微、可自动微分, Myia、Flux、Julia 等已采用, 而现有 DL 编译器支持极少, 难点在数据结构与语言语义(如 Julia 的命令式控制流 vs XLA 的符号式控制流)。
  8. 隐私保护: 边云协同把模型切成两半分别部署, 但中间结果被截获后可被用于训练窥私模型; 现有做法是注入带统计特性的噪声, 难点是噪声该插在哪一层——编译器掌握模型的丰富信息, 正好能自动指导插入位置。
  9. 训练支持: 现有编译器普遍弱, 因为主要目标是高效部署; 扩展到训练会打开梯度算子优化、高阶自动微分等空间。

7. 落点: 用这套分层做判断

7.1 面对一个新硬件, 从哪层下手?

  1. 先看它能否承载低层 IR 的降级路径： 若已有 LLVM 后端, 大概率走”低层 IR → LLVM IR”这条最省事的路; 若没有, 就得自建低层 IR 或新 dialect(这正是 MLIR 的存在意义；来源 综述原文)。
  2. 再决定是”改调度”还是”改图”: 硬件特性(缓存、向量宽度、共享内存大小、是否 DAE 架构)主要影响算子级——分块尺寸、向量化、内存 scope、延迟隐藏（综述原文）; 这些参数往往靠自动调优确定。
  3. 若硬件厂商自带高质量 kernel 库, 最省力的策略是像 nGraph 那样不做细粒度调优、把子图交给库（综述原文）; 代价是失去跨算子融合能力, 因此必须做子图划分——库擅长的交给库, 剩下的自己编译。
  4. 最后补上层: 硬件相关优化只有在前端把图级优化(融合、布局、内存规划)做干净之后才有意义, 因为后端收到的算子序列已被前端改写（综述原文）。

7.2 面对一个新模型, 从哪层下手?

  • 先问图 IR 表达得了吗: 有循环/条件分支的模型(RNN、RL)需要控制流算子; Relay 用 if + 递归函数, XLA 用 while/conditional, 否则退化到宿主语言或静态展开, 直接损害效率（综述原文）。
  • 再问动态 shape 谁支持: Any(TVM)/None(XLA)/PartialShape(nGraph) 都只是”标记未知”, 论文明确说完整支持还需放宽边界推断与维度检查、并额外保证内存有效性。
  • 再问算子的可融合性: 难点不在”能不能融”, 而在”多广播 + 多归约的复杂块如何识别”（综述原文）; TVM 的四类算子分类(injective / reduction / complex-out-fusible / opaque)是判断融合边界的现成工具。
  • 最后才是逐算子调优: 只在 GPU 这类线程与存储层次复杂的后端上收益显著(实测平均 41.26×), CPU 上调不调差别可忽略（综述原文）。

8. 速查 + 记忆口诀

两级 IR, 三档图优化, 五把后端刀, 四件调优事。

  • 两级 IR: 高层图 IR(硬件无关) / 低层算子 IR(设备相关); HLO 是唯一的”兼职者”。
  • 三档图优化: 节点级(消) → 块级(化: 代数化简 / 融合 / 下沉) → 数据流级(全局: CSE / DCE / 内存规划 / 布局)。
  • 五把后端刀: 内建指令映射、内存分配与取数、内存延迟隐藏、循环类优化(融合 / 滑动窗口 / 分块 / 重排 / 展开)、并行化。
  • 四件调优事: 参数化、代价模型、搜索策略、加速(并行 + 复用)。

一句话定位五个编译器(据（综述原文表 1）与实测):

编译器 记忆标签
TVM Relay + Halide 两级 IR, 自动调优最完整; GPU 上最强(本组中)
nGraph 背靠 Intel 软硬协同, 图库(DNNL)路线; CPU 卷积最强
TC 爱因斯坦记法 + 多面体, 自动微分是亮点; 性能最依赖初始 kernel
Glow 指令式私有低层 IR, 内存/布局优化精细; 不支持线程并行, CPU 上吃亏
XLA HLO 一级 IR 兼高低层, 与 TPU 共生; 前后端紧耦合, 逐层难测

互斥关系速查: 自动调优 vs 直接调内核库(nGraph/Glow 属后者); JIT vs AOT(五家都从 JIT 起家, 陆续补 AOT); 编译器自研优化 vs 外包给 LLVM(Glow 的向量化就外包给了 LLVM)。

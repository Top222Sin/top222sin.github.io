一、深度学习编译器概览

1.1 为什么需要深度学习编译器？

推理引擎（ncnn / MNN / ONNX Runtime / TensorRT）能加速模型部署，但它们有一个根本限制：
每个引擎手动实现了固定算子的优化。当出现新算子、新硬件、新模型结构时，手动优化跟不上。

深度学习编译器解决了这个问题：

1.2 三款编译器定位

编译器 定位 抽象层级 适合用途 学习难度
TVM 端到端 DL 编译器 模型 → 图 → 张量 → 循环 快速部署新模型到新硬件 ⭐⭐⭐
MLIR 编译器基础设施 多级 IR 转换框架 构建自己的编译器、算子 dialect ⭐⭐⭐⭐⭐
Triton GPU Kernel DSL 手写高效 kernel 的语言 替代手写 CUDA kernel ⭐⭐

1.3 与传统编译器的类比

Phase 1：编译原理基础（2 周）

目标

虽然不需要成为编译器专家，但理解编译器的核心抽象能让后续学习高效 10 倍。

1.1 LLVM 基础 — DL 编译器的”后端工厂”

大多数 DL 编译器最终通过 LLVM 生成 CPU 代码。理解 LLVM 的 IR 是理解 TVM/MLIR 的前置。

关键理解： IR 是编译器内部的语言，它在”源码的便利性”和”机器码的高效性”之间架起桥梁。你不需要手写 LLVM IR，但需要理解这个概念，因为 TVM 的 Relay IR 和 MLIR 的各层 dialect 遵循同样的哲学。

1.2 核心概念速查

概念 传统编译器（LLVM） TVM MLIR
IR LLVM IR Relay IR / TIR 多级 dialect
Pass 优化转换 Relay Pass / TIR Pass Pass Pipeline
Target x86 / ARM / NVPTX LLVM / CUDA / OpenCL LLVM / SPIR-V / NVVM
调度 指令调度 Tensor 调度（compute/schedule） 转换（transform）
Dialect — Relay / TensorIR Linalg / SCF / Affine

Phase 3：MLIR 基础与实战（4 周）

3.1 为什么需要 MLIR？

TVM 解决了”从模型到代码”的问题，但它的 IR 是为深度学习定制的。当需要引入新的硬件（自定义 NPU）、新的计算模式（量化、稀疏计算）时，修改 TVM 的 IR 非常困难。

MLIR（Multi-Level Intermediate Representation） 是 LLVM 社区发起的编译器基础设施，核心理念是：

  • 不定义一种 IR，而是提供一个定义 IR 的框架（Dialect）
  • 不同抽象层次的 IR（dialect）可以在同一个编译流水线中共存、互相转换

Phase 4：Triton DSL 与 Kernel 编译器（2 周）

4.1 Triton 定位

Triton 是 OpenAI 开发的一种类 Python 语言，用于编写高效的 GPU kernel。它填补了”手写 CUDA”和”TVM 自动生成”之间的空白：

Triton 的核心思想： 你用 Python 写按程序块（tile） 级别描述计算，Triton 编译器自动处理：

  • tile 在 SM 间的分配
  • 共享内存分配与复用
  • 全局内存的合并访问
  • warp 级别的指令调度

6.2 推荐进阶项目

  1. Compiler Triathlon：用 TVM / MLIR / 手写三种方式实现同一个模型，对比开发时间和运行性能
  2. MLIR Dialect for ncnn：参考 ncnn/tools/mlir，创建一个完整的 MLIR ↔ ncnn 转换链

你对编译器的独特优势

作为已经手写实现过全部六种推理方案的人，你对编译器的理解会比纯算法工程师更深刻：

这些手写经验是学习编译器最宝贵的资产——你不是在学”另一个框架”，而是在学”如何自动化你手头正在做的调优工作”。

附录：快速入手命令汇总

最后的话： 深度学习编译器是这个领域里最”硬核”的方向之一。它需要编译原理、体系结构、深度学习三重知识。但不要被”编译器”三个字吓到——你现在手写 SIMD 卷积代码的过程，本质上就是在”编译”一个高效的 kernel。编译器只是把这个过程自动化、系统化了。你的 ncnn_deploy 项目已经证明了你对计算图的深刻理解，有了这个基础，进入编译器世界只是换个视角看同一件事。

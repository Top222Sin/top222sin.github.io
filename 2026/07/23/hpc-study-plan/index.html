Phase 1：C++ 核心内功（2 周）

目标

扎实的 C++ 是现代 HPC 的基石。此阶段重点：RAII、移动语义、模板元编程、编译期计算。

学习内容

主题 关键知识点 对应模型部署场景
RAII 与智能指针 unique_ptr/shared_ptr 管理 GPU 内存、std::vector 做连续 buffer cuda_forward() 中的 static 变量可改为 RAII 类
移动语义与完美转发 减少中间 Tensor 拷贝、std::move 优化 pipeline manual_forward() 传参时避免 Eigen::Tensor 拷贝
模板与 SFINAE 类型萃取（std::is_same）、enable_if 选择 kernel 编译期选择 SSE4.1 / AVX2 路径
constexpr / if constexpr 编译期查表（如 sigmoid LUT）、编译期分支 conv2d_simd_impl 的 #if defined 可改为 if constexpr
Lambda 与函数对象 自定义算子注册、std::function vs auto ncnn 的 Layer 工厂注册模式
alignas / alignof 缓存行对齐（64B）、SIMD 对齐（32B） ncnn::Mat 的 align_malloc

推荐资源

  • 《C++ High Performance》（已有 PDF） — 第 1-7 章
  • 《现代 C++ 教程》（已有 PDF） — 快速回顾
  • cppreference.com — 随时查
  • 代码实验：用 RAII 包装 manual_cuda.cu 的 cudaMalloc/cudaFree

Phase 2：内存与数据布局（2 周）

目标

理解现代 CPU/GPU 的内存层次结构，学会以数据为中心的优化——这是模型部署性能调优最常忽略但效果最显著的一环。

学习内容

主题 关键知识点 对应模型部署场景
缓存层次 L1(32KB)/L2(256KB)/L3(8MB) 大小与延迟、cache line(64B) im2col 的 col buffer(288KB) 超过 L2 的大小
内存带宽 DDR4/5 带宽 ~30-50 GB/s、NUMA 架构 为什么 21M FLOPs 的小模型 CPU 瓶颈在内存带宽
数据布局 NCHW vs NHWC vs CHWN、NC4HW4、tiling ncnn 的 packing-aware 布局 vs MNN 的 NC4HW4
内存对齐 aligned_alloc(32)、__attribute__((aligned)) SIMD load/store 需要 32B 对齐
预取 _mm_prefetch、__builtin_prefetch SIMD 卷积的软件预取
内存池 预分配复用、避免反复 malloc ncnn PoolAllocator → manual_optimized 的 workspace
大页 (Huge Pages) HugeTLB、透明大页 TensorRT 和 ncnn 的大页优化选项

关键实验：动手跑通缓存分层

推荐资源

  • Computer Architecture: A Quantitative Approach (Hennessy & Patterson) — 第 2 章内存层次
  • What Every Programmer Should Know About Memory (Ulrich Drepper) — 经典神文
  • ncnn 源码：src/mat.h 的 PoolAllocator、src/layer/convolution.cpp 的 padding 处理

Phase 3：并行计算 — CPU（2 周）

目标

从多线程到SIMD 向量化，再到两者结合——覆盖 CPU 模型部署所需的全部并行手段。

主题 关键知识点 对应模型部署场景
OpenMP 基础 #pragma omp parallel for、collapse、schedule、reduction ncnn / MNN 的多线程推理

OpenMP + SIMD 混合 外维开线程、内维 SIMD 生产级推理引擎的标准模式
循环展开 #pragma unroll、手动 4×/8× 展开 编译器不一定做好的地方

Phase 4：并行计算 — GPU（2 周）

目标

从 CUDA 编程模型到 cuDNN/TensorRT 高级 API——掌握 GPU 上的模型部署。

学习内容

主题 关键知识点 对应模型部署场景
CUDA 编程模型 Grid/Block/Thread、warp divergence、bank conflict manual_cuda.cu 的 3D grid 卷积
内存层次 Global/Shared/Local/Texture/Constant __ldg() 只读缓存、__shared__
共享内存 2D block tiling、bank conflict 避免 卷积的输入 tile 放到共享内存
cuBLAS / cuDNN cublasSgemm、cudnnConvolutionForward 厂商优化库 vs 手写 kernel
CUDA Stream 与异步 cudaMemcpyAsync、cudaStream_t 实现计算-传输 overlap
TensorRT 基础 构建期优化、INT8/FP16 量化 生产级 GPU 部署标准方案
CUDA Graph 将推理图捕获为 cudaGraphExec_t 消除小模型的 kernel launch 开销
Nsight 性能分析 Occupancy、roofline、SM 利用率 发现性能瓶颈（你的 CUDA 方案利用率仅 1.7%）

八、总结性能力阶梯

关键认知： 对 21M FLOPs 的 CIFAR-10 CNN，性能天花板是 ~0.03 ms（受限于 kernel launch + 内存搬运）。
更大模型（>100M FLOPs）时，极致调优的效果会更显著。

推荐下一步动手方向

  1. 短期（1-2 天）：在 ncnn_deploy 中加入第 7 种推理方案（ONNX Runtime C++ API）
  2. 中期（1 周）：实现 manual_simd 的寄存器分块版本（4pixel × 8OC）
  3. 中期（1 周）：融合 manual_cuda 的 kernel（减少 9→3 次 launch）
  4. 长期（2-3 周）：在 st_nndeploy 中复现同一套六路对比，验证统一封装层的性能开销
  5. 长期（2-3 周）：TensorRT 部署 CIFAR-10 CNN，加入对比

最后的话： 模型部署最核心的竞争力不在于”会用某个引擎”，而在于理解推理引擎内部发生了什么。你的 ncnn_deploy 项目——从手写 6 层循环到 SIMD 到 CUDA——已经让你具备了这种”从底层到上层”的完整认知。本计划的目标是帮你把散落的知识点串成体系，并找到每个知识的工程落脚点。不需要全部学完再动手——学一个概念，立即可在项目中验证，才是最高效的路径。

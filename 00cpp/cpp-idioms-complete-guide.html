一、资源管理惯用法

1.1 RAII（Resource Acquisition Is Initialization）

最核心的 C++ 惯用法，没有之一。C++ 标准库和所有优秀项目都遵循此惯用法。

1.2 Scope Guard / Scope Exit

保证在作用域退出时执行指定操作——无论正常返回还是异常。

1.3 Copy-and-Swap

提供强异常安全的赋值操作符。传统经典惯用法。

1.4 Move-and-Swap（现代 C++ 版）

1.5 Rule of Three / Five / Zero

二、编译期惯用法

2.1 CRTP（Curiously Recurring Template Pattern）

编译期多态，零运行时开销。Eigen、LLVM、ncnn 都大量使用。

2.2 SFINAE / enable_if

模板元编程的基石。C++17 后被 if constexpr 部分替代，但仍在库代码中广泛存在。

2.3 Tag Dispatch（标签派发）

利用空类型做编译期函数重载选择。

2.4 If Constexpr（C++17）

编译期条件分支，选中的分支才实例化。替代大部分 SFINAE 和 Tag Dispatch。

2.5 Type Traits / 类型萃取

编译期检查和变换类型。C++17 _v/_t 后缀让使用更简洁。

2.6 Thin Template（瘦模板）

减少模板代码膨胀。将类型无关的代码移到非模板基类。

2.7 Policy-Based Design（基于策略设计）

编译期组合行为，零开销抽象。Andrei Alexandrescu 在《Modern C++ Design》中推广。

2.8 Empty Base Optimization（EBO）

空基类不占用空间。std::tuple、std::allocator 等依赖此优化。

三、异常安全惯用法

3.1 NVI（Non-Virtual Interface）

基类公开非虚接口，私有虚函数让派生类定制实现。Herb Sutter 推崇。

3.2 Two-Phase Construction

构造不抛出异常，用工厂函数完成可能失败的操作。

3.3 Finally（保证清理操作）

3.4 ScopeLock / RAII Lock

四、类型与接口惯用法

4.1 Pimpl（Pointer to Implementation）

编译防火墙，隐藏实现细节。Qt、LLVM 大量使用。

4.2 Type Erasure（类型擦除）

将不同类型统一到同一个接口下，但不使用继承。std::function、std::any 的核心。

4.3 Attorney-Client / PassKey（律师-客户惯用法）

细粒度的访问控制。比 friend 更精确。——控制谁可以访问特定方法。

4.4 Mixin（混入）

通过模板继承组合行为，实现”编译期装饰器”。

4.5 Virtual Friend Function

虚函数不能是 friend，但可以用间接方式实现类似效果。

4.6 Virtual Constructor（Clone）

通过虚函数实现多态克隆。

4.7 Make_Shared / Make_Unique

优先使用 make 函数而非直接 new。

五、模板元编程惯用法

5.1 Expression Templates（表达式模板）

延迟求值，避免临时对象。Eigen 的核心技术。

5.2 Metafunction / Type Computation

在编译期”调用函数”操作类型。

5.3 Variadic Template Expansion

现代 C++ 惯用法最佳实践总结

最后的话： C++ 惯用法是无数 C++ 程序员经过二十多年实践锤炼出来的”最佳实践”。
它们不是语言规则，而是经过验证的模式。理解这些惯用法，你就能读懂 LLVM、ncnn、Folly 这些大型 C++ 项目的代码风格。
最重要的三个惯用法是：RAII、RAII、RAII。
